# Эксплуатация

Проверено 14.10.2026. При наличии `backlog-assistant/.env` стандартный запуск автоматически поднимает помощника. Без файла он остаётся необязательным. Доступ определяется настройками DMB.

## Подготовка

1. Установить окружение по [README](../README.md), собрать runtime Dockerfile и записать **локальный immutable image ID** `sha256:…` в `ASSISTANT_RUNTIME_IMAGE`.
2. Подготовить отдельные PostgreSQL database/credentials для агента. Не использовать URL DMB. Скрипт не создаёт пользователей БД и не подменяет PostgreSQL SQLite.
3. Скопировать `.env.example` в `.env`, задать случайные gateway/service secrets не короче 32 символов, модель и ключ. Выбранный пользователем провайдер аналогичен V1/V2: `https://opencode.ai/zen/go/v1`, `glm-5.3-flash`. Ключ можно взять из существующей разрешённой конфигурации, но он не должен попадать в git, аргументы CLI, браузер или OpenCode.
4. Выдать сертификаты от доверенной локальной CA для agent listener/client и DMB listener/client; SAN серверов должен включать `127.0.0.1`, EKU — соответствующие server/client назначения. Прописать абсолютные пути CA/cert/key. TLS нельзя отключить заголовком или переменной обхода.
5. DMB: установить обновлённый backend requirements.lock, применить обычные Alembic-миграции. Новая миграция создаёт только интеграционную таблицу. Seed не нужен и не запускается.

### Настройки агента

Все переменные перечислены в [.env.example](../.env.example). `DMB_DATA_API_URL` для локального режима: `https://127.0.0.1:9450/internal/backlog-assistant/v1`. `ASSISTANT_STATE_DIR` лучше задать абсолютным путём в `.runtime/`; это каталог временных UUID instances. `ASSISTANT_RUNTIME=opencode`; fake допускается только при `ASSISTANT_SYNTHETIC_ONLY=true`.

### Настройки DMB

В `dmb-backlog/.env`: `BACKLOG_ASSISTANT_SERVICE_URL=https://127.0.0.1:9400`, `BACKLOG_ASSISTANT_GATEWAY_SECRET` и `BACKLOG_ASSISTANT_SERVICE_TOKEN` совпадают с агентом. `BACKLOG_ASSISTANT_TLS_CA/CERT/KEY` — сертификаты DMB. `BACKLOG_ASSISTANT_ENABLED=false`, `BACKLOG_ASSISTANT_KILL_SWITCH=false`, `BACKLOG_ASSISTANT_PILOT_USER_IDS=` остаются безопасными исходными значениями до приёмки. Пилот ограничивается IDs существующих пользователей; изменение защищённых учётных записей не требуется.

## Запуск и остановка

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-project.ps1
```

Сначала проверяются предпосылки помощника, затем выполняется стандартный запуск проекта. Дополнительный скрипт применяет только миграцию собственной БД агента, запускает Data API (9450) и Agent API (9400), проверяет оба health endpoint по mTLS. Логи — `.runtime/backlog-assistant*.out.log` и `.err.log`. Документация внутреннего API доступна только с клиентским сертификатом; браузер работает через `http://127.0.0.1:8000/#/backlog-assistant`.

`scripts/project-status.ps1` показывает отдельные процессы; для защищённых endpoints сообщает необходимость mTLS-проверки. Из каталога агента с загруженными настройками: `python -m service.preflight --health`.

`scripts/stop-project.ps1` останавливает также оба дополнительных процесса. При принудительном завершении контроллера контейнер ограничен собственной жизнью 90 секунд; при следующем запуске janitor удаляет оставшееся состояние по сохранённой identity. Отсутствие Docker daemon не считается подтверждением очистки.

Для быстрого отключения доступа выставить `BACKLOG_ASSISTANT_KILL_SWITCH=true` и перезапустить DMB gateway/Data API: новые действия запрещены, последующие проверки активных grants отклоняются. Отмена отдельного вопроса доступна в интерфейсе. Отключение UI не удаляет историю автоматически.

## Что ещё требуется перед пилотом

Реальные сертификаты, отдельная БД, выбранный набор существующих пользователей, разрешение на обработку предметных данных выбранным провайдером и результаты оценки качества. На локальной машине отдельная БД, сертификаты и allowlist уже настроены по запросу пользователя; их секреты находятся только в игнорируемых `.env` и `.runtime/`. Локальные leaf-сертификаты выданы на 90 дней; перед истечением их нужно перевыпустить. Подробные границы проверки — [TESTING](TESTING.md).


## Ограничения запуска, проверено 15.10.2026

Docker resolver/cleanup-команды ограничены по времени; зависший CLI-процесс завершается. Служебный адрес `host.docker.internal` кешируется на пять минут для закреплённого образа, без пользовательского состояния и credentials. При неподтверждённой очистке сохраняется признак `cleanup_pending`.

Оценочный стенд Windows располагает примерно 8 ГБ RAM; одновременный запуск тяжёлых тестов увеличивает холодный старт OpenCode. Для функционального оценочного набора используется последовательный режим. Native launcher остаётся разрешённым только для синтетического DataPort; рабочий сервис по-прежнему использует Docker с прежними сетевыми ограничениями.

## Повторный запуск, проверено 15.10.2026

`start-backlog-assistant.ps1` перед запуском определяет владельцев портов 9400/9450. Перезапускаются только Python-процессы с ожидаемым модулем; чужой процесс вызывает явный отказ. После mTLS health проверяется, что listener принадлежит новому launcher, и в `.runtime/*.pid` сохраняется PID реального сервера, а не промежуточного venv-процесса. Это устраняет оставшийся дочерний процесс и ложную успешность health-check. Два последовательных перезапуска проверены.
