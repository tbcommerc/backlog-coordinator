# Оценка на 80 примерах

Набор `corpus.py` фиксирует распределение 30/20/10/20 из продуктового проекта. Эталон не передаётся модели. `run.py` запускает настоящий OpenCode 1.17.13, контролируемый ModelBroker и ToolBridge. На 72 вопросах используется настроенная модель; восемь оставшихся случаев детерминированно внедряют отказы. Отказы не засчитываются как успешные ответы модели.

Данные синтетические и существуют в памяти. Пользователи, роли, команды и справочники в БД не создаются. `data.py` — реализация тестового DataPort, а не доказательство правильности SQL. Она использует тот же серверный `presentation.present`, что и DMB. Реальные SQL-предикаты отдельно проверяются `postgres_domain.py` на 1101 временной задаче в собственной БД помощника. Защищённые справочники заменены заглушками в памяти.

Основные проверки: точный состав объектов, top-5, количество и суммы с неизвестными значениями, интервал UTC/МСК, нужное уточнение, отсутствие запрещённых объектов и неподтверждённых чисел. Свободная проза модели не публикуется: сервер формирует проверяемые факты. Наличие корректного JSON само по себе не означает успешный пример.

Успешный результат с fallback помечается отдельно от полного модельного цикла. Задержки, ошибки, модельные запросы и очистка сохраняются для каждого случая. Корпус и метаданные с хешами инструкций и схемы сохраняются рядом с результатом. Финальный отчёт обязан перечислять все отказы, даже если позднее повтор прошёл.

Из `backlog-assistant`:

```powershell
.\.venv\Scripts\python.exe -m evaluation.run --output evaluation/results/run.jsonl --parallel 1
# Только синтетический диагностический запуск без контейнера:
.\.venv\Scripts\python.exe -m evaluation.run --native --output evaluation/results/native.jsonl --parallel 1
```

Из корня (зависимости DMB):

```powershell
.\.venv\Scripts\python.exe backlog-assistant/evaluation/postgres_domain.py
```

Полный набор не доказывает отсутствие любых ошибок и не заменяет нагрузочный пилот. Отдельно фиксируются ограничения стенда и недостигнутые пороги.
