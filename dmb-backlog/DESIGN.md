# Дизайн Backlog Coordinator

Проверено по реализации: 04.11.2026. Контекст для агента и Impeccable.

Для одного параметра с взаимоисключающими значениями утверждён вариант А:
[SegmentControl](docs/SEGMENTED_CONTROL.md), общая нейтральная подложка и
подвижная выбранная поверхность. Для навигации остаются вкладки, для независимых
условий — чипсы и checkbox/switch. Использовать общий компонент без локального
переоформления; размеры соответствуют соседним контролам UI Kit.

Это рабочая система для ежедневного поиска, сопоставления и обработки задач.
Режим проектирования — Operate: сдержанный интерфейс, читаемая плотная информация,
предсказуемые действия. Не использовать эстетику лендинга для рабочих реестров.

Источник правил — [UI Kit](docs/UI_KIT_CONTRACTS.md),
[дизайн-система](docs/DESIGN_SYSTEM.md) и
[протокол визуальной приёмки](docs/UI_KIT_REVIEW_PROTOCOL.md).
Этот файл не вводит независимую палитру, шкалу отступов или размеры контролов.

Перед реализацией выбрать [композицию страницы](docs/UI_PAGE_COMPOSITIONS.md):
реестр, карточка, реестр с инспектором. Записать основной сценарий, главное действие,
порядок блоков и что должно быть доступно на первом экране. Сначала композиция,
затем компоненты, затем детали оформления.

Нельзя компенсировать плохую компоновку уменьшением шрифта, скрытием необходимой
информации или ослаблением UI Kit. Второстепенные фильтры допустимо перенести в
раскрываемую панель, если активное условие видно и его можно отменить.
Внутри одной карточки применять `sectionCard({variant:'plain'})`, если рамка
не обозначает самостоятельный объект.

Пилот: реальные рабочие задачи в полной оболочке приложения, изолированные API,
длинные русские названия, обе темы, 1440×900 / 1366×768 / 390×844.
`npm run test:design` проверяет Windows Chromium screenshots; общий E2E-прогон
на других ОС проверяет поведение и сохраняет снимки без сравнения с Windows.
Снимок-эталон фиксирует выбранное состояние, но не означает одобрения пользователя.

Не выдавать screenshots изолированного стенда за проверку работающей БД, прав,
реальных сохранений или пользовательскую приёмку. Итог всегда разделять на
функциональность, визуальную оценку и соответствие UI Kit.
