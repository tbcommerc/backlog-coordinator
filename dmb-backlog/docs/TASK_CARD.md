# Карточка задачи бэклога

Проверено по реализации и парной fixture-проверке: 11.11.2026. Live-приёмка
всех сценариев остаётся отдельной открытой проверкой. Активная реализация —
[modal.js](../frontend/js/components/modal.js), `renderTaskDetailModal` →
`cardInit` → `cardBodyMainV30`. Старые render-функции не являются AS-IS.

Композиция «карточка»: идентификатор и единственное название → шесть вкладок →
рабочая сводка (статус, исполнитель, срок, приоритет, прогресс) → описание с
внутренним комментарием → участники и классификация → четыре показателя →
раскрываемые трудозатраты, стоимость и обоснования. «Все атрибуты» раскрывает
дополнительные свойства внутри участников. В полном редакторе шапка сохраняет
название, а тело начинается формой: название; статус, исполнитель, срок;
приоритет, прогресс, команда; описание и внутренний комментарий.
Остальные бизнес-поля доступны ниже формы без дополнительных раскрытий.
Полное display name API не сокращается. Пустой исполнитель — «Не назначен»,
пустой срок — «Не указан».

Внутренние разделы используют `SectionCard` с `variant: plain`, поля —
`ReadOnlyField`, сводка — пять колонок на desktop и две на mobile. Отчётные встречи
остаются отдельными объектами. Справка показателей, обоснования и трудозатраты
используют общий Disclosure/SectionCard. Основная композиция оформлена именованным
вариантом `ui-task-detail-composition`, оболочка — `ui-task-dialog` (1160 px).
Редактор использует три колонки на desktop и две на mobile. Срок выбирается из
действующего справочника, команда остаётся редактируемой при наличии права:
статичный прототип не заменяет эти бизнес-контракты. У короткого прошлого статуса нет
искусственной высоты; длинный раскрывается, редактор имеет собственную высоту.

## Вторичные вкладки — проверка 11.11.2026

Именованная композиция `ui-task-secondary` находится в
[`task-secondary-composition.css`](../frontend/css/ui/task-secondary-composition.css).
Отчётные статусы — полноширинные блоки с предыдущим и текущим текстом;
пустые встречи компактны, редактор открывается явно. Прошедшая дата подписана
«Встреча», будущая — «Следующая». Каждая встреча сохраняется отдельно.
Обсуждение — лента с вложенными ответами и единственным редактором снизу;
счётчик вкладки учитывает ответы. Материалы располагаются до списка файлов,
ниже списка находится зона загрузки. Системные сведения свёрнуты отдельно.
История — хронологическая лента от новых изменений к старым, с автором,
датой и значениями до/после. Рабочие задачи — список с единым поиском,
фильтром статуса, созданием/привязкой и внешними связями; общий рабочий
реестр сохраняет свою прежнюю композицию. Права и API определяют действия.

Вспомогательный диалог требований AI использует `ui-task-requirements`,
отдельный список отметок/полей/состояний и общие кнопки. Конфликт версий
использует именованный `ui-task-conflict-table` с читаемыми колонками выбора
и горизонтально переносимую панель действий; на узком экране таблица
прокручивается внутри области сравнения. Жизненный цикл диалогов сохраняет
фокус и закрывает только верхний слой по Escape.

С 11.11.2026 новые записи истории PATCH сохраняют числовой ноль как `"0"`,
отличая его от `null`. Ранее потерянные нули, записанные сервером как `null`,
не восстанавливаются предположениями и не переписываются. Рендер показывает
нулевые значения, а отсутствующее новое значение — «Не указано».

Вторичные вкладки проверены в fixture на 1440, 390 и 320 px, светлой и тёмной
темах. Парное сравнение с прототипом выполнено на 1440 и 390 px. Реальные
URL, число доступных видов встреч, названия статусов и права не заменяются
демонстрационными данными ради визуального совпадения. См.
[свежие снимки](../artifacts/task-card-secondary-2026-11-11/) и
[парное сравнение](../artifacts/task-card-secondary-reference-2026-11-11/).

## Сохранение

Все поля задачи, включая inline-приоритет и срок, изменяются только в черновике.
Запись выполняется кнопкой «Сохранить», Ctrl+S либо Ctrl+Enter. Счётчик отражает
diff; возврат значения к исходному убирает изменение. Двойная отправка блокируется.
Ошибка сохраняет ввод; конфликт не перезаписывается молча. Выход предлагает
сохранить, продолжить редактирование или отказаться. Переключатели команд и меток
передают `aria-pressed` и сохраняют фокус после перерендера.

Undo использует версию ответа конкретного сохранения, а не более новую версию
последующего чтения. Конфликт версии отменяет undo. Результат и действие отмены
показаны общим Alert в потоке перед нижней панелью: сообщение не закрывает кнопки.
Действие undo не исчезает по таймеру; следующий результат заменяет его.

Отчёт встречи, публикация комментария и загрузка файла — самостоятельные
операции. Нижняя кнопка «Редактировать задачу» не редактирует опубликованный
комментарий или рабочую задачу. Объяснение readonly выводится обычным текстом.
Отчётные черновики хранятся независимо для каждой встречи; повтор чтения их не
стирает и не подменяет сохранённую в черновике версию.

## Состояния и вторичные поверхности

Файлы и история различают loading, успешную пустоту, данные, ошибку первого
чтения и stale-данные. При ошибке сохраняются строки и счётчики; «Повторить»
повторяет запрос на текущей вкладке. Отменённый/устаревший ответ не применяется.
Вкладка истории и отчётов активируется до ожидания запроса.

AI-требования используют общую регистрацию диалога и находятся вне CSS-области
карточки. Один Escape закрывает один слой; фокус возвращается на кнопку AI.
Восстановление фокуса не переоткрывает подсказку поверх только что закрытого окна.
Следующий Escape закрывает карточку. Реальный AI-сервис этим изменением не запускается.

«Материалы и требования» содержат макеты, Jira и БТ в полях задачи. «Внешнее
исполнение» находится в рабочих задачах и использует отдельную модель ссылок.
Данные между ними не переносятся. Новые ссылки проверяются общим HTTP(S) allowlist;
дубликат внутри одного списка отклоняется без потери ввода. Изменения ссылок
сохраняются вместе с задачей. Встроенный поиск рабочих задач выполняется при вводе;
лишние submit и раскрытие поиска убраны только из связанного списка.

## Числа

Прогресс редактируется целым числом от 0 до 100 с шагом 1. Значение не округляется
до ближайших пяти; пустое, дробное или выходящее за диапазон значение не сохраняется.
Финансовый эффект в рабочей сводке сохраняет единицу «млн ₽» после динамического
обновления; null остаётся «Не рассчитан», а ноль отображается как известное значение.

Ноль трудозатрат отличается от null/undefined/пустого значения. Стоимость известна,
только если для всех заданных трудозатрат известны ставки; неизвестная ставка не
превращается в нулевую стоимость. Нулевая известная ставка допустима. C/V и выбор
года ставки сохраняют предметную формулу; нулевой знаменатель не даёт Infinity.
Hard — завершённость, Soft — взаимодействие; ЭО — экспертная оценка, ФТЗ — факт.
На узком экране таблица трудозатрат использует общий вариант UI Kit
`data-ui-responsive="scroll"`: колонки доступны горизонтальной прокруткой,
контейнер доступен с клавиатуры, числа не сжимаются до отдельных символов.
