# Политика изменения схемы базы данных

> Статус: проверено по `backend/models.py`, `backend/database.py` и цепочке
> запуска `backend/main.py` на 2026-08-24.

## Источник истины

Единственный поддерживаемый источник структуры базы данных — SQLAlchemy-модели в
`backend/models.py`. При старте приложения `backend/database.py:ensure_schema()`:

1. создаёт отсутствующие таблицы через `Base.metadata.create_all()`;
2. сравнивает колонки существующих таблиц с моделями;
3. добавляет отсутствующие колонки через `ALTER TABLE ADD COLUMN`.

## Добавление таблицы или колонки

1. Изменить `backend/models.py`.
2. Проверить совместимость значения по умолчанию и nullable-ограничений с уже
   существующими строками.
3. Перезапустить сервер и проверить startup-логи.
4. Выполнить read-only smoke-проверку приложения.

Не нужно вручную выполнять SQL, Alembic или скрипты из `backend/migrations/`.

## Ограничения

`ensure_schema()` предназначен только для аддитивных изменений. Он не выполняет:

- переименование или удаление таблиц и колонок;
- изменение типов и ограничений существующих колонок;
- backfill или иное преобразование бизнес-данных;
- автоматический откат схемы.

Для такого изменения нужен отдельный согласованный план обслуживания: резервная
копия, проверенный одноразовый сценарий, окно выполнения, проверка результата и
процедура восстановления. Выполнение операции с данными требует отдельного явного
разрешения владельца системы.

## Legacy-артефакты

`backend/alembic/`, `backend/alembic.ini` и `backend/migrations/` не входят в
поддерживаемую цепочку запуска или развёртывания. Они сохранены только для изучения
истории проекта и не должны запускаться без отдельного решения о миграционной
стратегии.
