## Интерфейс

Маршрут `#/work-tasks?display=board`. Переключатель «Список / Доска / Сводка» сохраняет общие условия, выбранную задачу и контекст рабочего места. Используется существующая [карточка рабочей задачи](WORK_TASKS.md), включая результат, комментарии, файлы, историю, приоритет и чек-лист. На широком рабочем месте карточка открывается справа; на узком — диалогом, на мобильном — на весь экран. Изменения фильтров не закрывают карточку; если задача перестала соответствовать выборке, появляется пояснение.

Пять основных колонок: «Новые», «К исполнению», «В работе», «На приёмке», «Выполнены». Отменённые вынесены в отдельный сворачиваемый раздел. Колонка, исключённая фильтром, показывает «Скрыта фильтром», а не ложный нулевой счётчик. По умолчанию показаны активные задачи; выполненные можно добавить за последние 7 или 30 календарных дней Москвы либо за весь период.

Компактная карточка показывает название, контекст, следующего участника, срок, прогресс чек-листа и исключения. Высокий и срочный приоритеты выделены; обычный не создаёт лишнего визуального шума. Полные описания, результаты и пункты чек-листа загружаются только общей карточкой.

Каждая колонка независимо листается по 20 задач. Перелистывание заменяет страницу, не накапливает DOM. Положение прокрутки и курсоры сохраняются в sessionStorage отдельно для пользователя и условий. На мобильном экране отображается одна выбранная колонка; выбор колонки отражается в URL. Горизонтальное положение доски сохраняется при возврате из карточки.

Меню действий — основной способ управления, доступный с клавиатуры и на сенсорном экране. Drag-and-drop дополнительно включён для точного указателя: захват доступен за название, контекст, исполнителя и свободную область карточки. Меню и раскрытие препятствия сохраняют собственные действия. Обычный клик открывает карточку; перенос начинается после движения на 6 px. Допустимые цели определяет сервер. Перенос, требующий результата, причины или назначения, открывает существующую форму; отмена не меняет статус. Двойные команды блокируются на время записи. При 409 введённые значения сохраняются, требуется повторное открытие актуальной карточки и осознанная отправка.

**Исправление захвата, проверено 29.10.2026:** ранее обработчик разрешал захват
только непосредственно за пустой отступ карточки и игнорировал её содержимое.
Регрессия за название сначала воспроизвела отказ. После исправления **8 PASS**:
захват за название/контекст/исполнителя, Escape, обычный клик, недопустимая цель,
форма обязательного результата, меню и настольная геометрия.

SSE обновляет доску с объединением событий (350 мс, не более 2 с ожидания); открытое меню не уничтожается обновлением. Возвращение во вкладку, восстановление сети и смена календарной даты обновляют выборку. Редактор сохраняет ввод при внешних изменениях и сообщает о новой версии. Есть ручное обновление, состояние отсутствия сети и повтор отдельной страницы после ошибки.

## API и доступ

Все маршруты ниже имеют префикс `/api/v1`. Доступ проверяется сервером через действующую политику WorkTask. Клиенты заказчиков не получают доску; наблюдатель видит только доступные задачи без команд записи.

| Метод и маршрут | Назначение |
|---|---|
| GET `/work-tasks/options` | Дополнительно возвращает `board_enabled` |
| GET `/work-tasks/board` | Колонки, первые страницы, точные счётчики, сводка, коллекции, нормализованные условия и ключ запроса |
| GET `/work-tasks/board/columns/{column_status}` | Независимая страница колонки с курсором |
| POST `/work-tasks/{id}/transitions` | Существующая версионная команда, общая для списка, доски и карточки |

Общие фильтры списка и доски реализованы в `backend/services/work_query.py`: коллекция `view`, `status`, поиск `q`, команда, исполнитель, родитель, направление, приоритет, проект, признаки внимания, `done_period`, сортировка. `effective_project_id` учитывает прямой проект либо проект доступного родителя; недоступный родитель не раскрывается. Старый `project_id` сохраняет значение прямой связи. Для `status` добавлено `active_done`; значения `active`, конкретные статусы и пустое значение сохранены. Ошибочные значения не расширяют выборку молча.

`page_size` от 1 до 50, по умолчанию 20. `selected_id` в начальном запросе позволяет вернуть `selected_matches` для открытой карточки. Колонка содержит `state`, `total`, `items`, `range_start/end`, `next_cursor`, `previous_cursor`; у исключённой колонки `total=null`. Компактный DTO включает `transition_options` с целями, подписью, доступностью и требуемыми полями. Бизнес-политика переходов общая с карточкой; клиент не назначает произвольный статус.

Курсор подписан HMAC, содержит границу сортировки, направление, время, пользователя, размер страницы и ключ условий; действует 30 минут. Неверная подпись/формат даёт 400, устаревший или не соответствующий условиям курсор — 409. Проверки ACL повторяются на каждой странице. Сортировки детерминированы сроком и ID; keyset-пагинация не использует offset для чтения карточек. PostgreSQL читает первоначальную доску в REPEATABLE READ, связанные имена и контексты выбираются пакетно. SQL-выборки не загружают учётные данные пользователей.

## Включение и откат

`WORK_TASK_BOARD_ENABLED=false` по умолчанию. Для локальной приёмки включено `true` в локальном `.env`; файл не предназначен для Git. После изменения переменной требуется перезапуск backend. При отключении API доски отвечает 404, переключатель скрыт, прямой вход с `display=board` возвращает список. Действующие задачи и история сохраняются.

При включении старая внутренняя ссылка `#/kanban` перенаправляет на рабочие задачи, её пункт меню скрыт. Старый ID продуктовой задачи не переносится в WorkTask. При выключении прежний канбан остаётся доступным. R2 (WIP, метрики потока) не реализован в этом этапе.

Новых таблиц, колонок, индексов и миграций не потребовалось: используется модель WorkTask этапа 2. Изменений защищённых справочников, пользователей, ролей и состава команд нет.

Синтетические WRK-64–72 отменены после проверки. Ошибок JavaScript в успешных прогонах не зарегистрировано. После последнего штатного запуска повторены чтение PostgreSQL и открытие карточки: положительные ID, пять колонок, первая карточка на 235 px, заголовок 14 px/500, нет горизонтального overflow на 1440/390 px.

Таблицы TEMP и транзакционный rollback: постоянная БД не пополняется.
