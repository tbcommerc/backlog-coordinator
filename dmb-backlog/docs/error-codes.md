# Справочник кодов ошибок быстрого редактирования

## Как читать этот справочник

Каждый код ошибки содержит:
- **HTTP статус** — числовой код, который отображается в модальном окне ошибок
- **Метка** — краткое название для пользователя
- **Описание** — понятное объяснение для пользователя
- **Причина** — техническая причина для администратора
- **Решение** — что делать администратору

---

## Клиентские ошибки (4xx)

### 400 — Неверный запрос
| Поле | Значение |
|------|----------|
| **Метка** | Неверный запрос |
| **Описание** | Сервер не смог обработать запрос из-за некорректных данных |
| **Причина** | Запрос содержит malformed JSON, неверный тип данных или отсутствует обязательное поле |
| **Решение** | Проверить консоль браузера (F12) для деталей запроса. Убедиться что отправляемые данные соответствуют схеме TaskUpdate |

### 401 — Сессия истекла
| Поле | Значение |
|------|----------|
| **Метка** | Сессия истекла |
| **Описание** | Авторизация истекла — войдите в систему заново |
| **Причина** | JWT token expired, refresh token не сработал или отсутствует |
| **Решение** | Пользователю перезайти в систему. Если проблема повторяется — проверить настройки JWT_EXPIRE_MINUTES в config.py |

### 403 — Нет прав
| Поле | Значение |
|------|----------|
| **Метка** | Нет прав |
| **Описание** | У вас недостаточно прав для изменения этой задачи |
| **Причина** | Роль пользователя не имеет разрешения `backlog_team: write_own` или `backlog_dmb: read_write` |
| **Решение** | Проверить роль пользователя в админ-панели. Убедиться что роль имеет нужные права. Проверить что пользователь принадлежит команде задачи (для write_own) |

### 404 — Не найдено
| Поле | Значение |
|------|----------|
| **Метка** | Не найдено |
| **Описание** | Задача не найдена — возможно, она была удалена |
| **Причина** | Задача с указанным ID не существует или помечена как is_deleted=True |
| **Решение** | Обновить страницу (F5). Если задача действительно удалена — убрать её из кэша фронтенда |

### 409 — Конфликт версий
| Поле | Значение |
|------|----------|
| **Метка** | Конфликт версий |
| **Описание** | Задача была изменена другим пользователем — обновите страницу |
| **Причина** | Optimistic lock: submitted_version != task.version. Другой пользователь или процесс изменил задачу между моментом загрузки и сохранением |
| **Решение** | Это штатное поведение. Пользователю обновить страницу и повторить изменения. Проверить что lock_until не истекает слишком быстро (LOCK_DURATION_MINUTES в tasks_router.py) |

### 422 — Ошибка валидации
| Поле | Значение |
|------|----------|
| **Метка** | Ошибка валидации |
| **Описание** | Одно или несколько полей содержат недопустимые данные |
| **Причина** | Pydantic validation error: значение не соответствует типу, выходит за границы (ge/le), превышает max_length и т.д. |
| **Решение** | Проверить консоль браузера для деталей. Типичные случаи:<br>• **string too long** — текст превышает max_length в схеме<br>• **greater than / less than** — число вне диапазона<br>• **not a valid** — недопустимое значение (например, несуществующий ID) |

### 423 — Заблокировано
| Поле | Значение |
|------|----------|
| **Метка** | Заблокировано |
| **Описание** | Задача редактируется другим пользователем |
| **Причина** | Активный lock: task.lock_owner_id != current_user.id и lock_until ещё не истёк |
| **Решение** | Подождать пока другой пользователь закончит редактирование (lock истекает через LOCK_DURATION_MINUTES = 15 мин). Или проверить что пользователь сам захватил lock перед редактированием |

### 429 — Слишком много запросов
| Поле | Значение |
|------|----------|
| **Метка** | Слишком много запросов |
| **Описание** | Подождите немного и попробуйте снова |
| **Причина** | Rate limiting: слишком много запросов за короткий период |
| **Решение** | Подождать 30-60 секунд. Если проблема системная — проверить настройки rate limiter в middleware.py |

## Серверные ошибки (5xx)

### 500 — Ошибка сервера
| Поле | Значение |
|------|----------|
| **Метка** | Ошибка сервера |
| **Описание** | Внутренняя ошибка — обратитесь к администратору |
| **Причина** | Unhandled exception в бэкенде. Типичные случаи:<br>• **notifications** — ошибка вставки уведомления (NOT NULL constraint, missing column)<br>• **constraint / not null** — нарушение целостности данных<br>• **unique** — нарушение уникальности (duplicate key)<br>• **foreign key** — ссылка на несуществующую запись |
| **Решение** | 1. Открыть логи сервера (stdout или файл)<br>2. Найти строку `[update_task] ERROR` с traceback<br>3. Определить причину по тексту ошибки<br>4. Если ошибка в миграции БД — запустить `python migrations/...`<br>5. Если ошибка в модели — добавить недостающее поле в models.py |

### 502 — Сервер недоступен
| Поле | Значение |
|------|----------|
| **Метка** | Сервер недоступен |
| **Описание** | Бэкенд временно не отвечает — попробуйте позже |
| **Причина** | Сервер упал, перезагружается или не слушает порт 8000 |
| **Решение** | Проверить что процесс Python запущен: `Get-Process -Name python`. Перезапустить: `python main.py` |

### 503 — Сервер перегружен
| Поле | Значение |
|------|----------|
| **Метка** | Сервер перегружен |
| **Описание** | Сервер временно не обрабатывает запросы |
| **Причина** | Сервер перегружен запросами или находится в режиме обслуживания |
| **Решение** | Подождать и повторить. Проверить нагрузку на сервер. |

## Диагностика

### Шаг 1: Откройте консоль браузера (F12)
Ищите строки:
- `[save] PUT /tasks/XXX` — что отправляется
- `[save] Failed task #XXX` — что вернул сервер

### Шаг 2: Проверьте логи сервера
Ищите строки:
- `[update_task] task_id=XXX, update_data={...}` — входящие данные
- `[update_task] ERROR task_id=XXX: ...` — ошибка с traceback

### Шаг 3: Проверьте БД
```bash
cd backend
python -c "import sqlite3; conn = sqlite3.connect('dmb_backlog.db'); print([r[1] for r in conn.execute('PRAGMA table_info(tasks)').fetchall()]); conn.close()"
```

## Частые проблемы и решения

| Симптом | Причина | Решение |
|---------|---------|---------|
| `NOT NULL constraint failed: notifications.type` | Колонка type есть в БД, но не заполняется | Добавить `type=category` в notifications.py |
| `NOT NULL constraint failed: notifications.message` | Колонка message есть в БД, но не заполняется | Добавить `message=title[:500]` в notifications.py |
| `task has no attribute 'xyz'` | Поле удалено из models.py, но осталось в seed.py или фронтенде | Удалить упоминание из всех файлов |
| `403 Forbidden` на admin/* | У пользователя нет admin_access | Назначить роль с admin_access в админ-панели |
| `409 Conflict` | Version mismatch | Обновить страницу, проверить lock |
