# Протокол сквозного ревью UI Kit

Проверено по коду: 27.10.2026. Область: активный SPA Backlog Coordinator, включая lazy routes, карточки, встроенные редакторы и диалоги. Протокол заменяет вывод о полноте по количеству зелёных тестов. Он не отменяет предметные правила страниц.

## Единица проверки

Единица — конкретный сценарий: поверхность × функция × роль × состояние × тема × ширина × способ ввода. «Страница проверена» без этих измерений не является приёмкой. У каждого результата есть источник кода, сценарий, ожидаемое поведение, фактическое наблюдение, дата и доказательство.

Три независимых уровня: `code` — анализ реализации; `fixture` — настоящий компонент с изолированными данными; `live` — работающая система с готовой QA-учёткой. Успех одного уровня не переносится на другой. Исторический отчёт сохраняет дату и область, но не становится текущей проверкой автоматически.

## Поиск неизвестных реализаций

1. Генерировать `frontend/ui-catalog/review-inventory.json`: все активные JS-модули вне vendor/legacy, импорты, render/open/show/init entry points, статическая карта роутов, места динамической маршрутизации и кандидаты по 30 семействам поведения.
2. Сопоставить карту с меню, lazy imports, параметризованными карточками, вкладками, overlay и редакторами. 117 строк прежней матрицы — исходный материал, не доказательство полноты.
3. Для каждого семейства прочитать все найденные реализации. Поиск по экспорту UI Kit недостаточен: проверяются HTML, обработчики событий, локальные CSS и пользовательские действия. Regex-кандидат может быть ложным; отсутствие совпадения не доказывает отсутствие функции.
4. Проверить обратное направление: каждый найденный элемент страницы должен соответствовать общему контракту, обоснованному предметному исключению или зарегистрированному дефекту. Не ограничиваться только семействами, которые уже есть в UI Kit.
5. Сопоставить контрольные снимки одинаковой функции на разных страницах при одинаковых теме, ширине и данных. Отдельно сравнить последовательность действий, подписи, клавиатуру, фокус, disabled/busy и ошибки.

## Обязательные измерения

| Измерение | Требования |
|---|---|
| Роли | Готовые admin, tribe-lead, BA своей/чужой/без команды, PO/PL/CL, IT PL, customer связанный/чужой/без связи, no-access; неактивный — только отказ входа. Для каждого экрана записать применимость и ожидаемые права, а не просто список входов |
| Данные | 0, 1, граница страницы N/N+1, много; длинный русский текст, неразрывная строка, null, ноль, большие значения, отсутствующая ссылка |
| Состояния | loading, ready, empty, filtered-empty, error/retry, partial/stale, forbidden, readonly, disabled, busy, validation, save-success, save-error, conflict, cancel/unsaved, hidden |
| Переходы | Первая/средняя/последняя страница; фильтр после дальней страницы; сортировка/смена представления при выборе; закрытие и возврат фокуса; навигация при несохранённом; устаревший асинхронный ответ |
| Среда | Светлая и тёмная темы; 320/390/1440 px, короткий экран, zoom 200%; pointer, touch, клавиатура; длинные данные не заменять пустыми |
| Доступность | Имя и роль, aria-current/pressed/expanded, ошибки и описания, порядок Tab, видимый focus, Escape, возврат фокуса, объявления результата, контраст, reduced motion/forced colors |

Полный декартов перебор не подменяется словом «всё». Для каждой поверхности фиксируется обязательный набор и причины сокращения. Общая геометрия проверяется на представителях плюс всех локальных отклонениях; права, асинхронные переходы и сохранение — на каждом соответствующем потребителе.

## Очерёдность

1. Навигация и реестры: пагинация, поиск, фильтры, сортировка, выбор, массовые действия, таблица/карточки, сохранённые представления.
2. Состояния и обратная связь: пустота, загрузка, ошибки, повтор, toast/alert, счётчики, статусы, прогресс.
3. Ввод и операции: поля, validation, busy, формы/диалоги, подтверждение, unsaved/conflict, файлы.
4. Композиции: вкладки, меню, popover/tooltip, collapse, даты, аватары, графики, drag/drop, экспорт и ссылки.
5. Повторный независимый проход по глаголам пользователя: найти → отфильтровать → выбрать → перейти → открыть → изменить → сохранить/отменить → восстановить после ошибки. Не использовать список уже исправленных дефектов как единственный маршрут.

## Контроль полноты

- `npm run check:ui-review` проверяет актуальность обнаружения и структуру доказательств. Его PASS не означает приёмку интерфейса.
- `npm run check:ui-acceptance` требует завершённой маршрутизации, разборов семейств и живых доказательств для заявленных сценариев. Непроверенные строки оставляют итог INCOMPLETE.
- `npm run verify:ui-kit` остаётся регрессией компонентов и изолированных потребителей, а не сертификатом полного продуктового ревью.
- Новые потребители или маршруты требуют разбора diff реестра. Новый тест должен воспроизводить нарушение и сохранять пользовательскую возможность; нельзя просто ослаблять assert или обновлять снимок без проверки разницы.
- Исключение имеет область, причину, альтернативный контракт и доказательство. Например, неизвестное число страниц при курсорном API не позволяет показывать вымышленные номера; append сохраняет уже загруженные элементы и отличается от замены страницы.
- Завершение: нет неразобранных реализаций, подтверждённых открытых дефектов и необоснованных исключений; обязательные сценарии имеют доказательства. Если это условие не выполнено, отчёт перечисляет остаток и не говорит «всё проверено».

## Ограничения данных

Защищённые сущности в живой БД — только чтение и открытие форм без сохранения. Изолированные fixture не пишут в БД. Отсутствующие данные/профили отмечаются конкретно; их нельзя заменить предположением или молча создать защищённые записи. Находка, исправление и повторная проверка ведутся раздельно.

27.10.2026: verify:ui-kit автоматически включает все frontend unit-тесты и все frontend/e2e/*.spec.mjs, включая потребителей без префикса uiKit. Ни ручной список, ни название файла больше не могут незаметно исключить существующий сценарий. Отдельно проведён разбор динамических ветвей router.js; записи code-reviewed не являются live-приёмкой. Сырые наблюдения без записанной темы/ширины не повышаются до accepted.

28.10.2026: component fixture рабочих экранов загружает CSS из frontend/index.html с сохранением порядка; отдельная unit-проверка закрепляет подключение. Нельзя исправлять конфликты каскада только в стенде. Длинные составные проверки разделяются на независимые сценарии (включая каждый импортный файл); общий таймаут не должен скрывать, какая возможность осталась непроверенной.

28.10.2026: обнаружение сохраняет именованные UI-импорты exported/local/from/line и не зависит от псевдонима. Неподдержанный namespace/dynamic UI import должен сначала получить обработку в обнаружении; отдельный gate не позволяет молча его пропустить. Поведенческий поиск остаётся независимым и может давать ложные кандидаты: обязательны disposition/reason, а не массовая миграция по одному совпадению слова.

## Уточнение области — 28.10.2026

При аудите унификации единица работы — семейство компонента и все его реализации. Маршруты, роли и состояния выбираются для сравнения этого семейства. Общий функциональный прогон, число просмотренных страниц и найденные гонки запросов не являются показателем завершения унификации. Сопутствующие функциональные находки учитываются отдельно. Для каждого потребителя фиксируются общий владелец или конкретное семантическое исключение; результат code-reviewed не объявляется полной приёмкой UX.
