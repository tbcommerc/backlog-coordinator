# Документация DMB Backlog

Начальная точка для изучения фактически реализованной системы — [`PROJECT_OVERVIEW_AS_IS.md`](PROJECT_OVERVIEW_AS_IS.md). После неё открывай только документ, относящийся к текущей задаче.

## Правило доказательности

Документация должна описывать только то, что подтверждено исполняемым кодом, конфигурацией, моделями, API, тестами, фактическим интерфейсом либо прямым решением пользователя.

Запрещено:

- додумывать отсутствующий функционал и пользовательские сценарии;
- описывать заглушку, интерфейс или пример конфигурации как работающую интеграцию;
- придумывать роли, права, владельцев, SLA, RTO, RPO, метрики и инфраструктуру;
- выдавать целевое решение или рекомендацию за текущее состояние;
- считать существующий документ источником истины без сверки с реализацией.

Если доказательств недостаточно, используй один из вариантов:

- `AS-IS PARTIAL` — подтверждена только явно перечисленная часть;
- `TO-BE APPROVED` — целевое решение прямо утверждено пользователем;
- `OPEN QUESTION` — требуется проверка или решение пользователя.

Статус `AS-IS VERIFIED` допустим только после фактической проверки утверждений по первичным источникам.

## Приоритет источников

При расхождении сведений используй следующий порядок:

1. исполняемый код и модели;
2. конфигурация;
3. автоматические тесты;
4. фактический OpenAPI и работающий интерфейс;
5. прямое решение пользователя;
6. существующая документация.

Расхождение не исправляй догадкой: зафиксируй его и укажи, какие сведения требуют подтверждения.

## Как обновлять документ

1. Указать область проверки.
2. Найти первичные источники для каждого существенного утверждения.
3. Отделить подтверждённое AS-IS от целевого состояния.
4. Неподтверждённое перенести в `OPEN QUESTION` или удалить.
5. Проверить команды, пути, ссылки и примеры.
6. Зафиксировать дату проверки и перечень использованных источников.

Не создавай пустые разделы «на будущее». Новый документ или каталог добавляется только при наличии подтверждённого содержания либо явно утверждённого TO-BE решения.
