# Закрепление заголовков таблиц реестров

Общий вариант композиции «реестр» для **Бэклога, Метрик, Проектов и Рабочих
задач**. Имя файла сохранено для совместимости ссылок; прежняя отдельная
реализация закрепления бэклога заменена общим контроллером UI Kit.

Последняя [проверка всех четырёх шапок, 09.11.2026](../../docs/dev-testing/REGISTRY_HEADER_AUDIT_2026-11-09.md)
добавляет проверку границ текста и колонок при сужении. Исправлены переносы
в закреплённых Метриках и выход длинного заголовка Проектов в соседнюю ячейку.
Результаты ниже сохраняют историю предыдущих этапов; актуальная матрица — в отчёте.

## Поведение и внешний вид

- В начале страницы показан обычный заголовок внутри таблицы.
- При прокрутке страницы заголовок закрепляется под верхней навигацией.
  Между навигацией и шапкой остаётся **16 px непрозрачного пространства**:
  `--ui-table-sticky-gap: var(--space-4)`. Фон совпадает с `--bg-primary`;
  прокручиваемые строки не просвечивают через зазор.
  Подложка перекрывает также внешний бордюр реестра по 1 px с обеих сторон,
  включая область за скруглёнными углами шапки; геометрия колонок не меняется.
- Поиск, фильтры и заголовок страницы уходят вверх вместе с содержимым.
  В бэклоге для этого используется именованный вариант
  `.sticky-toolbar[data-ui-toolbar="flow"]`.
- Активная панель быстрого редактирования бэклога остаётся сверху. Шапка
  учитывает её фактическую нижнюю границу и сохраняет тот же зазор 16 px.
- Сохраняются фон, типографика, отступы и высота исходной шапки UI Kit.
  Вычисленные `white-space`, `overflow-wrap`, `word-break` также копируются:
  сужение не должно менять переносы при переходе в закреплённое состояние.
  Верхние углы используют `--radius-lg`, снизу — обычную границу таблицы.
  Нет размытия, полупрозрачности или дополнительной тяжёлой тени.
- Ширины колонок, горизонтальная прокрутка и закреплённые слева колонки
  синхронизированы с исходной таблицей. Боковое меню может менять ширину.
- При возврате к началу, выходе за нижнюю границу таблицы или смене страницы
  закреплённый заголовок удаляется. Пустое состояние и загрузка его не создают.
- В мобильном карточном представлении закрепления нет. Таблицы, сохраняющие
  горизонтальную прокрутку (например годовые метрики), сохраняют закрепление.

## Подключение

Контроллер: [stickyTableHeader.js](../frontend/js/ui/stickyTableHeader.js).
Стили: [registry-tables.css](../frontend/css/ui/registry-tables.css).
Приложение устанавливает контроллер один раз в `app.js`.

Для компонента UI Kit:

```js
dataTable({ stickyHeader: true, variant: 'registry', label, rows, columns });
```

Для существующей семантической таблицы:

```html
<table data-ui-sticky-header="page">…</table>
```

`stickyHeader` по умолчанию выключен. В каталоге UI Kit включён на примере
таблицы показателей. `initStickyTableHeader(tableId)` из `filterToolbar.js`
сохранён как совместимый экспорт общего модуля для бэклога.

| Потребитель | Где включено |
|---|---|
| Бэклог | Табличное представление единого рабочего места |
| Метрики | Квартальный и годовой реестры |
| Проекты | Каталог в табличном виде, план, отклонения и таблицы результатов |
| Рабочие задачи | Основная очередь и таблицы контекста проекта |

## Геометрия, события и жизненный цикл

Контроллер создаёт фиксированную проекцию `thead` вне прокручиваемого
контейнера. Это позволяет одновременно прокручивать страницу вертикально,
а широкую таблицу — горизонтально. Единственный исходный `tbody` остаётся
в таблице; дополнительного набора строк или повторного запроса данных нет.

Видимая проекция не дублирует DOM ID. Исходный `thead` на время закрепления
получает `visibility:hidden`, сохраняя размеры; после снятия возвращается
исходное значение. Сортировка и изменение ширин бэклога используют прежнюю
делегацию через `data-source-table`; checkbox передаёт изменение оригиналу.
Клавиатурный фокус переносится между исходным заголовком и проекцией и
сохраняется при перестроении шапки.

Прокрутка, изменение размеров и перерисовка SPA объединяются через
`requestAnimationFrame`. `ResizeObserver` отслеживает таблицу, контейнер,
контент и навигацию. `MutationObserver` отслеживает новые/удалённые таблицы
и изменения заголовков. Наблюдение не реагирует на собственную проекцию.
При удалении таблицы контроллер снимает наблюдатели и удаляет проекцию.

Контракт рассчитан на используемые реестрами одноуровневые заголовки без
`colspan`/`rowspan`; многоуровневые шапки требуют отдельного расширения.

## Проверка 09.11.2026

### Разделение подписи и значка сортировки

Убран локальный стиль бэклога, разрешавший тексту выходить за выделенную
область. Общий вариант `.table-sort-button` в `tables.css` теперь отделяет
несжимаемый значок зазором 8 px, а подпись ограничивает двумя строками
с многоточием. `headerCellHtml` сохраняет полное название в `title` кнопки
и её доступном имени. Исправление одинаково работает в исходной шапке
и проекции; изменение ширин и сортировка остаются прежними.

Проверка дополнена двумя сценариями (светлая/тёмная тема): длинные русские
названия, сужение колонок штатным клавиатурным управлением до 90 px,
измерение границ реально отрисованного текста относительно стрелки,
ограничение высоты подписи и сортировка через Enter после прокрутки.
Полные fixture-снимки: `dmb-backlog/artifacts/table-sort-spacing-final/`.
Живой экран до: [исходная шапка](../../artifacts/table-sort-spacing-2026-11-09/live-before-top.png).
Живой экран после: [закреплённая шапка](../../artifacts/table-sort-spacing-2026-11-09/live-after-sticky.png).
Функциональность: 17 сценариев пройдены; после ограничения двух строк повторно
пройдены все 5 затронутых сценариев бэклога. Полные экраны светлой и тёмной тем
осмотрены: стрелки отделены от текста, сужение колонок не увеличивает подпись
выше двух строк. На живом экране проверены исходная и закреплённая шапки,
отсутствие текстового переполнения и доступность полного названия в подсказке.
UI Kit: общий вариант и прежние токены; локальный override удалён.
Дизайн-пилот — 6 PASS / 5 FAIL, все пять diff побайтно совпали с прежними
расхождениями текста бокового меню; эталоны не менялись.

### Исправление полосы у левого края

После первой проверки пользователь указал на вертикальную линию над левым
углом шапки. Предыдущий визуальный осмотр пропустил этот дефект: проверка
непрозрачного фона внутри шапки не покрывала внешний бордюр контейнера.

Причина: область закреплённого заголовка начинается внутри 1 px рамки таблицы,
поэтому рамка продолжалась вверх в свободном зазоре. Общая подложка теперь
перекрывает эту рамку слева и справа через псевдоэлемент; ширины, координаты
колонок и интерактивные элементы не изменены. Используется прежний токен фона
UI Kit, без новых теней или локальных переопределений страницы.

Восемь существующих сценариев четырёх реестров в двух темах дополнены проверкой
пикселей всей полосы зазора, включая оба внешних края. Живой Бэклог повторно
осмотрен целиком со свёрнутым меню: линия исчезла, отступ и скругление сохранены.

Артефакты повторных сценариев: `dmb-backlog/artifacts/sticky-registry-edge-fix/`;

Повторный результат: **15 PASS**; дизайн-пилот — **6 PASS / 5 FAIL**.

новых расхождений нет, эталоны не изменялись. Impeccable по изменённому CSS —
без замечаний. Функциональность, вид исправленного края и применение общего
