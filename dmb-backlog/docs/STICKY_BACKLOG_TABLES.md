# Закрепление панелей и заголовков таблиц бэклога

Этот документ описывает рабочую реализацию прокрутки на страницах **«Бэклог DMB»** и **«Бэклог команды»**. Он нужен как обязательная памятка перед изменениями тулбара, быстрого редактирования, таблицы, отступов `.main-content` и responsive-стилей.

## Что должно работать

В табличном режиме одновременно участвуют четыре слоя:

1. `.navbar` — верхняя навигация.
2. `.sticky-toolbar` — панель страницы с фильтрами и действиями.
3. `.qe-toolbar` — панель быстрого редактирования, видимая только в соответствующем режиме.
4. Заголовок таблицы — обычный `<thead>` в начале страницы и его fixed-клон после прокрутки.

Обязательные инварианты:

- при `scrollTop = 0` исходный `<thead>` виден;
- панель быстрого редактирования находится непосредственно над `<thead>` и не перекрывает его;
- начало прокрутки не вызывает вертикального рывка;
- при прокрутке fixed-клон заголовка располагается сразу под видимой `.qe-toolbar`, либо под `.sticky-toolbar`, если быстрый режим выключен;
- при возврате к `scrollTop = 0` клон удаляется, а исходному `<thead>` возвращается `visibility`;
- ширины всех столбцов клона совпадают с основной таблицей, включая колонку чекбокса;
- горизонтальная прокрутка одинаково смещает основную таблицу и fixed-клон;
- логика одинакова для `#tasks-table` и `#team-tasks-table`.

## Где находится реализация

- `frontend/js/components/filterToolbar.js`
  - `updateStickyOffsets()` — вычисляет вертикальные координаты и компенсационные отступы;
  - `initStickyTableHeader(tableId)` — управляет исходным `<thead>` и fixed-клоном.
- `frontend/js/components/quickEdit.js`
  - создаёт `.qe-toolbar` и вызывает перерасчёт при входе/выходе из режима.
- `frontend/js/components/taskTable.js` — таблица «Бэклог DMB».
- `frontend/js/components/teamBacklog.js` — таблица «Бэклог команды».
- `frontend/css/components.css` — стили `.sticky-toolbar`, `.qe-toolbar`, таблиц и navbar.
- `frontend/css/responsive.css` — переключение `.sticky-toolbar` с `fixed` на `sticky` на узких экранах.

## Почему нельзя заменить всё одним `position: sticky`

`.main-content` является отдельным вертикальным scroll-контейнером, а `.table-container` прокручивается горизонтально. Горизонтальный `overflow-x: auto` мешает нативному `sticky` у `<thead>` работать одинаково во всех браузерах и режимах. Поэтому заголовок таблицы после вертикальной прокрутки представлен отдельным fixed-клоном.

Клон создаётся только пока таблица пересекает sticky-зону. Исходный `<thead>` скрывается через `visibility: hidden`, чтобы сохранить геометрию строк и столбцов.

## Две системы координат

Главная причина прошлых поломок — смешивание координат viewport и scroll-контейнера.

### Fixed-элементы

`.sticky-toolbar` и клон заголовка позиционируются относительно viewport. Их положение измеряется через:

```js
element.getBoundingClientRect().bottom
```

### Sticky-панель быстрого редактирования

`.qe-toolbar` находится внутри `.main-content`. Её `top` отсчитывается от **padding box scroll-контейнера**, а не от верхней границы viewport.

Поэтому на desktop правильная формула:

```js
qeStickyTop = toolbarBottom - mainContentTop - mainPaddingTop;
```

Вычитать `mainPaddingTop` обязательно. При `padding-top: 32px` отсутствие этого вычитания давало измеренное перекрытие около 31,33 px.

Для responsive-режима, где `.sticky-toolbar` сама находится в потоке и имеет `position: sticky`, используется её фактическая высота.

## Порядок вычислений

`updateStickyOffsets()` выполняется в `requestAnimationFrame`, когда браузер может предоставить актуальную геометрию.

Порядок нельзя произвольно менять:

1. Найти видимую `.sticky-toolbar` и определить её реальный `bottom`.
2. Получить `top` и `padding-top` элемента `.main-content`.
3. Если видна `.qe-toolbar`, временно поставить ей `top: auto`, чтобы измерить естественное положение в потоке.
4. Вычислить `--qe-sticky-top` в системе координат `.main-content`.
5. Вычислить компенсационный `margin-top` для `#tasks-content` и `#team-backlog-content`.
6. При необходимости скорректировать margin по естественному положению `.qe-toolbar`.
7. Вернуть `.qe-toolbar` значение `top: var(--qe-sticky-top)`.
8. Вычислить `--sticky-thead-offset` по фактическому нижнему краю видимой панели.
9. Вызвать обновление fixed-клона заголовка.

Если измерять `.qe-toolbar`, не снимая sticky-позицию, браузер уже покажет скорректированную координату. На её основе невозможно обнаружить перекрытие в естественном потоке.

## Условия появления и удаления клона

Клон создаётся только при реальной вертикальной прокрутке и когда таблица проходит под sticky-зоной:

```js
verticalScrollTop > 0.5
tableRect.top < offsetTop - 0.5
tableRect.bottom > offsetTop + theadHeight
```

Допуск `0.5px` защищает от дробных координат и масштабирования браузера.

В ветке, где клон не нужен, исходный заголовок должен восстанавливаться **безусловно**:

```js
thead.style.visibility = '';
```

Нельзя восстанавливать видимость только при существующем wrapper: wrapper мог быть удалён наблюдателем, повторным рендером или сменой маршрута.

После первичной инициализации выполняется ещё один `requestAnimationFrame(update)`. Он нужен потому, что компенсационный margin фиксированного тулбара также применяется асинхронно.

## Синхронизация ширины столбцов

Основные таблицы используют `<colgroup>`. В режиме быстрого редактирования появляется дополнительная колонка чекбокса шириной 40 px.

Fixed-клон обязан копировать не только `<thead>`, но и `<colgroup>`:

```js
const sourceColgroup = table.querySelector('colgroup');
if (sourceColgroup) clonedTable.appendChild(sourceColgroup.cloneNode(true));
```

Для клонированной таблицы используется `table-layout: fixed`. После создания каждому клонированному `<col>` присваивается фактическая ширина соответствующего исходного `<th>`, полученная через `getBoundingClientRect().width`.

Позиция wrapper должна вычисляться по фактическому дробному положению таблицы с компенсацией горизонтальной прокрутки, а его видимая ширина — до внешней правой границы контейнера. Это сохраняет правую рамку заголовка: `clientWidth` отсчитывается от внутренней границы и при старте таблицы после левой рамки срезает справа один пиксель.

```js
const tableOriginLeft = tableRect.left + container.scrollLeft;
const visibleWidth = Math.max(0, containerRect.right - tableOriginLeft);
```

По вертикали fixed-клон перекрывает нижний слой на 1 px. Это закрывает субпиксельный зазор между независимо рассчитанными sticky/fixed-координатами, через который иначе видны прокручивающиеся строки.

Нельзя вычислять левую координату как `containerRect.left + container.clientLeft`: `clientLeft` целочисленный, а реальная граница таблицы может быть дробной из-за масштабирования и device pixel ratio. В реальном замере это давало одинаковый сдвиг всех колонок на `0.3333px`, особенно заметный на первой узкой колонке с чекбоксом.

Если копировать только `<thead>`, браузер самостоятельно перераспределит ширины. Это особенно заметно по колонке чекбокса: при появлении fixed-заголовка остальные столбцы слегка смещаются.

## Жизненный цикл и очистка

При повторной инициализации необходимо:

- вернуть видимость предыдущему `<thead>`;
- отключить старый `ResizeObserver`;
- снять обработчики `scroll` и `resize`;
- удалить старый `#sticky-header-wrapper`;
- сбросить ссылки на предыдущую таблицу.

После изменения размеров таблицы observer удаляет клон, восстанавливает исходный `<thead>` и строит клон заново с актуальными ширинами.

Обработчик `scroll` необходимо снимать со всех элементов, куда он был добавлен: `window`, старого `.table-container` и `.main-content`. Недостаточно вызвать только `window.removeEventListener()`. Иначе после каждого повторного рендера в `.main-content` остаются старые замыкания с предыдущими таблицами. При следующей прокрутке они могут создать устаревший sticky-заголовок — например, вернуть чекбокс из обычного режима поверх заголовка быстрого редактирования.

## Что обычно ломает закрепление

Перед изменением перечисленных мест нужно перечитать этот документ.

- Изменение `padding` у `.main-content` без учёта в `qeStickyTop`.
- Изменение высоты, padding или позиционирования `.sticky-toolbar`.
- Перенос `.qe-toolbar` в другой DOM-контейнер.
- Добавление `overflow` родителю `.qe-toolbar` или таблицы.
- Замена `margin-top` компенсации на константу.
- Удаление повторного расчёта через `requestAnimationFrame`.
- Скрытие `<thead>` без гарантированного восстановления.
- Клонирование только `<thead>` без `<colgroup>`.
- Установка ширины клона по конфигурации столбцов вместо фактического `getBoundingClientRect()`.
- Загрузка разных query-версий `filterToolbar.js` из `taskTable.js`, `teamBacklog.js` и `quickEdit.js`. Это создаёт несколько экземпляров ES-модуля с разным состоянием.
- Обновление вложенного модуля без повышения cache-buster по всей цепочке импортов до `index.html`.

## Обязательная проверка после изменений

Проверять обе страницы: «Бэклог DMB» и «Бэклог команды».

### Обычный режим

1. Открыть страницу при `scrollTop = 0` — исходный заголовок виден.
2. Начать прокрутку — заголовок закрепляется без скачка.
3. Прокрутить таблицу горизонтально — заголовок движется синхронно.
4. Вернуться наверх — клон исчезает, исходный заголовок виден.

### Быстрое редактирование

1. При `scrollTop = 0` включить режим.
2. Проверить, что нижний край `.qe-toolbar` совпадает с верхним краем `<thead>` с допуском не более 1 px.
3. Начать прокрутку — панель и заголовок не прыгают.
4. Проверить, что fixed-заголовок расположен сразу под `.qe-toolbar`.
5. Сравнить левую границу каждой колонки до и после закрепления, особенно чекбокс, ID и название задачи.
6. Вернуться наверх и выйти из режима — обычный заголовок восстановлен.

### Размеры экрана

Минимальный набор:

- desktop: 1440 × 900;
- граница responsive: около 1024 px;
- mobile: около 557 × 560 или стандартный мобильный viewport.

### Полезные измерения в DevTools

```js
const qe = document.querySelector('.qe-toolbar');
const thead = document.querySelector('#tasks-table thead');
const sticky = document.querySelector('#sticky-header-wrapper');

({
  scrollTop: document.querySelector('.main-content').scrollTop,
  qeBottom: qe?.getBoundingClientRect().bottom,
  naturalHeaderTop: thead?.getBoundingClientRect().top,
  stickyHeaderTop: sticky?.getBoundingClientRect().top,
  initialGap: qe && thead
    ? thead.getBoundingClientRect().top - qe.getBoundingClientRect().bottom
    : null,
  stickyGap: qe && sticky
    ? sticky.getBoundingClientRect().top - qe.getBoundingClientRect().bottom
    : null,
});
```

Нормальное значение gap — от `0` до `1px` с учётом округления.

Для проверки колонок нужно сравнить `left`, `right` и `width` всех исходных и клонированных `th`.

## Автоматические проверки

Контрактные проверки находятся в:

```text
frontend/tests/moduleContracts.test.mjs
```

Запуск:

```bash
node --test frontend/tests/moduleContracts.test.mjs
```

Тесты контролируют ключевые элементы реализации: повторный layout-pass, учёт padding scroll-контейнера, восстановление `<thead>`, стабильный sticky inset, копирование `colgroup` и фактических ширин.

Автотесты не заменяют визуальную проверку на desktop и mobile: часть ошибок возникает только из-за реальной геометрии браузера и дробных координат.
