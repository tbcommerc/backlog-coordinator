# Логика работы страниц DMB Backlog

**Версия:** 3.0  
**Дата:** 2026-06-29

---

## Навигация

### Sidebar (левая панель)

Пункты меню сгруппированы по разделам:

**Управление бэклогом:**
- Главная (`#/dashboard`)
- Бэклог DMB (`#/backlog`) — требуется `backlog_dmb != none`
- Бэклог команды (`#/team-backlog`) — требуется `backlog_team != none`
- Канбан-доска (`#/kanban`) — требуется `backlog_dmb != none`

**Аналитика:**
- Статусы для встреч (`#/reports`) — требуется `reports != none`
- Аналитика ЛТ (`#/analytics/tribe`) — требуется `analytics != none`
- Аналитика PO/PL (`#/analytics/po-pl`) — требуется `analytics != none`

**Бизнес-заказчику:**
- Мои задачи (`#/customer`) — требуется `customer != none`
- Создать задачу (`#/customer/create`) — требуется `customer != none`

**Настройки и администрирование:**
- Мои уведомления (`#/notifications`) — всегда доступно
- Настройки (`#/settings`) — требуется `settings != none`
- Администрирование (`#/admin`) — требуется `admin != none`

Пункты, на которые у пользователя нет прав (`none`), скрываются из меню.

### Breadcrumbs (хлебные крошки)
Автоматически формируются роутером на основе текущего пути. Формат: `Главная › Бэклог DMB › ...`

## 1. Dashboard (Главная) — `#/dashboard`

### Описание
Обзорная страница с ключевыми метриками портфеля. Доступна всем пользователям.

### Состояния
- **Загрузка**: скелетон-компоненты (placeholder с анимацией pulse) для каждого виджета. 4 KPI-карточки отображаются серыми прямоугольниками, график — пустым контейнером.
- **Данные загружены**: все виджеты заполнены данными. Квартальный прогресс-бар, KPI (4 числа), уведомления (до 3), риски (до 3), кольцевая диаграмма.
- **Ошибка**: виджет ошибки с сообщением «Не удалось загрузить данные» и кнопкой «Повторить».
- **Нет данных**: KPI-карточки показывают 0, график пустой, уведомления и риски — «Нет данных».

### Состояния загрузки виджетов
- **Квартальный прогресс-бар**: вычисляется на клиенте (не требует API), всегда доступен.
- **KPI-карточки**: при загрузке `GET /tasks/stats` — скелетон. Ошибка: красный тост «Ошибка загрузки статистики».
- **Уведомления и риски**: при загрузке `GET /notifications` — скелетон. Пусто: «Уведомлений нет» / «Рисков нет».
- **Трудозатраты по типам**: при загрузке — скелетон круговой диаграммы. Пусто: «Нет данных».

### Виджеты
1. **Квартальный прогресс-бар** — визуализация текущего квартала с метками «Начало экспресс-оценки» (за 40 дней) и «PIP» (за 7 дней)
2. **KPI-карточки** (4 шт): Всего задач, В работе, Под риском, Ключевые проекты
3. **Уведомления и риски** — два виджета рядом: последние уведомления (до 3) и топ рисков (до 3), с кнопкой «Ещё N»
4. **Быстрые действия** — ссылки: Все задачи, Добавить задачу, Канбан-доска, Аналитика
5. **Трудозатраты по типам** — кольцевая диаграмма (Chart.js doughnut), переключатели: Моя команда / Трайб, Квартал / С НГ

## 2. Бэклог DMB — `#/backlog`

### Описание
Полный список всех задач платформы с тулбаром фильтрации.

### Состояния
- **Загрузка**: скелетон таблицы (10 строк с серыми прямоугольниками) + тулбар в disabled-состоянии. Индикатор загрузки «Загрузка задач...».
- **Данные загружены**: таблица с данными, активный тулбар, фильтры, поиск, сортировка, пагинация.
- **Ошибка**: сообщение «Ошибка загрузки данных. Попробуйте обновить страницу» + кнопка «Повторить».
- **Нет данных**: сообщение «Задачи не найдены» с предложением изменить фильтры или кнопкой «Создать задачу».

### Элементы
- **Тулбар**: поиск (debounce 250ms), сортировка, фильтры (статус, приоритет, команда, проект, тип, владелец, канал, подразделение), настройка колонок, переключение таблица/карточки, экспорт Excel, кнопка «Добавить задачу»
- **Таблица**: sticky-заголовок, сортировка по клику на колонку, клик по строке → карточка задачи
- **Карточки**: альтернативный вид (grid), та же информация в компактном формате

### Доступ
- PO/PL/CL/Admin — полный (редактирование)
- Developer — read-only
- Бизнес-заказчик — read-only

## 3. Бэклог команды — `#/team-backlog`

### Описание
Задачи только своей команды. Автоматически фильтруется по `user.team_id`.

### Состояния
- **Загрузка**: скелетон таблицы + тулбар.
- **Данные загружены**: таблица с данными команды, активный тулбар, чекбоксы для bulk-операций.
- **Ошибка**: сообщение об ошибке с кнопкой «Повторить».
- **Нет данных**: сообщение «В вашей команде нет задач» + кнопка «Создать задачу».

### Элементы
- Тот же тулбар что в Бэклоге DMB
- **Bulk-операции**: чекбоксы → панель «Закрыть», «На холд», «Удалить»

### Доступ
- PO своей команды — полный + bulk-операции
- Developer — read-only

## 4. Канбан-доска — `#/kanban`

### Описание
Визуальное управление потоком задач. 13 колонок по статусам.

### Состояния
- **Загрузка**: 13 пустых колонок с индикаторами загрузки «Загрузка...».
- **Данные загружены**: 13 колонок с карточками задач, счётчиками в заголовках.
- **Ошибка**: сообщение «Не удалось загрузить канбан-доску» + кнопка «Повторить».
- **Нет данных**: пустые колонки с надписью «Нет задач» в каждой.

### Колонки
НОВАЯ ЗАДАЧА → НАЗНАЧЕНА КОМАНДА → СБОР ТРЕБОВАНИЙ → ПРОВЕРКА ТРЕБОВАНИЙ → УТОЧНЕНИЕ ТРЕБОВАНИЙ → ЭКСПРЕСС-ОЦЕНКА → ПРИНЯТИЕ РЕШЕНИЯ → ПРИНЯТА В РАБОТУ → ЭСКАЛАЦИЯ НА ЛТ → ХОЛД → ОТКЛОНЕНА → НЕ АКТУАЛЬНА → ВЫПОЛНЕНА

### Логика
- Drag-and-drop карточек между колонками → PUT `/tasks/{id}` с новым status_id
- Клик по карточке → модальное окно задачи
- Счётчик задач в заголовке каждой колонки

## 5. Карточка задачи (Modal)

### Состояния
- **Загрузка**: модальное окно с пустыми полями и индикатором загрузки в заголовке.
- **Данные загружены**: полная карточка задачи с заполненными полями.
- **Ошибка**: тост «Не удалось загрузить задачу», модальное окно закрывается.
- **404**: тост «Задача не найдена», модальное окно закрывается.

### Режим просмотра
- **Шапка** (sticky): ID, статус, приоритет, название, бейдж «Ключевой проект»
- **Статус и приоритет**: is_from_leadership, is_regular, rejection_reason
- **Основная информация**: команда, канал, подразделение, проект, тип, владелец, дедлайн, дедлайн PO, прогресс
- **Ответственные**: owner, responsible_po, business_analyst, it_product_lead
- **Сроки и оценки**: deadline, deadline_po, ICE Score, effort_days, effort_rub, financial_effect, C/V
- **Описание**: description, DoD, What-If, комментарий, status_comment
- **Ссылки**: link_mockups, link_jira

### Режим редактирования
- Все поля становятся редактируемыми (input/select/textarea/checkbox)
- Причина отклонения показывается только при статусе «ОТКЛОНЕНА»
- При сохранении: PUT `/tasks/{id}` → task_history → тост

## 6. Портал бизнес-заказчика

### Мои задачи — `#/customer`

#### Состояния
- **Загрузка**: скелетон таблицы + 4 KPI-карточки.
- **Данные загружены**: таблица задач заказчика, статистика.
- **Ошибка**: сообщение с кнопкой «Повторить».
- **Нет данных**: сообщение «У вас нет созданных задач» + кнопка «Создать задачу».

- Таблица задач, созданных заказчиком (read-only)
- Фильтр по статусам: Все / Активные / В риске / Выполненные
- Статистика: 4 карточки (аналогично dashboard)
- Кнопка «Создать задачу» → `#/customer/create`

### Создать задачу — `#/customer/create`

#### Состояния
- **Загрузка**: пустой чат-интерфейс с активным первым шагом.
- **Данные загружены**: последовательные шаги чата.
- **Ошибка сохранения**: тост «Не удалось создать задачу. Попробуйте снова».
- **Успех**: тост «Задача создана» + редирект на `#/customer`.

- Чат-интерфейс: последовательный ввод атрибутов задачи
- Кнопка «Назад к задачам» → `#/customer`

## 7. Статусы для встреч — `#/reports`

### Состояния
- **Загрузка**: 4 карточки-скелетона с градиентной анимацией.
- **Данные загружены**: 4 карточки отчётов с названиями и описаниями.
- **Ошибка при выполнении отчёта**: тост «Не удалось выполнить отчёт» + данные таблицы не меняются.

### Описание
4 стандартных отчёта в виде карточек с градиентами:
- Директорат (priority = ВЫСОКИЙ + риски)
- DID (did_status в работе/требует решения/блокировано)
- Проекты (key_project = true)
- Рег-директора (ключевые проекты)

Клик по карточке → выполнение отчёта → таблица с результатами + кнопка экспорта.

## 8. Аналитика

#### Состояния (для обеих аналитик)
- **Загрузка**: скелетоны графиков (прямоугольники и круги с анимацией pulse).
- **Данные загружены**: графики Chart.js, таблицы с данными.

- Топ задач по C/V (bar chart)
- Задачи с низким C/V (C/V < 1.0)
- Риски по командам
- Здоровье портфеля (pie chart статусов)
- Топ команд по фин. эффекту (таблица)

### Аналитика PO/PL — `#/analytics/po-pl`
- Загрузка команд (workload)
- Соблюдение сроков (deadline compliance)
- Прогресс ключевых проектов
- Дефицит атрибутов (missing attributes)

- **Данные загружены**: список уведомлений с разбивкой по вкладкам.
- **Ошибка**: тост «Не удалось загрузить уведомления».

- 5 вкладок: Все, Просрочено, Без оценки, Обновления, Атрибуты

- Кнопка «Открыть» для уведомлений с taskId
- Кнопка «Отметить прочитанным» / «Вернуть в непрочитанные»
- KPI-карточки на dashboard кликабельны — открывают соответствующий таб

## 10. Настройки — `#/settings`

### Состояния
- **Загрузка**: страница отображается сразу (настройки из localStorage). Данные пользователя загружаются через `GET /auth/me`.
- **Данные загружены**: все секции настроек активны.
- **Ошибка загрузки профиля**: тост «Не удалось загрузить профиль», настройки темы и внешнего вида доступны из кеша.

- **Внешний вид**: тёмная/светлая тема (авто по системе), 10 акцентных цветов, компактный режим
- **Профиль**: ФИО, email, роль, команда
- Настройки сохраняются в localStorage, тема — в `data-theme` на `<html>`

## 11. Администрирование — `#/admin`

### Состояния
- **Загрузка**: скелетон вкладок и содержимого.
- **Данные загружены**: активная вкладка с CRUD-интерфейсом.
- **Ошибка**: тост «Не удалось загрузить данные» + пустое состояние вкладки.
- **Нет данных**: сообщение «Нет записей» + кнопка «Добавить».

### Вкладки

**Команды:**
- Карточки команд в grid (320px min)
- Аватар с аббревиатурой, название, руководители (PL/PO/CL/IT PL), описание
- Кнопки: редактировать, удалить
- Модалка редактирования: название, тип команды, цвет, PL, PO, CL, IT PL, описание, домен
- При удалении — проверка: нет пользователей и задач в команде

**Пользователи:**
- Таблица: ФИО (с аватаром), роль, команда, email, статус
- Сортировка по всем столбцам
- Поиск по ФИО (debounce 300ms) с кнопкой очистки
- Модалка: ФИО, email, роль, команда, статус

**Роли:**
- Таблица: название, права по 7 разделам, статус
- Модалка: название, описание, 7 уровней доступа
- Защита: нельзя лишить себя админского доступа

**Справочники (9 типов):**
- Карточки: приоритеты, статусы, типы задач, бизнес-заказчики, каналы, сроки, подразделения, типы команд, статусы проектов
- Модалка: список значений с цветом, кодом, кнопками добавления/удаления

**Уведомления (шаблоны):**
- Таблица: название, текст, адресаты, срок, регулярность, статус
- Модалка: все поля шаблона

**Отчёты:**
- Карточки стандартных отчётов (read-only)

## 12. Ключевые пользовательские сценарии

### 12.1 Сценарий: Создание задачи бизнес-заказчиком

1. Пользователь (Бизнес-заказчик) открывает страницу `#/customer`
2. Нажимает кнопку «Создать задачу» → переход на `#/customer/create`
3. Чат-интерфейс последовательно запрашивает:
   - Название задачи
   - Описание
   - Бизнес-заказчик (автоматически)
   - Подразделение
   - Приоритет
   - Желаемый срок
4. После заполнения → нажимает «Отправить»
5. `POST /api/v1/tasks` → задача создаётся со статусом «НОВАЯ ЗАДАЧА»
6. Тост «Задача создана», редирект на `#/customer`
7. Задача отображается в таблице «Мои задачи»

### 12.2 Сценарий: Принятие решения по задаче (PO/PL)

1. PO открывает `#/backlog` и находит задачу в статусе «ЭКСПРЕСС-ОЦЕНКА»
2. Использует поиск или фильтр по статусу
3. Кликает по строке задачи → открывается `#/modal` карточки задачи
4. Просматривает оценку (effort_days, effort_rub), финансовый эффект, C/V, ICE Score
5. Принимает решение:
   - **Принять**: меняет статус на «ПРИНЯТА В РАБОТУ» через выпадающий список
   - **Отклонить**: меняет статус на «ОТКЛОНЕНА», заполняет `rejection_reason`
   - **Отправить на уточнение**: меняет статус на «УТОЧНЕНИЕ ТРЕБОВАНИЙ»
6. `PUT /api/v1/tasks/{id}` → система фиксирует изменения в `task_history`
7. Тост «Задача обновлена»

### 12.3 Сценарий: Формирование статус-отчёта для встречи

1. ЛТ открывает `#/reports`
2. Видит 4 карточки предустановленных отчётов
3. Кликает по карточке, например «Директорат»
4. Система выполняет `GET /api/v1/tasks/report/directorate`
5. Отображается таблица с группировкой по проектам:
   - Название проекта
   - Количество задач
   - Активные задачи
   - Выполненные
   - Финансовый эффект
6. ЛТ может нажать «Экспорт» → выгрузка в Excel
7. Скопировать данные для презентации

### 12.4 Сценарий: Dashboard и мониторинг портфеля

1. ЛТ открывает `#/dashboard`
2. Видит квартальный прогресс-бар с ключевыми датами
3. KPI-карточки: Всего задач, В работе, Под риском, Ключевые проекты
4. Просматривает топ рисков (виджет справа)
5. Анализирует трудозатраты по типам на кольцевой диаграмме
6. При клике на KPI «Под риском» → переход в `#/backlog` с фильтром по рискам

### 12.5 Сценарий: Bulk-операция закрытия задач (PO)

1. PO открывает `#/team-backlog`
2. Отмечает чекбоксами 3 выполненные задачи
3. Появляется панель bulk-операций
4. Нажимает «Закрыть»
5. `POST /api/v1/tasks/bulk` с `action: "close"` и `task_ids: [1,2,3]`
6. Все 3 задачи получают статус «ВЫПОЛНЕНА» и progress = 100
7. Тост «Action 'close' applied to 3 tasks»

### 12.6 Сценарий: Канбан — перемещение задачи

1. PL открывает `#/kanban`
2. Видит 13 колонок с карточками задач
3. Перетаскивает карточку из колонки «СБОР ТРЕБОВАНИЙ» в «ЭКСПРЕСС-ОЦЕНКА»
4. `PUT /api/v1/tasks/{id}` с новым `status_id`
5. Карточка перемещается в новую колонку, счётчик обновляется
6. Тост «Задача перемещена»

### 12.7 Сценарий: Управление пользователями (Администратор)

1. Администратор открывает `#/admin`, вкладка «Пользователи»
2. Видит таблицу всех пользователей с сортировкой по роли
3. Нажимает «Добавить пользователя»
4. Заполняет: email, ФИО, должность, команда, роль
5. `POST /api/v1/admin/users` → пользователь создан
6. Может отредактировать: клик по строке → модалка → сохранить
7. Может деактивировать (удалить): `DELETE /api/v1/admin/users/{id}` → `is_active = false`

## 13. Обработка ошибок на страницах

### 13.1 Dashboard (`#/dashboard`)
| Ошибка | Реакция системы |
|--------|----------------|
| `GET /tasks/stats` возвращает 401 | API-клиент пытается refresh, при неудаче — редирект на `/login` |
