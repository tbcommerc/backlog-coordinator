## Выбор компонента

### Центрирование состояний — проверено 30.10.2026

Сообщения об отсутствии данных/совпадений, загрузке, ошибке и недоступности
всегда располагаются по центру **видимой области своего поля** по горизонтали
и вертикали. Иконка, заголовок, пояснение и действия образуют единый блок;
текст также центрируется. Правило действует для страниц, таблиц, карточек,
панелей и `scope:partial`, на настольных и мобильных экранах.
Центр рассчитывается по доступной области содержимого после заголовка,
фильтров и панелей действий, а не по полной ширине прокручиваемой таблицы
или скрытой части контейнера. Состояние не должно требовать прокрутки для
прочтения. Потребители не переопределяют выравнивание влево; при собственной
прокрутке обязаны ограничить область состояния видимой шириной/высотой.
В `ViewState` удалено исключение выравнивания влево для `scope:partial`.

**Карточки сущностей, 29.10.2026:** значения без редактирования собираются
через ReadOnlyField/DescriptionList; секции с заголовком — через SectionCard.
Не использовать disabled input для обычного просмотра. Ноль не означает
отсутствие данных; ошибки и загрузка не маскируются прочерком. Произвольный
HTML допускается только в явно доверенных слотах, строки всегда экранируются.
DetailPanel разделяет оболочку и предметные правила: компонент управляет
режимом окна и единым запросом закрытия, потребитель — правами, сохранением,
черновиком и переходами. При миграции сохраняются делегированные обработчики
родителя. Перемещение окна не считается его закрытием и не возвращает фокус
на фон. Новые семейства включены в `family-contracts.mjs`; их изолированные
браузерные проверки не означают полной живой приёмки приложения.

**Кардинальность фильтров, 29.10.2026:** [решение по каждому фильтру](FILTER_CARDINALITY.md).
Категориальный отбор допускает несколько значений (ИЛИ внутри поля, И между
полями). Одиночный выбор требует предметного обоснования; прежний scalar API
или обычный HTML select таким обоснованием не являются. Исполняемый реестр —
`ui/filterPolicy.js`; `ui/filterValues.js` сохраняет наборы при перерисовке,
передаче через FormData и восстановлении адреса. Для каждого одиночного
контрола реестр содержит причину. Быстрые выборки метрик, рабочих задач,
ревью и уведомлений также сохраняют набор выбранных значений.

## Счётчик в FilterChip — проверено 29.10.2026

Во всех потребителях `filterChip` счётчик расположен у правого внутреннего края
кнопки с сохранением её padding. Иконка и подпись остаются слева; свободное
место между подписью и счётчиком занимает автоматический отступ счётчика.
Оболочка `.quick-filter-info` растягивается (`flex:1 1 auto`, `min-width:0`),
а `.quick-filter-count` не сжимается и имеет `margin-left:auto`.
При нехватке места подпись сокращается многоточием, число остаётся видимым.
Правило действует для обычного, выбранного и недоступного состояний, всех тонов,
настольной и мобильной раскладки; страницы не переопределяют позицию счётчика.
Фильтр без счётчика не резервирует для него место.

## Выпадающие фильтры — единый стандарт от 29.10.2026

Реализовано 29.10.2026: `ui/filterSelect.js` подключается один раз из `App.init`.
Он использует общий `createPopover` и сохраняет исходные select, их значения,
программное заполнение, form/name и обработчики `input`/`change`. Перехватывается
открытие фильтра мышью и клавиатурой, вместо системного меню показывается панель
UI Kit. Динамические фильтры подключаются автоматически. Перечень поверхностей
задан явно в `FILTER_SELECT_SELECTOR`: метрики, рабочие задачи, аналитика,
админка/аудит, отчёты, ревью и клиентские списки. Новый нестандартный потребитель
помечает select атрибутом `data-ui-filter-select`. Поля редактирования и пагинация
не входят в этот адаптер.

Общие стили — `ui/filter-select.css`: базовая ширина 240 px через
`--filter-control-width`, равные колонки панели метрик сохраняют свою сетку.
В бэклогах существующая панель множественного выбора использует то же семейство
стилей; «Очистить» меняет черновик. В отчётах и ДИД выбор также применяется
только кнопкой «Применить», закрытие без применения сохраняет прежние условия.

Проверка: браузерные сценарии `filterSelect.spec.mjs`, `metricsToolbar.spec.mjs`,
`uiKitBacklog.spec.mjs`, `workToolbar.spec.mjs`, `adminAuditFixes.spec.mjs`;
модульные проверки фильтрации и предметного порядка. Тесты используют фикстуры
и подменённый API, проверка каждой страницы на живой БД этим не заявляется.

- Все выпадающие фильтры системы используют общий компонент раскрывающейся
  панели: единые шрифт, высота строки, отступы, рамка, радиус, тень, состояния
  hover/focus/selected/disabled и стрелка в закрытом контроле. Смешение нативного
  системного меню `select` и оформленной панели внутри фильтров после миграции
  не допускается. Требование не распространяется автоматически на поля форм.
- В пределах одной панели закрытые фильтры имеют равную ширину по общей сетке;
  смена значения не меняет ширину. Поиск может занимать больше места. При
  нехватке места переносятся целые поля, на узком мобильном экране поле занимает
  полную ширину строки. Длинное выбранное значение сокращается многоточием,
  полное значение доступно при наведении и с клавиатуры.
- Раскрытая панель не уже своего контрола, может быть шире для читаемости
  значений, ограничена границами viewport. Длинный список прокручивается внутри
  панели; страница и соседние контролы не сдвигаются. Это единый popover-слой
  UI Kit с общей обработкой позиционирования и закрытия.
- Одиночный выбор: одна выбранная строка с отметкой; выбор сразу применяется
  и закрывает панель. Чекбоксы и кнопка «Применить» не показываются.
- Множественный выбор: чекбоксы, черновик выбора, действия «Очистить» и
  «Применить». «Очистить» очищает черновик, «Применить» применяет его и закрывает
  панель. Escape и клик вне панели закрывают её без применения черновика.
- Поиск значений включается для длинных списков и справочников; для коротких
  фиксированных наборов он необязателен. Поиск не сбрасывает выбор; предусмотрены
  состояния загрузки, ошибки с повтором и отсутствия совпадений.
- «Все» означает отсутствие ограничения. «Не заполнено» — отдельное условие,
  если оно поддержано данными. Порядок значений определяется предметными
  правилами; периоды следуют принятому хронологическому порядку.
- Компонент доступен с клавиатуры: открытие Enter/Space, перемещение по
  вариантам стрелками, выбор с клавиатуры, закрытие Escape с возвратом фокуса
  на контрол. Доступное имя содержит название фильтра и выбранное значение;
  раскрытость и выбранность отражаются соответствующими ARIA-атрибутами.

Приёмка миграции: сверять закрытые контролы и открытые панели на реальных
страницах, оба типа выбора, светлую/тёмную темы, мобильную ширину, длинные
подписи, клавиатуру, применение и отмену. Оформление одиночного и множественного
выбора едино, различия ограничены необходимым поведением выбора.

## Состояния и композиция

Статус проекта «Активен» использует Badge с тоном `success` (зелёные
семантические токены) в каталоге и паспорте проекта. Отсутствующий или
неизвестный статус — `neutral`. Правило уточнено 29.10.2026.

`hidden` исключает компонент из layout, фокуса и доступности. Исключение нативного `hidden=until-found` сохраняется. `disabled` блокирует действие и показывает единый визуальный сигнал; `aria-disabled` у ненативного действия требует блокировки обработчика. `readonly` оставляет чтение, выделение и копирование; select не поддерживает readonly. Busy блокирует повторное действие до завершения и сохраняет понятное имя.

Минимальная сенсорная цель — `--control-target-min`, в том числе на широком coarse pointer; компактная плотность не отменяет минимум. Это правило относится к интерактивной цели, а не размеру информационного чипса. Чипсы всегда однострочные (уточнено 27.10.2026): перенос текста внутри статуса, метки или фильтра запрещён. При ограниченной ширине подпись сокращается многоточием, полный текст сохраняется в DOM; счётчик не сжимается. Перенос допускается только между чипсами группы; родитель допускает min-width:0. Проверяются строки с пробелами и без, неизвестные и большие количества.

Кнопки используют безопасные пары `--action-*-bg/text`; выбранный счётчик использует ту же primary-пару. `--accent` сам по себе не разрешает белый мелкий текст. Проверяются все десять акцентов обеих тем. Статусы рабочих задач имеют общий словарь `WORK_STATUSES/WORK_STATUS_TONES`, включая ready=info. Иконки должны существовать в поставляемой Lucide; новые имена проходят через словарь совместимости `icon()` либо заранее нормализуются в шаблоне. Необработанная неизвестная иконка — ошибка проверки.

Field связывает label, hint и error с контролом. Переданный извне `aria-invalid` сохраняется. Один field имеет один слот ошибки: showFieldError заменяет сообщение в слоте Field, clearFieldError скрывает его и снимает принадлежащую ошибке invalid-семантику. Внешние описания не удаляются. Tooltip при destroy удаляет только свой ID. Для нескольких серверных ошибок `showFormErrors` создаёт summary со ссылками на поля и фокусирует первое поле один раз; `clearFormErrors` очищает цикл. FieldFrame требует, чтобы caller передал уже связанный controlMarkup: он не переписывает произвольную HTML-разметку.

Upload сохраняет нативный file input и ограничения предметной области. Состояния: idle, dragover, selected, uploading, cancelled, error, disabled. `setUploadState` владеет отображением и ARIA, транспортом и отменой владеет caller; наличие dragover-состояния не делает область автоматически принимающей drop. Ошибка остаётся рядом с полем; повторный выбор разрешён. Range сохраняет нативные min/max/step, клавиатуру и доступное имя; нельзя заменять его декоративной полосой Progress.

## Сообщения, загрузка и повтор

| Ситуация | Правило |
|---|---|
| Нет данных для всей поверхности | ViewState loading/empty/error/forbidden/unavailable |
| Не обновилась часть данных | ViewState `scope:partial`, `kind:stale` рядом с сохранёнными данными; не стирать исправный результат |
| Контекстное предупреждение или инструкция | Alert, по умолчанию без live; live только при новом результате действия |
| Ошибка ввода | Field/summary, не только Toast |
| Короткий результат выполненного действия | Toast. Action/persistent не исчезают по умолчанию; hover/focus приостанавливают таймер |
| Повтор загрузки | Сохранить фильтры/черновик/доступный результат; блокировать дубликат запроса; фокус не уводить самопроизвольно |

При смене фильтра пагинация сбрасывается на первую страницу. Во время запроса переходы заблокированы. После успешной перерисовки сохраняется логически тот же переход либо ближайший доступный. При load-more сохраняются список и позиция, а ошибка добавления не заменяет весь список. Бизнес-состояния не выводятся из цвета или одного наличия CSS-класса.

## Владение стилями

`core.css` транзитивно содержит всё для публичных примитивов при подключённых fonts/tokens. В нём нет селекторов страниц и ID диалогов. SPA `kit.css` дополнительно подключает adapters, registry и совместимые информационные чипсы. Страница владеет сеткой, шириной колонок и размещением; размер кнопок/полей, их дочерние иконки/подписи, радиус и семантические цвета принадлежат семейству. Новый вариант добавляется в UI Kit с отдельным именем и проверкой, а не дополнительной специфичностью страницы.

## Защита от пропусков

Дополнение по живой проверке 27.10.2026: основная область `main` принадлежит оболочке SPA; компоненты страниц не создают вложенный `main`. При повторном входе состояние отрисованного маршрута сбрасывается, обработчик переходов регистрируется один раз. Пункты фильтра должны сохранять различимые подписи даже для нового типа данных; пустое состояние предлагает только доступные действия. Отсутствующая команда объясняется как предпосылка работы, а не необработанная серверная ошибка.

Регрессии: `uiMainLandmark.test.mjs`, `taskOpenRouting.test.mjs`, `adminAuditLabels.test.mjs`, `expressNoTeam.test.mjs`. Эти проверки дополняют, но не заменяют живую ролевую матрицу.

- [family-contracts.mjs](../frontend/ui-catalog/family-contracts.mjs) классифицирует **каждый экспорт** публичного API: семейство, состояния, селекторы и браузерная проверка. Неучтённый экспорт ломает тест.
- [build-family-inventory.mjs](../frontend/ui-catalog/build-family-inventory.mjs) строит вторую ось «семейство → кандидаты-потребители → хеши исходников» и считает поверхности из JSON. Кандидат не объявляется автоматически проверенным.
- [uiDeepOwnership.test.mjs](../frontend/tests/uiDeepOwnership.test.mjs) проходит транзитивные CSS imports, все CSS/inline JS ссылки на токены и статические иконки, а также воспроизведённые ошибочные шаблоны.
- [uiKitDeepContracts.spec.mjs](../frontend/e2e/uiKitDeepContracts.spec.mjs) проверяет граничные состояния и композицию в браузере, отдельно core и SPA. Стенд согласованности получает список CSS прямо из index.html в реальном порядке.
- `npm run verify:ui-kit` выполняет набор unit/browser-проверок и выдаёт receipt только при PASS и неизменности исходников за время прогона. `npm run check:ui-evidence` отвергает receipt после изменения кода, контрактов или тестов. Старый `browser-verified` в матрице — историческая область проверки, а не действующий сертификат.

Новый компонент принимается вместе со всеми состояниями, aliases, потребителями, семантикой и граничными данными. Снимок каталога не заменяет проверку потребителя. ## Межэкранная пагинация — 27.10.2026

Обычные списки с известным количеством страниц используют pagination из ui/forms.js: Назад, ограниченное окно номеров с aria-current, текущая страница/общее число, Далее. ## Дополнение повторного аудита — 27.10.2026

Проверено по исполняемому коду и браузерным сценариям:

- **Форма и ошибки.** Ошибки API 422 показывают понятные сообщения и связываются с полями; доступное имя поля не включает текст ошибки. Общая сводка — заголовок и список ссылок. Ввод сохраняется после ошибки, фокус переводится к ошибке, соседние поля выровнены по верхнему краю. Связанные даты проверяются до отправки.
- **Изменение и busy.** Пока идёт запрос, действия и поля блокируются с сохранением прежнего disabled; Escape, фон и повторное подтверждение не обходят блокировку. После ошибки исходные значения и доступность восстанавливаются.
- **Черновик.** Escape, отмена и смена маршрута проходят одну защиту. Подтверждение использует «Не сохранять» и «Продолжить редактирование». Маршрутизатор проверяет защиту до отказа доступа и перенаправления старых адресов; отмена сохраняет URL и форму.
- **Поиск и append.** Ответ старого поиска, включая ошибку, не заменяет актуальный результат. Offset/cursor подтверждается только успешной догрузкой; ошибка сохраняет строки и выбор, повтор запрашивает ту же порцию. Клавиатурный фокус переходит в первую добавленную запись, черновики остаются.
- **Сортировка.** Доступна через нативную кнопку с именем; th содержит scope и aria-sort. Числа сравниваются как числа, фокус сохраняется после перерисовки; смена сортировки реестра сбрасывает страницу. Отчёт без поддержки сортировки не показывает ложное действие.
- **Пагинация.** При известных total и pageSize общий компонент сохраняет диапазон записей («21–23 из 23») вместе с номерами страниц. Начальная, последняя и пустая выборки не показывают нечисловые значения.
- **Чипсы.** Информационные и фильтрующие чипсы остаются однострочными, включая уведомления на 320 px. Контейнер управляет переносом самих чипсов, доступная подпись сохраняется полностью.
- **Страница.** Единственный main принадлежит оболочке, включая ленивые модули agent-v2. Мобильный заголовок не сжимается между действиями. Отказ доступа обновляет хлебные крошки и состояние маршрута; возврат повторно рисует исходную страницу.
- **Диалог.** Все способы завершения освобождают клавиатурные обработчики, возвращают фокус и завершают Promise. Замена подтверждения завершает предыдущее как отменённое.

Обязательный `verify:ui-kit` теперь обнаруживает все `uiKit*.spec.mjs` и `infoChips.spec.mjs`, а не вручную выбранное подмножество. Запуск ограничен двумя параллельными исполнителями изолированного стенда. Зелёный receipt подтверждает этот набор и текущие хеши, но не заменяет сценарные live-доказательства.

Редактор клиентов ДИД также соблюдает busy для всех действий, сохраняет ввод после ошибки, использует общие поля/подтверждение и стабильный заголовок диалога. Если запись выполнена, а обновление списка завершилось ошибкой, retry повторяет только чтение. Проверка мутаций защищённых справочников выполняется только в памяти изолированного стенда; живой тест ограничен открытием и отменой.

При смене режима требование снимается с неприменимых полей; доступное имя не содержит декоративную звёздочку. Контроль выполняется после каждого переключения режима, а не только на первом рендере.

### EntityPicker — проверено 29.10.2026

Для одиночной связи с сущностью через асинхронный поиск используйте
`entityPicker`/`bindEntityPicker`. Компонент отвечает за debounce, защиту от
устаревших ответов, отмену, status/retry, сохранение и очистку выбора. Экран
отвечает за API, разрешённую область, тип сущности, лимиты и сохранение связи.
При смене области обязателен `refresh({reset:true})`, при закрытии — destroy.
Не сортируйте/не фильтруйте защищённую серверную область только на клиенте.

Выбор хранится в native select с name и required. Enter в поиске не отправляет

новой поисковой выдаче, сохраняется с подписью; потеря доступа определяется
отдельно сервером. Родительская форма владеет busy и серверными ошибками, а

### Таблицы данных — проверено 29.10.2026

Для новых табличных реестров используйте `dataTable` и `tableCell` из публичного
UI API. Таблица требует непустую подпись и уникальные ключи колонок; отвечает за
caption, scope, состояния, скролл и мобильные подписи. TableCell возвращает
содержимое ячейки, без td. Пользовательские строки экранируются; `markup`,
`render`, `toolbar` и `footer` — только доверенная композиция компонентов.

Сортировка управляемая: `bindDataTable` передаёт `{key,direction}` в `onSort`,
но сам не сортирует данные и не объявляет новый порядок до ответа потребителя.
В серверном реестре экран обновляет запрос, страницу и URL; после перерисовки
восстанавливает фокус на кнопке. Для локальных данных сортировка выполняется
явно в потребителе. Повторный bind заменяет обработчик; dispose снимает его.
Асинхронные операции, busy, отмена устаревшего ответа и ошибки принадлежат экрану.

Режим `cards` переносит значения и сохраняет доступные заголовки на мобильном;
`scroll` сохраняет таблицу с горизонтальной прокруткой и фокусируемой областью.
Не делайте кликабельной всю строку: переходы и изменения — явные ссылки/кнопки.
При загрузке/ошибке/пустом результате устаревшие строки не выводятся. Состояния
используют ViewState; retry задаётся явным действием. Нет общего disabled у таблицы.
Выбор строк, массовые операции и пагинация пока остаются у потребителей.

## Вызов AI-агентов — проверено 30.10.2026

Кнопка запуска/вызова агента или входа в работу с ним использует Button
`variant: 'ai'`, главное AI-действие — `variant: 'ai-primary'`.
Иконка искр обязательна (в renderer добавляется по умолчанию). Стили и
семантическая палитра `--ai-action-*` принадлежат `css/ui/ai-actions.css`;
частные цвета AI-кнопок на страницах не допускаются. Палитра не зависит от
акцента приложения и поддерживает обе темы, disabled, hover, фокус и busy.
В busy сохраняется текст процесса, повторный запуск блокируется; reduced
motion отключает вращение. Обычное сохранение, применение предложения и
отправка на человеческое согласование не получают AI-вариант.
