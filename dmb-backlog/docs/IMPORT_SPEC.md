> Статус: проверено по `backend/import_service.py`,
> `backend/routers/tasks_router.py` и `frontend/js/components/modal.js` на 2026-11-04.

## Уточнение контракта от 17.10.2026

P1 IMP-01/02/03 проверены изолированными регрессиями. Backend и preview принимают UTF-8 с BOM/без BOM, Windows-1251 и UTF-16 LE/BE с BOM. UTF-16 без BOM и NUL отклоняются. Начальные пустые строки игнорируются; разделитель определяется по первой непустой строке заголовка вне кавычек. Пустые строки данных пропускаются, переносы внутри кавычек сохраняются. Ошибка структуры CSV возвращается как ошибка валидации (400).

После общего rollback: created=0, skipped=total, task_ids=[]; инвариант total=created+skipped сохраняется и при частичном успехе. Предупреждения для технических ключей и русских подписей проверены одинаковыми ошибочными значениями. Предпросмотр не подтверждает существование справочных записей и успешный commit.

Проверки: [серверные doubles](../backend/tests/p1_validation_contracts.py), [клиентские регрессии](../frontend/tests/p1Import.test.mjs), [браузер с подменённым API](../frontend/e2e/p1Validation.spec.mjs). Рабочая БД не использовалась. Остальные замечания импорта остаются в [реестре](../../docs/OPEN_TASKS.md).

## Контракт

- Endpoint: `POST /tasks/import`, multipart-поле `file`.
- Backend принимает только файл с расширением `.csv`; пустой файл отклоняется с `400`.
- Требуется аутентификация и право `backlog_team: write_own`.
- После валидации каждой строки и до persist проверяется объектное право изменения
  Task для ответственной команды. При запрете строка пропускается: `permission_denied`,
  `field=team_id`, `fatal=true`; остальные строки продолжают обрабатываться.
  Справочники, пользователи и команды не создаются и не изменяются.
- Поддерживаются UTF-8 с BOM/без BOM, Windows-1251 и UTF-16 с BOM; разделитель `,` или `;`
  определяется по первой непустой строке.
- Заголовки сопоставляются с ключами из белого списка `IMPORTABLE_FIELDS` через
  записи `field_labels`; также распознаются сами ключи без учёта регистра.
- Неизвестные заголовки игнорируются.

Frontend позволяет выбрать CSV, XLS или XLSX и преобразует Excel-файл в CSV перед
отправкой. Это клиентская возможность: прямой API-запрос с `.xls`/`.xlsx` backend
не принимает.

## Проверки значений — проверено 17.10.2026

Числа принимаются в конечной десятичной записи с точкой; NaN, Infinity и экспоненциальная запись отклоняются. Целые поля допускают только нулевую дробную часть. Диапазоны берутся из TaskBase: effort_days — 0–10000, progress — 0–100, финансовый эффект и ограниченные схемой оценки — неотрицательные. Для actual_effort_days, cv, metric_kr_plan/fact запрет отрицательных значений не добавлен.

Непустой did_demo принимает true/1/yes/да/y и false/0/no/нет/n без учёта регистра; прочие значения дают invalid_boolean. Числовой ID в involved_teams должен существовать, иначе team_not_found. Название длиннее 255 Unicode-символов даёт invalid_length с указанием строки и поля до построения задачи. Эти ошибки фатальны для строки.

Предпросмотр предупреждает о длине, числовом формате/диапазонах и boolean для технических и пользовательских заголовков. Предупреждения не блокируют отправку всего файла: сохраняется частичный импорт валидных строк. unknown_error содержит общее сообщение без текста исключений, SQL и внутренних параметров; ошибка общего commit означает откат всего импорта.

[Серверные регрессии](../backend/tests/import_validation_contracts.py) выполняются без рабочей БД.

## Валидация строки

Источником полного списка импортируемых полей служит
`backend/import_service.py:IMPORTABLE_FIELDS`.

- Обязательность берётся из `field_labels.is_required`; строка с незаполненным
  обязательным полем пропускается (`required_missing`).
- Команда, канал, подразделение, проект, тип, приоритет, срок и статус
  разрешаются по загруженным справочникам. Не найденное значение — фатальная
  ошибка соответствующего типа `*_not_found`.
- Не найденный исполнитель даёт нефатальную ошибку `owner_not_found`: задача
  сохраняется без исполнителя.
- Некорректные дата, число или прогресс дают соответственно `invalid_date`,
  `invalid_number`, `invalid_progress`.
- Неожиданная ошибка строки или сохранения обозначается `unknown_error`.

Поддерживаемые даты: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `DD.MM.YY`,
`DD/MM/YY`. Прогресс должен быть целым числом от 0 до 100.

## Сохранение и результат

Валидные строки создают обычные записи `tasks`. Ошибочные строки пропускаются,
не останавливая остальные. Для созданной задачи сервис также записывает ссылки
Jira в `task_jira_links`, отдельные поля истории в `task_history` и событие
`action=import` в `audit_log`.

Ответ содержит:

```json
{
  "total": 2,
  "created": 1,
  "skipped": 1,
  "errors": [],
  "task_ids": [123]
}
```

Каждая ошибка содержит `row`, `field`, `field_label`, `value`, `type`, `message`
и `fatal`. При ошибке общего `commit` транзакция откатывается, `created`
становится равным нулю, `skipped=total`, `task_ids=[]` и добавляется `unknown_error`.

## Важные границы

- В модели `Task` нет поля `external_id`; поиск дубликатов по внешнему ID не
  реализован.
- Импорт читает справочники и пользователей только для разрешения ссылок; он не
  должен изменять защищённые данные.
- Значение статуса по умолчанию в сервисе импорта — числовой ID `1`. Это
  фактическое поведение кода, а не гарантированный бизнес-инвариант справочника.
- Автотесты `backend/tests/test_import.py` создают тестовые справочники и
  пользователей. В рабочем окружении их нельзя запускать против штатной БД.

Связанные источники: [API](API_SPEC.md), [модель данных](DATA_MODEL.md),
[коды ошибок](error-codes.md), [изменения схемы](SCHEMA_CHANGES.md).

## Поля отчёта ДИД — проверено 04.09.2026

Импорт поддерживает `did_client_group_id` («Клиент ДИД» / «Группировка для клиентов ДИД») и существующий `business_customer_id` («Бизнес-заказчик»). Значения сопоставляются с активным справочником клиентов ДИД по названию/коду и существующим справочником «Бизнес-заказчики» по имени. Однофамильцы разрешаются по подразделению строки; неоднозначные и неизвестные значения дают нефатальное предупреждение, поле остаётся пустым. Новые записи справочников не создаются. См. [отчёт ДИД](DID_BACKLOG_REPORT.md).

## Предпросмотр и CSV-выгрузка — проверено 13.10.2026

Клиентский CSV-предпросмотр использует общий `frontend/js/taskCsv.js`:
поддерживает BOM, UTF-8/Windows-1251, кавычки, разделители внутри ячеек и
многострочные значения. Разделитель определяется по заголовку, а не по содержимому
описания. Незакрытые кавычки и отсутствие строк показывают постоянную ошибку.
Проверка строк понимает технические ключи и подписи полей, включая `progress`.
При выборе следующего файла предыдущий предпросмотр сбрасывается; повреждённый
или пустой файл не оставляет активной отправку предыдущих данных.

CSV-шаблон экранирует составные примеры команд и Jira, сохраняя число колонок.
Выгрузка обоих бэклогов содержит отфильтрованные строки и видимые колонки в
пользовательском порядке: полный публичный ID, названия ссылочных полей, списки
меток и команд. UTF-8 BOM и CRLF поддерживают открытие в Excel; кавычки,
разделители и переносы экранируются. Строковые значения, начинающиеся как
формула, получают префикс апострофа; числовые отрицательные значения остаются числами.
Временные Blob URL освобождаются после скачивания.

Проверки: `frontend/tests/taskCsv.test.mjs` и
`frontend/e2e/backlogAuditClosure.spec.mjs`. Проверены фактически скачанные файлы
в изолированном Chromium и предпросмотр XLSX, SpreadsheetML XLS, 10 000 строк,
Windows-1251, многострочного CSV и ошибок строк. Запросы API подменены; это
не утверждение о повторном импорте всех форматов в рабочую БД.

## IMP-10 / IMP-12 / UX-29 — проверено 17.10.2026

Неизвестный клиент ДИД или неизвестный/неоднозначный бизнес-заказчик оставляет поле пустым с нефатальным предупреждением. Если это поле обязательно по field_labels, required_missing делает строку фатальной. При нескольких одноимённых заказчиках выбирается единственный в подразделении строки; если такого нет, проверяется однозначность всего списка совпадений. Например: неизвестный необязательный заказчик → задача без заказчика с предупреждением; неизвестный обязательный → строка пропущена; два одноимённых заказчика в разных подразделениях и заданное подразделение → соответствующий заказчик. Справочники не изменяются. Разделитель определяется по первой непустой строке вне кавычек, а не по описанию задачи.

Предпросмотр показывает формат CSV/XLS/XLSX, фактически выбранную декодером кодировку (для Excel — преобразование в UTF-8 CSV), разделитель, имя первого листа Excel, число строк и предварительное сопоставление колонок. Неизвестные колонки отмечены как игнорируемые. Отображаются первые 5 строк; существование справочных записей и сохранение проверяет сервер.

После полученного ответа отправка исходного файла блокируется. Если число уникальных фатальных номеров строк точно соответствует skipped, все номера допустимы и total совпадает с preview, можно скачать CSV только пропущенных строк, исправить его и выбрать заново. Успешные строки с нефатальными предупреждениями исключаются. При общем сбое/неоднозначных номерах выгрузка не предлагается — нужно сверяться с отчётом. Заголовки и значения экранируются без изменения содержимого. Это не серверная дедупликация: повторный ручной выбор исходного файла по-прежнему может создать дубли.

Проверки: backend/tests/import_customer_contracts.py — 4 PASS; клиентские taskCsv/p1Import/importValidation/importMetadata — 10 PASS; браузерные importRetry/importGuards/importFeedback/importValidation/p1Validation — 17 PASS, exit 0. Рабочая БД не использовалась.

## Размер импорта (UX-43) — проверено 17.10.2026

UI принимает исходные CSV/XLS/XLSX размером не более 10 МиБ (10 485 760 байт). Превышение выявляется до чтения файла. Для Excel также проверяется размер полученного UTF-8 CSV перед отправкой: компактный Excel может превысить лимит после преобразования. Серверный предел CSV остаётся 10 × 1024 × 1024 байт, превышение возвращает 413.

Ошибка остаётся рядом с выбором файла (role=alert), содержит точный предел и предложение уменьшить файл или разделить его на части. Превышение исходного размера сбрасывает прежний preview и блокирует отправку; превышение преобразованного CSV и серверный 413 также блокируют отправку. Выбор нового допустимого файла очищает ошибку. Равенство лимиту проходит проверку размера, но не отменяет остальные проверки содержимого.

Проверки: frontend/e2e/importSize.spec.mjs — 6 новых сценариев, вместе с importRetry/importGuards/importFeedback — 19 PASS, exit 0; клиентские taskCsv/p1Import/importValidation/importMetadata — 10 PASS. Границы до чтения проверены с подменённым FileReader; расширение Excel — с подменённым декодером, 413 — с подменённым API. Рабочая БД не использовалась.
