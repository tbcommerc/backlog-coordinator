# Режим выбора каждого фильтра

Дополнение 29.10.2026: реестр запросов фильтрует команды, бизнес-заказчиков и
ответственных за сопровождение множественными наборами. Поиск, режим, стадия,
сортировка и счётчики применяются на сервере по всему доступному набору перед
пагинацией. Контракт: [REQUESTS.md](REQUESTS.md).

Проверено по коду и целевым тестам 29.10.2026. Источники: `frontend/js/ui/filterPolicy.js`,
`filterValues.js`, `filterSelect.js`, компоненты страниц, backend-роутеры и
`services/filter_values.py`. Документ охватывает фильтры основного приложения
Backlog coordinator; поля создания/редактирования сущностей не являются фильтрами.

## Квартальные метрики v2 — 03.11.2026

Команда, владелец, проект, состояние метрики и периода — множественные категории.
Скаляр сохраняет совместимость, несколько значений передаются JSON-массивом
в URL-параметре. Внутри категории ИЛИ, между категориями И. Год, квартал,
представление, сортировка и область «Все/Мои» — одиночные контексты.
Быстрые выборки missing_fact/awaiting_close/not_achieved/overdue объединяются ИЛИ;
счётчики учитывают основные фильтры, но не выбранные быстрые выборки.
Годовые условия состояния и внимания должны совпадать на одном квартале.
Данные реестра и счётчики ограничиваются общей policy чтения метрик.

## Общее решение

Для отбора категорий — **множественный выбор по умолчанию**. Значения одного поля
объединяются через **ИЛИ**, разные поля — через **И**. «Все»/«Любая стадия» означает
отсутствие ограничения и не выбирается одновременно с конкретными значениями.
Пустой набор при применении также снимает ограничение. Список изменяется в
черновике: «Применить» сохраняет, Escape/клик снаружи отменяет.

Одиночный выбор допустим только для одного контекста, режима расчёта или порядка;
причина для каждого такого контрола указана ниже и в исполняемой политике.
Ограничение текущего API или прежний HTML `select` не являются обоснованием.
Новый фильтр должен быть добавлен в политику с режимом и предметной причиной.

## Метрики

| Фильтр/контрол | Выбор | Решение |
|---|---|---|
| Команда (`team_id`) | Несколько | Метрики любой из выбранных команд |
| Владелец (`owner_id`) | Несколько | Метрики любого из выбранных владельцев |
| Проект (`project_id`) | Несколько | Метрики любого из выбранных проектов |
| Состояние (`state`) | Несколько | Объединение состояний периодов |
| Активные / Цель достигнута / Просрочен замер / Без измерений | Несколько | Быстрые выборки объединяются через ИЛИ, счётчики не суммируются с повторами |
| Период реестра (`period`) | Один | Одна строка метрики содержит факт, цель и прогресс одного периода. Для нескольких периодов одной метрики потребовались бы отдельные строки и другая модель сравнения |
| Период карточки (`period_id`) | Один | Замеры, цель, история и действия относятся к одному выбранному периоду |
| Сортировка | Один | Определяет единую схему порядка строк |
| Все метрики / Мои метрики | Один | Вложенные области: «Все» уже включает «Мои»; их объединение равно «Все» |
| Архив | Да/нет | Два раздела жизненного цикла; параметр задаёт контекст архивного или действующего реестра, не категорию объекта |

## Рабочие задачи: список, доска, сводка

| Фильтр/контрол | Выбор | Решение |
|---|---|---|

| Приоритет (`work-priority`) | Несколько | Любой выбранный приоритет |
| Направление (`work-direction`) | Несколько | Продуктовые и организационные задачи можно смотреть вместе |
| Команда (`work-team`) | Несколько | Любая выбранная команда, с сохранением ACL |
| Исполнитель (`work-assignee`) | Несколько | Любой выбранный исполнитель |
| Проект (`work-filter-project`) | Несколько | Прямые задачи и задачи обязательств любого выбранного проекта |
| Сегодня / Просрочены / С препятствием (`work-focus`) | Несколько | Объединение быстрых выборок через ИЛИ |

| Подборка: мне выполнить / мне принять / я поручил / команда / все | Одна | Рабочий контекст очереди, включая отдельные правила приёмки и доступных состояний. «Все» даёт объединённый доступный список, остальные фильтры сужают его |
| Список / доска / сводка | Один | Способ представления одних и тех же результатов, не условие отбора |
| Порядок (`work-sort`) | Один | Единая схема сортировки и курсоров канбана |
| Период завершённых (`work-done-period`) | Один | Вложенные окна «7 дней», «30 дней», «всё время»: объединение равно самому широкому окну |
| Завершённые (`work-completed`) | Один | Компактный переключатель того же временного окна и включения завершённых; не дополнительный категориальный фильтр |
| Родительская задача / контекст проекта в адресе | Один | Контекст вложенного списка и создания новой задачи под конкретным родителем/проектом. Для отбора нескольких проектов служит `work-filter-project` |
| Колонка доски на мобильном | Одна | Выбор видимой колонки, остальные колонки существуют независимо |

## Общая панель бэклогов и запросов

Все столбцы `type:select` — множественные: статус, приоритет, проект, тип задачи,
команда, исполнитель, автор, бизнес-заказчик, клиент ДИД, подразделение,
вовлечённые команды, канал, срок и теги. Булевый фильтр «Демо для ДИД» также
допускает набор значений. Независимые быстрые признаки бэклога сохраняют AND.

Текстовые ID/название/описание, тексты отчётных статусов, ссылки, причина
отклонения и комментарий — одна поисковая строка, не список значений справочника.
Дата получения/создания/изменения/обновления отчётного статуса — один интервал.
Прогресс, оценка/факт трудозатрат, финансовый эффект, C/V и план/факт KR —
один числовой интервал. «Не заполнено» — отдельное условие, не подмена «Все».

## Передача и проверка

Одиночное значение API сохранено для обратной совместимости. Набор передаётся
JSON-массивом в строковом query-параметре: `team_id=["1","2"]`. Это сохраняет
запятые внутри названий. `filterValues`/`setFilterValue` сохраняют выбор при
перерисовке и восстановлении URL; HTML select остаётся совместимым с FormData
и существующими обработчиками. Сервер проверяет типы, допустимые enum и максимум
100 значений. ACL применяются до/вместе с фильтром; расширение выбора их не меняет.

Проверки: `frontend/e2e/filterSelect.spec.mjs`, `metricsToolbar.spec.mjs`,
`workToolbar.spec.mjs`, `adminAuditFixes.spec.mjs`, модульные проверки компонентов
и `backend/filter_tests/test_filter_cardinality.py`. Последний набор не подключается
к БД и не создаёт пользователей, команды или справочники: проверяются парсер,
SQL-условия и сборка схемы API. Полный ручной прогон всех страниц на живой БД
этими тестами не подменяется.

## Единый бэклог — 04.11.2026

Текущая реализация, маршруты, права, настройки и команды проверки описаны в
[профиле единого бэклога](BACKLOG_WORKSPACE.md). Два прежних экрана заменены
общим controller/renderer с областями all/team; прежний team-маршрут — alias.

Область all/team — одиночный контекст данных; team фиксирует свою команду,
all допускает несколько team-значений. Восемь quick-флагов объединяются И,
счётчики относятся ко всей области до остальных фильтров. Сброс условий,
восстановление pinned-панели и сброс колонок имеют независимый охват.
