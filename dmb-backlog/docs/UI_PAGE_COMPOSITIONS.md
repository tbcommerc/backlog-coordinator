## Три исполняемых образца

Это реальные компоненты приложения, а не отдельные макеты, которые расходятся с кодом.

| Композиция | Реализация | Порядок и назначение |
|---|---|---|
| Реестр | `renderWorkTasks` / `mountWorkList` в [workTasks.js](../frontend/js/components/workTasks.js) | Заголовок и действия → подборка → поиск и статус → быстрые условия и сортировка → данные. Приоритет и остальные условия доступны через «Все фильтры». Активные условия отображаются отдельно |
| Карточка | `openWork` в [workTaskDrawer.js](../frontend/js/components/workTaskDrawer.js) | Идентификатор, статус, название и контекст → исполнитель/срок/принимающий → результат и описание → чек-лист и дополнительные сведения. Действия в нижней панели. При редактировании основные поля стоят перед описанием |
| Реестр с инспектором | тот же `mountWorkList` + [bindSplitPane](../frontend/js/ui/splitPane.js) | Список сохраняет контекст выбора; карточка справа при достаточной ширине. На узком экране — диалог. Использовать существующее управление фокусом, шириной и закрытием |

Полные экраны воспроизводит [workDesignPilot.spec.mjs](../frontend/e2e/workDesignPilot.spec.mjs),
загружая SPA через `/#/work-tasks`. Набор данных и API-перехват —
[workDesignPilot.mjs](../frontend/e2e/helpers/workDesignPilot.mjs).
При переносе на другой экран переиспользовать структуру и компоненты,
но не бизнес-обработчики рабочих задач и фиксированные имена селекторов.

## Общие варианты UI Kit

В [page-compositions.css](../frontend/css/ui/page-compositions.css):

Изолированный визуальный образец вариантов — [каталог композиций](../frontend/ui-catalog/page-compositions.html).

- `filterChip({variant:'navigation'})` — подборки одного реестра, подпись и счётчик в строку. Сохраняет button и `aria-pressed`; это не ARIA tabs с панелями.
- `.ui-registry-toolbar` — поверхность панели; `.ui-registry-fields` — группа условий.
- `.ui-registry-header` — заголовок с контекстом и переносом по ширине; `.ui-registry-actions` — действия справа.
- `.ui-registry-secondary` — строка быстрых условий и сортировки; `.ui-registry-conditions` — переносимая группа применённых условий. Эти варианты задают композицию, а не размеры контролов.
- `.ui-field-inline` — компактный вариант стандартного поля: подпись рядом с контролом. При переносе в вертикальную панель класс снимается. Размер самого контрола остаётся в `sizing.css`.
- `sectionCard({variant:'plain'})` — встроенный раздел без дополнительной рамки. API состояний, заголовка, действий, collapse и footer сохраняется. Неизвестный вариант использует обычную карточку.
- `.ui-detail-summary` на `descriptionList` — основные атрибуты карточки, две колонки, переносы длинных значений.

Страница управляет сеткой и доступным пространством. Общий компонент управляет
внутренним видом, размерами и состояниями. Сначала удалить конфликтующее локальное
правило, затем использовать общий вариант; не добавлять ещё один слой `!important`.

Проверено 06.11.2026: `.ui-tabs` не сжимаются по главной оси flex-контейнера.
В реестре запросов заголовок и панели сохраняют естественную высоту, а список
получает оставшееся место через `flex:1 1 0; min-height:0`. Строки карточек
имеют высоту по содержимому, без выравнивания по самой высокой записи.

## Рабочий цикл

### Метрики: реестр и аналитическая карточка — 04.11.2026

`metricsQuarterly.js` использует композиции «реестр» и «карточка». Реестр:
заголовок/период/создание → поиск → активные условия → сравнение плана, факта
и результата. Карточка: название/основное действие → принадлежность и период →
вкладки → результат → динамика и замеры → дополнительные сведения.
Внутренние разделы используют `sectionCard({variant:'plain'})`.

Именованные варианты для этих и других ограниченных поверхностей:

- `badge({wrap:true})`: смысловой статус переносится целиком; обычные бейджи остаются однострочными.
- `detailPanel({size:'wide'})`: ширина до 65rem, границы в процентах, полный экран до 700px; поддерживает увеличение без выхода действий за экран.
- `tabs({variant:'fit'})`: три короткие вкладки распределяют ширину до 360px.
- `.ui-field-fluid`: FilterSelect заполняет выделенную колонку, без ограничения 240px.
- `.ui-field-label-hidden`: визуально скрытая подпись компактного поля; доступное имя сохраняется.
- `.ui-search-field`: поле с ведущей поисковой иконкой.
- `.ui-segmented-fill`: сегменты занимают выделенную ширину поровну.
- `.ui-btn-mobile-icon`: подписанная кнопка с иконкой становится иконкой до 700px, сохраняя подпись для скринридера. Только для узнаваемого вторичного действия; активные фильтры показываются отдельно.

Размеры года, квартала, сетки результата и графика остаются ответственностью
метрик; внутренние размеры и состояния контролов — UI Kit. Проверки:
`metricsQuarterly.spec.mjs`, включая 8 полных экранных сценариев в обеих темах.
Доказательства и ограничения: [ревью R6](../../docs/dev-testing/METRICS_IMPECCABLE_REVIEW_2026-11-04.md).

1. Определить основной сценарий, важность данных и действие. Выбрать один образец.
2. Осмотреть полный исходный экран на реалистичных данных. Для нового экрана выбрать
   существующий эталон. Не начинать со случайного набора карточек и KPI.
3. Impeccable использовать в режиме Operate с контекстом `PRODUCT.md` / `DESIGN.md`.
   Его рекомендации проверять против действующего UI Kit. Skill помогает находить
   проблемы, но не подтверждает качество автоматически.
4. Реализовать композицию; нужный новый вариант добавлять в UI Kit и каталог.
5. Проверить полный экран: обе темы, короткий ноутбук, мобильный экран, длинный текст,
   пустоту, ошибку, редактирование и клавиатуру в применимой области.
6. Исправить выявленное и повторно осмотреть весь экран, включая участки вне списка замечаний.
7. Запустить регрессию и отдельно записать функциональный, визуальный и UI Kit-вывод.
   Снимок после изменений не становится одобренным дизайном только потому, что сохранён в Git.

## Воспроизводимый визуальный контроль

Из `dmb-backlog` на Windows, после `npm ci` и установки Chromium Playwright:

```powershell
npm run test:design
# Только после ручного осмотра и объяснения изменения:
npm run test:design -- --update-snapshots
```

Конфигурация [playwright.design.config.mjs](../playwright.design.config.mjs) запрещает
неявное обновление эталонов. PNG включают ОС в имени: шрифты Windows и Linux нельзя
объявлять одинаковыми. Выделенная Windows CI-задача выполняет этот небольшой набор;
общий Linux E2E продолжает проверять поведение. CI не запускался из локального чата.
Если версия Chromium, ОС или шрифты изменились, сначала исследовать diff, затем
осознанно обновлять эталоны. Первое выполнение на CI требует проверки среды.

Для разового снимка `DESIGN_PILOT_CAPTURE=before` или `after` сохраняет материалы
в `test-results` через `testInfo.outputPath`. В документацию копируются только
отобранные и просмотренные материалы. Это режим сбора доказательств,
а не screenshot-регрессия; в обычной проверке переменная должна отсутствовать.

Пилот не доказывает преимущество инструмента в процентах: это последовательная
доработка одного интерфейса. Контролируемое сравнение «без skill / skill / skill +
композиции» потребует отдельных реализаций, одинаковых лимитов и независимой оценки.

## Панели проекта и запросов — 05.11.2026

- `ui-registry-search-row` + `ui-registry-search` размещают широкий поиск и действия.
- `ui-registry-filter-panel`/`ui-registry-filter-grid` — раскрываемые условия,
  три колонки на широком экране и одна до 700px. `hidden` обязателен для закрытия.
- `ui-registry-sort` ограничивает ширину вторичной сортировки.
- `ui-registry-collections-responsive` и `ui-registry-mobile-collection` показывают
  только один способ выбора подборки на текущей ширине. Обработчик потребителя
  синхронизирует значение, счётчики и URL; это не разные фильтры.
- `routeTabs({label,items,selected})` — навигационные ссылки внутренних маршрутов
  с `aria-current="page"`; без ложных `tablist`/`tabpanel`.
- `kpiCard({variant:'inline'})` в `ui-summary-strip` сохраняет button, реальное
  значение и доступное название; компактность не меняет поведение KPI.

Варианты представлены в каталоге композиций. Изменены только два его эталона
(light/dark): внизу добавлен раздел маршрутов и компактных показателей. Полные
снимки и diff просмотрены перед обновлением; существующие блоки не менялись.
Пилотные рабочие задачи проверяются по прежним эталонам.
