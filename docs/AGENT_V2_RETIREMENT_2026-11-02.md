# Удаление старого V2: сравнение и сохранённые решения

Проверка выполнена по исполняемому коду, моделям и тестам 02.11.2026. Сравнивались прежний самостоятельный `assistant-v2/` (после промежуточного переноса — `legacy/assistant-v2/`) и действующий `agent-v2/`. Существование полезных идей не означает необходимость сохранять второй неиспользуемый сервис.

## Что уже сохранено в актуальном V2

| Механизм прежнего прототипа | Текущая реализация и проверка |
|---|---|
| Источники, фрагменты и новые версии без перезаписи исходного текста | `agent-v2/agent_v2/v2/document_workspace.py`: `add_source`, адреса версий/разделов/строк; `test_sources_preserve_unmapped_original_versions_and_invalidate_review` |
| Отличие сообщения человека от гипотезы модели | `v2/models.py`: `ProvenanceRecord`; `dialogue/state.py`; проверки неподтверждённой генерации и доказательств в `test_document_workspace.py` и `test_v2_domain.py` |
| Неизменяемые редакции и отпечатки содержимого | `v2/fingerprint.py`, `v2/composer.py`, `session.py`, а также DMB `requirement_reviews`; тесты ручных редакций, перезапуска и следующей версии |
| Подтверждение перед выпуском и проверка пробелов/конфликтов | `v2/readiness.py`: `assignment_readiness`, `requirement_readiness`; тесты отсутствия подтверждения, критических пробелов и непроверяемых критериев |
| Правка только человеком или после явного принятия предложения | `v2/document_workspace.py`: выбор операций, валидация текущей редакции, отказ от отклонённого предложения; тесты частичного принятия и защиты ручных правок |
| Защита от устаревших источников, документа и связанного объекта | Отпечатки в предложениях, review и metadata; `test_stale_source_prevents_apply_and_finding_decision`, `test_stale_proposal_cannot_overwrite_manual_edit` |
| Защита от повторного выполнения и конфликта версий | `api/router.py`: ключи операций привязаны к payload и владельцу; `session.py`: optimistic version; тесты `test_document_api_idempotency_payload_binding_and_ownership` и повторов привязанного объекта |
| Ограничение доступа к пилоту и доверенный пользовательский контекст | DMB `services/agent_v2_gateway.py`, `routers/agent_v2_router.py`; существующие boundary-тесты и тесты владения сессией |
| Безопасные предложения изменения бэклога | `v2/patches.py`: allowlist, защищённые поля, базовая версия/отпечаток, явное решение человека; прямого клиента записи в DMB нет |
| Согласование конкретной редакции БТ | DMB `routers/requirement_reviews_router.py` и документный gateway; отдельные неизменяемые редакции вместо повторного создания задач |

Это соответствие механизмов, а не утверждение о побайтовом совпадении поведения или полной производственной приёмке.

## Полезные отличия, которые нельзя выдавать за уже реализованные

Следующие элементы сохранились как материал для развития. Перенос их старого кода в актуальный V2 автоматически не выполнялся: он зависит от иной схемы из 22 таблиц, иного протокола API и ручного процесса. Новые продуктовые функции этой очисткой не объявляются выбранными или внедрёнными.

1. **Разделение поручения на несколько связанных.** Старый `split_case` сохранял источник происхождения от родительского поручения и не копировал подтверждение фактов. Полного аналога в текущем V2 не найдено. Возможное требование: дочерние поручения сохраняют ссылки на исходные материалы, а подтверждения даются заново.
2. **Транзакционный аудит и очередь событий.** Старые `AuditEvent` и `OutboxEvent` записывались вместе с изменением. Текущая история редакций и журналирование не являются полным аналогом надёжной доставки событий. Возможное требование: события решений фиксируются атомарно и могут быть доставлены повторно без дублирования эффекта.
3. **Отдельные записи решений по пробелам и противоречиям.** В прежнем сервисе были собственные идентификаторы, версии и мотивировки `DecisionRecord`, включая эскалацию и владельца следующего шага. В текущем V2 есть пробелы/конфликты и решения по замечаниям ревью, но полного равенства этого процесса не подтверждено.
4. **Заполнение формы задачи принятыми изменениями.** Старый `apply-intent` переносил безопасные поля в форму без автоматического сохранения. Его UI давно не импортировался активным router. Текущий V2 показывает предложения и решения по ним; перенос в форму не объявляется сохранённой функцией. Если он понадобится, следует использовать актуальный контракт и существующие права задачи.
5. **Короткоживущий подписанный контекст и защита от повторного использования токена.** Это было частью удалённого протокола actor envelope. Актуальный V2 использует доверенный DMB gateway, отдельный секрет, проверку владельца и ключи операций. Повтор запроса с идемпотентным результатом и повтор использования токена — разные механизмы; при пересмотре межсервисной аутентификации это различие нужно учитывать.

Исходные решения доступны в [исторических документах](archive/assistant-v2/README.md). Полный старый код остаётся в истории Git: коммит `becac444`, путь `assistant-v2/`.

## Что удалено

- Старый сервис целиком: `app`, prompts, его Alembic-миграции, запуск и тесты. В корне и `legacy/` исполняемой версии больше нет.
- Старые DMB gateway/adapter, настройки `ASSISTANT_V2_*`, feature bootstrap и readiness-проверка старого сервиса.
- Флаг запуска `-IncludeAssistantV2`, установка зависимостей, настройка отдельной БД и запуск порта 9200; упоминание процесса в status/stop.
- Неиспользуемые frontend-модули, CSS и механизм предзаполнения формы старого прототипа. Исключения старой папки из UI-проверок убраны.

Для старых закладок сохранено только перенаправление `#/assistant-v2` на `#/agent-v2`. Оно не загружает удалённый код и не обращается к старому API.

Локальные секреты перенесены в игнорируемый каталог `.runtime/retired-assistant-v2/` без вывода значений. Рабочие БД, пользователи, роли, команды и справочники не изменялись. Существующая БД прежнего прототипа не удалялась. Локальное Python-окружение `.venv-assistant-v2/` не является исходным кодом, больше не используется скриптами и не удалялось.

## Проверка

- Актуальный V2: 89 тестов прошли (`test_v2_domain.py`, `test_document_workspace.py`, `test_document_generation.py`, `test_runtime_safety.py`). Использовались подменная модель и изолированные агентные хранилища; после ошибки доступа к общему временному каталогу Windows прогон выполнен в новом каталоге `.runtime/`.
- Изолированный документный gateway: 19 тестов прошли (`test_agent_v2_document_boundary.py`).
- Удаление старого API: три теста прошли (`test_legacy_v2_retirement.py`), включая случай старой переменной `ASSISTANT_V2_ENABLED=true`. Импорт приложения не запускает lifespan и не подключается к рабочей БД.
- Frontend до изменения: 461 тест, 458 прошли, три исходных сбоя. После удаления четырёх устаревших тестовых сценариев: 457 тестов, 454 прошли, те же три сбоя. Новых провалов нет. Сбои: `U28 core boundary follows every transitive CSS import`, `page CSS cannot set vertical dimensions on shared buttons and fields`, `active styles and templates cannot reintroduce tiny text or private weights`. Они относятся к CSS рабочего места и не исправлялись этой задачей.
- `npm run check:ui-review` прошёл после пересборки инвентаризации модулей и семейств UI. Подтверждение полной визуальной приёмки не обновлялось.
- Проверены 454 локальные Markdown-ссылки: битых нет. Синтаксис изменённых Python-файлов и трёх PowerShell-сценариев проверен; `git diff --check` прошёл.
- Удалённые модули не импортируются; `.runtime/assistant-v2.pid` отсутствует. Старые frontend-модули отсутствуют, redirect не подгружает их.

Полный запуск платформы с рабочей БД не выполнялся. Уже работающие процессы используют загруженный код до следующего штатного перезапуска. Коммит, staging и отправка на GitHub не выполнялись.
