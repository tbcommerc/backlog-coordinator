# Раздел «Метрики» и карточка метрического KR

Метрики становятся самостоятельной областью управления: у показателя один
паспорт, а цели, измерения и результаты сохраняются по периодам. Работы,
влияющие на показатель, связываются с ним без изменения их основного контекста.

**Согласовано пользователем 26.10.2026:** состав атрибутов, одна метрика с целями
по периодам, ручной ввод измерений в первой версии, необязательный проект,
обязательные команда и владелец, множественные связи с задачами.

**Реализовано 26.10.2026:** пользователь утвердил дизайн и поручил полностью
работающий раздел с верхней панелью из бэклога. [Текущее поведение, модель,
API и проверка](../dmb-backlog/docs/METRICS.md) описаны отдельно. Этот документ
сохраняет исходный проект; рабочие маршруты используют числовой ID и section,
карточка содержит семь тематических вкладок.

[Интерактивный прототип](../dmb-backlog/frontend/prototypes/metrics/index.html)
использует реальные токены, локальные шрифты, рендерер меню и UI-примитивы
приложения. Данные демонстрационные; действия меняют только состояние текущей
страницы. Перезагрузка восстанавливает примеры. Прототип не подключён к SPA-router
и не обращается к бизнес-API.

## 1. Навигация и основные сценарии

Пункт «Метрики» располагается в группе «Управление бэклогом» после «Рабочих задач».
Иконка — line-chart из комплектного Lucide. Реестр: будущий маршрут
«#/metrics». Карточка: «#/metrics/MET-001?period=2026-Q4».

Карточка открывается самостоятельной страницей. Это даёт достаточно места
графику, методике и истории. Название метрики и отдельная кнопка открытия строки
ведут на одну карточку; щелчок по числу не запускает скрытое редактирование.

Основные сценарии:

1. Найти метрику своей команды, проверить цель, факт и дату обновления.
2. Открыть карточку и добавить измерение с датой и источником.
3. Исправить измерение с обязательной причиной, сохранив предыдущую редакцию.
4. Переключить квартал и сравнить прежнюю цель с итогом.
5. Создать паспорт, настроить цель первого периода и активировать KR.
6. Связать работы, подготовить статус к встрече, оставить пояснение или файл.
7. Завершить период с итоговым комментарием и открыть следующий.

При возврате в реестр восстанавливаются его период, поиск, фильтры, сортировка,
страница и позиция прокрутки. Выбор исторического периода в карточке не меняет
выбор периода исходного реестра. В прототипе реализовано сохранение периода
и фильтров в памяти страницы; URL-состояние, пагинация и восстановление прокрутки
относятся к внедрению.

## 2. Страница «Метрики»

Порядок сверху вниз:

| Зона | Содержание и поведение |
|---|---|
| Заголовок | «Метрики», короткое пояснение, одна primary-кнопка «Создать метрику» |
| Сводка | Активные KR; цель достигнута; обновление просрочено; ожидают первого факта |
| Основные фильтры | Поиск по названию, ID и владельцу; период KR; команда; кнопка дополнительных фильтров |
| Дополнительные фильтры | Проект, владелец, состояние KR; при внедрении также направление и теги |
| Быстрые выборки | Все, мои, черновики; счётчики; число показанных записей и сброс |
| Реестр | Одна строка на метрику в выбранном периоде |
| Нижняя строка | Период, число результатов; при внедрении пагинация по 25 строк |

Квартал по умолчанию — текущий в часовом поясе приложения. В прототипе контрольная
дата зафиксирована 26.10.2026. Для года и произвольного периода применяются те же
элементы; в прототипе показаны кварталы.

Клик по сводке включает соответствующий фильтр; повторный клик выключает его.
Сводка считается после основных фильтров и до быстрой выборки/фильтра сводки.
Это позволяет видеть доступное множество и не терять соседние категории.
Сводки могут пересекаться: достигнутая цель может иметь просроченные данные.

«Цель достигнута» учитывает цели роста и снижения. Удержание в диапазоне
проверяется отдельно и не считается навсегда достигнутой целью по одному факту.
Среднее выполнение по разнородным метрикам и сумма значений разных единиц
не показываются.

### Строка реестра

| Колонка | Отображение |
|---|---|
| Метрика | Название-ссылка; ниже ID и состояние KR |
| Команда / владелец | Команда и имя владельца |
| Цель | ≥ 80%, ≤ 15 мин или диапазон 99,9–100% |
| Факт | Последнее значение и дата измерения; «— / Нет измерений» при отсутствии |
| Результат | Процент улучшения от базы или текст «В границах / Вне границ» |
| Данные | Актуально, обновить сегодня, просрочено на N дней, нет данных |
| Открытие | Иконка со смысловым доступным названием |

Ноль отображается как 0. Процент выше 100% и отрицательный процент сохраняются
в тексте, а полоса ограничена 0–100%. Семантика результата и свежести данных
раздельна: зелёный факт достижения не скрывает предупреждение об обновлении.

Внедрение предусматривает серверную сортировку по названию, команде, ближайшему
обновлению, результату и дате последнего факта. Начальная сортировка — название;
быстрый фильтр просрочки сортирует по наиболее раннему сроку обновления.
Числовая сортировка результата не сравнивает диапазон с процентным прогрессом.

## 3. Карточка метрики

Верхняя часть постоянна при переключении вкладок:

1. Возврат «Все метрики».
2. Название; действия «Редактировать» и primary «Добавить измерение».
3. ID, состояние KR, направление улучшения, проект или «Без проекта».
4. Выбор периода и его даты. Действия «Настроить цель», «Новый период»,
   «Завершить период». Для черновика primary — «Активировать KR».
5. При необходимости сообщение о первом измерении, просрочке или закрытом периоде.
6. Четыре значения: исходное, цель на дату, последний факт с датой, результат KR.
7. Вкладки «Обзор», «Измерения», «Связанные задачи», «История».

Одна primary-кнопка на рабочую область. Изменение паспорта отделено от изменения
цели: единый паспорт действует во всех периодах, у каждого периода собственные
база, цель, направление и график обновления.

### Обзор

Основная колонка:

- Динамика фактических значений. Цель на конец периода — отдельная пунктирная линия;
  для удержания — диапазон допустимых значений. Будущие факты не дорисовываются.
  Доступный текст и таблица измерений дублируют содержание графика.
- Назначение метрики, определение/методика расчёта, источник данных.
- Сворачиваемые статусы для ключевых проектов, директорской и оперативки ДИД.
- Обсуждение и материалы: комментарии, вложения, автор и время.

Правая колонка:

- Команда, владелец, вовлечённые команды, проект.
- Периодичность, ближайшая дата обновления, свежесть, последний факт.
- Приоритет, бизнес-заказчик, подразделение, клиент ДИД, теги.
- Необязательные вес оценки и прогноз выполнения выбранного периода.

Статусы для встреч в рабочей версии привязываются к конкретному экземпляру встречи,
сохраняют редакции и ссылку на период. Подготовка статуса не означает рассылку.
Прототип показывает редактор текста по видам встреч; выбор конкретной встречи
и сохранение её снимка относятся к реализации.

### Измерения

Таблица: дата измерения, значение с единицей, источник, автор, комментарий,
подтверждающие материалы, действие «Исправить». Сортировка — от нового к старому.

Дата измерения и момент внесения — разные атрибуты. Последний факт выбирается
по дате измерения, а не по времени редактирования. Ввод за прошлую дату не
перезаписывает более поздний факт. В первой версии одна действующая запись
на календарную дату в пределах периода; исправления сохраняются редакциями.

Диалог «Добавить измерение»:

| Поле | Правило |
|---|---|
| Значение | Обязательно; конечное число; ноль и отрицательные значения допустимы, если соответствуют определению показателя |
| Дата измерения | Обязательно; внутри выбранного периода, не в будущем |
| Источник / подтверждение | Обязательно; название отчёта, ссылка или документ |
| Комментарий | Необязательно при добавлении |
| Подтверждающий файл | Необязательно; общие ограничения вложений приложения |

Диалог исправления требует причину. До отправки видны старое и новое значение.
При конфликте версии предлагается перечитать запись, сохранив введённый текст;
никакого молчаливого перезаписывания. Дубликат даты предлагает открыть имеющееся
измерение. После успешного сохранения обновляются факт, результат, график, история
и соответствующая строка реестра.

В прототипе реализованы ввод, валидация дат/чисел/дубликатов и исправление с причиной.
Вложения представлены выбором файла и его метаданными на уровне карточки;
сам файл не отправляется и не сохраняется.

### Связанные задачи

Показываются крупные и рабочие задачи: ID, название, состояние, команда/владелец
при наличии доступа. Доступны поиск существующей работы, привязка и удаление связи.
Одна задача может влиять на несколько метрик. Связь не меняет проект и родительскую
задачу работы. Завершение работы не изменяет измерение.

Переход в задачу сохраняет возможность вернуться к метрике. Если права на работу
отозваны, её закрытые атрибуты не показываются. Прототип демонстрирует выбор
из локальных примеров; реальные переходы, поиск и ACL относятся к внедрению.

### История

События паспорта и периодов, изменение цели с причиной, измерения и исправления,
назначение владельца метрики, связи с работами, файлы и отчётные статусы.
Каждое событие содержит автора, время, изменённые поля, старое и новое значение,
период и причину при необходимости. История измерений не заменяется общим журналом
редактирования задачи.

## 4. Создание и жизненный цикл

Создание разделено на два коротких действия:

1. Паспорт: название, описание, команда, владелец, единица, необязательный проект,
   методика и источник. Дополнительные атрибуты раскрываются отдельно.
   Действие «Создать черновик».
2. Цель периода: период и даты, направление, исходное значение и его дата,
   цель либо границы, график обновления. Действие «Активировать KR».

Черновик допускает неполные методику, источник и цель. Для активации обязательны
согласованные поля; рост и снижение дополнительно требуют базы. Для диапазона
база необязательна. Увеличение требует цели выше базы, уменьшение — ниже;
равенство оформляется удержанием, иначе формула прогресса не определена.

Новый период копирует только выбранные настройки. Последний факт можно предложить
как базу с его реальной датой, но владелец подтверждает его применимость.
Закрытый период не перезаписывается. Периоды не объединяются автоматически.

| Состояние | Разрешённое поведение |
|---|---|
| Черновик | Редактирование паспорта и цели, подготовка к активации |
| Активен | Измерения, исправления, связи, статусы, завершение/отмена с причиной |
| Завершён | Просмотр зафиксированного итога и создание следующего периода |
| Отменён | Просмотр истории и причины; исключение из активных KR |

Достижение цели не завершает период автоматически. Завершение без данных требует
явного подтверждения результата «Нет данных» и итогового пояснения. Восстановление
закрытого периода — отдельное действие с правом и причиной, которое следует
спроектировать при реализации; в прототипе его нет.

Изменение единицы или методики, нарушающее сопоставимость исторических измерений,
не применяется задним числом. Новая единица требует новой метрики либо отдельной
согласованной процедуры преобразования. Методика хранит версию, используемую
периодом/измерением; новое определение не переинтерпретирует старые результаты.

## 5. Расчёт и свежесть данных

Для роста и снижения:

    выполнение = (факт − исходное значение) / (цель − исходное значение) × 100%

Примеры: 50 → 80 при факте 65 даёт 50%; 30 → 15 при факте 21 даёт 60%;
8 → 0 при факте 0 даёт 100%. Отрицательный прогресс означает ухудшение от базы,
выше 100% — перевыполнение. Отсутствие факта или базы не подменяется нулём.

Для удержания проверяется включение факта в границы. Процент выполнения
не рассчитывается. Итог периода должен отдельно учитывать нарушения за период:
одного последнего удачного измерения недостаточно, чтобы объявить весь период
успешным. Точное правило итоговой оценки удержания согласуется при внедрении;
прототип показывает текущее соответствие последнего измерения.

Следующее обновление определяется утверждённым графиком с календарными датами,
часовым поясом и датой следующего обязательного замера. Еженедельный или ежемесячный
график не сдвигается произвольно из-за позднего ввода. Просрочка наступает после
согласованной даты; текущий день отображается «Обновить сегодня».

Для демонстрации в прототипе используется простой интервал от последнего
измерения — 1/7/30/90 дней. Это не реализация календарного графика production.
В рабочей версии потребуются календарные неделя/месяц/квартал и произвольный график,
а также проверка пропусков обязательных измерений.

При изменении цели или базы записываются версия, автор, дата и причина.
Просмотр текущей цели и исторических снимков для встреч должен явно различаться.

## 6. Визуальная система и адаптивность

Используются текущие Inter, JetBrains Mono для ID, акцент приложения, семантические
цвета, светлая и тёмная темы. Общие button, field, badge, filterChip, kpiCard,
pageHeader, tabs и native details/dialog соответствуют UI kit.

Основной экран — компактный реестр без декоративных иллюстраций. График появляется
в контексте одной метрики. Статусы различаются текстом/иконкой наряду с цветом.

- От 1000 px видна боковая навигация, карточка имеет две колонки.
- На промежуточных ширинах меню сворачивается; элементы заголовка переносятся.
- До 700 px реестр превращается в карточки с подписями полей, без горизонтальной
  прокрутки всей страницы; сводка и значения располагаются в два столбца.
- На телефоне основное содержание предшествует дополнительным атрибутам.
- Вкладки допускают локальную горизонтальную прокрутку и навигацию стрелками.
- Диалоги ограничены высотой viewport, прокручиваются, сохраняют видимые действия.
- Фокус виден; после закрытия диалога возвращается к действию, которое его открыло.
  Уход с несохранённым вводом требует подтверждения. Иконки имеют доступные имена.

## 7. Состояния и доступ

| Случай | Поведение |
|---|---|
| Нет метрик | Пояснение и создание первой метрики при наличии права |
| Нет результатов фильтра | Сброс без потери выбранного периода |
| Нет измерений | «Нет данных», предложение внести первое измерение |
| Загрузка | Скелетон существующего UI kit; сохраняется геометрия |
| Ошибка чтения | Сообщение и повтор; действующие фильтры сохраняются |
| Ошибка сохранения | Данные формы сохраняются, ошибка у соответствующего поля |
| Конфликт версии | Перечитать изменения, сопоставить введённые значения |
| Нет права редактирования | Полноценный просмотр без изменяющих действий |
| Нет доступа к объекту | Общая недоступность без раскрытия закрытых атрибутов |

Права чтения/изменения/комментирования и принадлежность команде проверяются
сервером. Предлагается сохранить привычные пользователю области доступа
«свои команды / все», не менять роли и состав команд в рамках выделения метрик.
Владелец метрики — ссылка на существующего пользователя, не назначение роли
и не изменение ответственных команды.

В прототипе показан режим редактора; реальные роли, loading/error/forbidden,
конкурентное сохранение и серверная пагинация описаны здесь, но не симулируются
как готовая функциональность.

## 8. Перенос существующих метрических KR

Перед переносом нужен реестр кандидатов: задачи типа metric_kr и отдельная группа
задач других типов с заполненными metric_kr_plan/fact/unit. Вторую группу нельзя
автоматически считать самостоятельными метриками.

Сохраняются исходные ID и переходы, комментарии, история, вложения, статусы встреч,
связи с проектами и работами. Унаследованное поле fact не получает выдуманную дату
измерения: дата updated_at не является доказательством даты замера.
Записи с неполными базой/направлением/методикой получают признак необходимости
уточнения; их нельзя автоматически активировать.

После перехода метрики не учитываются одновременно как задачи и KR в общих
счётчиках, загрузке команды, канбане и отчётах выполнения. Для отчётных встреч
сохраняются осмысленные отдельные подборки метрик.

Справочник типов задач, пользователи, роли, состав и атрибуты команд не изменяются
автоматически. Для удаления/переименования записи справочника требуется отдельное
прямое указание согласно AGENTS.md. Рабочие задачи, у которых прежний KR был
основным родителем, требуют явного правила сохранения контекста до переноса.
