# ADR-01–10: самостоятельные сервисы агентов

Проверено 05.11.2026 по коду. Решения приняты для реализации; это не завершённая приёмка. Незавершённые проверки перечислены в [AS-IS](../dev-testing/agent-services/IMPLEMENTATION.md) и [матрице](../dev-testing/agent-services/test-matrix.json).

## ADR-01. Границы сервисов

Сохраняются пять самостоятельных сервисов: business-analyst, business-analyst-experimental, meeting-analyzer, backlog-assistant, value-priority-assessor. V1/V2 имеют отдельные исходники, БД и профили. Внутренние роли оценщика остаются внутри продукта. [SDK](../../packages/dmb-agent-contracts/README.md) содержит технические порты, транспорт, очередь, ошибки, resolver и limiter; предметные промпты, формулы и ORM в него не переносятся. Поставка SDK — wheel, не runtime sys.path к соседнему сервису. Offline import образа не заменяет проверку API/worker.

## ADR-02. Reference protocol

Закреплён OpenCode 1.17.13 и [snapshot с SHA256](../../packages/dmb-agent-contracts/dmb_agent_contracts/reference/manifest.json). Поддерживается ограниченное подмножество health/config/agent/session/message/permission/abort/delete. Другая или пустая версия отклоняется до create. Общий адаптер предоставляет status-only события, без raw reasoning. StructuredOutput с finish=tool-calls принимается только со structured object и последующей полной JSON Schema validation. Неизвестный finish, length и неправильный JSON не становятся успехом. Встроенный repair общего адаптера выключен: retryCount=0. Эмулятор и локальный runtime не подтверждают серверный S: real_remote=NOT_RUN.

## ADR-03. Доверенная идентичность

Browser DTO не определяет роли или область данных. Gateway передаёт caller/actor и разрешённый контекст через аутентифицированную границу. V1/V2 повторно проверяют владельца и ревизию диалога; оценщик ограничивает grants конкретными actor/task/operation/source/rubric/TTL. У ассистента сохранена более строгая mTLS/HMAC attestation, связанная с методом, путём, телом, ключом и nonce. Обычный service secret её не заменяет. История не даёт новых прав читать evidence; перед публикацией/чтением проверяются все использованные receipts.

## ADR-04. Старые API и единственный исполнитель

[Run API](../../agents/RUN_API.md) работает рядом с прежними маршрутами. Legacy chat/stream, generation/review V2 и расчёты оценщика адаптируются к долговечному run; выполняет его worker, HTTP ожидает сохранённый результат. Потеря HTTP не отменяет принятую операцию. Клиентский стабильный ключ восстанавливает прежний run; другое тело конфликтует. Необязательные ключи старых DTO остаются необязательными: без них назначается отдельная identity доставки, но восстановить неизвестный повтор без клиентского ключа нельзя. Новая API требует ключ. Прежние квитанции читаются без повторной модели. Разные operations не смешивают ключи. Для встреч DMB владеет capture intent/применением, новый сервис — извлечением. Старые queued/running сохраняют прежнего владельца и не переотправляются новым исполнителем; применение защищают CAS и receipt DMB.

## ADR-05. Хранение и миграции

Каждый сервис использует собственную PostgreSQL БД. SQLite допустим только как явный unit fixture или read-only источник переноса. Импорт API не выполняет DDL; расширение известной непустой схемы требует подтверждённого backup, неизвестная схема отклоняется. Общие agent_runs/events хранят запрос, профиль, source, delivery, terminal CAS и nullable retry ancestry. Область уникальности — caller/actor/operation/key внутри сервиса. Alembic оценщика — 20261104_03, техническая версия ассистента — 4. Миграции не создают и не переносят справочники, пользователей, роли и команды. Публикация продукта и финальный CAS выполняются в одной транзакции.

## ADR-06. Собственные профили и aliases

[Resolver](../../agents/CONFIGURATION.md) сохраняет приоритет источников; пустое значение — override, конфликт aliases отклоняется без значений. Обычный start не копирует ключи между сервисами. Explicit inheritance V2 действует только в памяти; launcher явно отмечает полный process-профиль, Settings сохраняет source=inheritance/from_service=business-analyst. Explicit значения не помечаются наследованием, изменение окружения не переписывает происхождение уже созданного Settings. Пользователь отдельно разрешил разовые Go-cutover V2, встреч, оценщика и ассистента на параметрах V1. Это не автоматический механизм: smoke проходит до записи, прежний профиль сохраняется DPAPI, секреты не попадают в Git/evidence. Модель фиксируется на run; смена профиля до prepare ограждается отказом.

## ADR-07. Tools и provisioning

Оценщик использует фиксированный HTTP-каталог без произвольного shell/URL/SQL/identity. Факторы сначала staged; публикация выполняется с финальным CAS после повторной проверки source/rubric/grant. Remote tools требуют доверенную IsolatedLease с фактической проверкой workspace/state/credentials, image digest, manifest, сетевых маршрутов и cleanup. ProvisioningPort — deployment interface, не выдуманный endpoint OpenCode. Loopback Windows-хоста не считается доступным удалённой машине. Native Docker-контроллер ассистента отделён от модели. Подготовлен контейнерный контроллер с явной сетью и проверкой своего IP; socket-доступ отклонён auto-review и до отдельного ответа пользователя не включается. Модельный runtime не получает Docker socket или provider key.

## ADR-08. Лимиты и конечные бюджеты

Глобальный Redis-профиль допускает две логические операции между процессами, standalone — одну. Per-process счётчик не называется global. Вложенные попытки используют тот же run без второго slot. Потеря Redis/epoch/journal закрывает новый допуск. TTL не доказывает физического завершения и не освобождает аренду. Очередь, deadline, attempts и токенные резервы конечны; сохранены четыре модели/шесть tools/60 секунд ассистента и 90 секунд жизни контейнера. Неизвестное usage не обнуляет резерв: broker ассистента отклоняет недостоверное usage, прочие порты сохраняют null с причиной. Reported cost и Go allowance учитываются отдельно, не вычисляются из неизвестного тарифа.

## ADR-09. Retention, ack и tombstones

Snapshot, result, events и idempotency metadata имеют отдельные сроки. Удалённый результат при действующем ключе возвращает 410 без нового run. Срок гарантии каждого ключа фиксируется в приватной metadata; уменьшение настройки его не сокращает. Старые строки без отметки удерживаются 90 дней. Активные runs не удаляются. Ack следует после commit применения DMB, а повтор применения ограждается receipt. Публичный статус не содержит transcript, credentials или runtime handle. Cancel запрещает публикацию сразу; slot удерживается до подтверждённой очистки всех физических ресурсов.

## ADR-10. Restore и совместимый rollback

Dump/restore проверяется на разрешённой синтетической истории с counts/hashes; предметное чтение и повторная доставка — отдельные проверки. Restore таблиц не доказывает application rollback. Downgrade автоматически не удаляет retry history и не сужает уникальность. Артефакт отката должен понимать новые строки и срок каждого ключа: старый cleaner несовместим с этой гарантией, а старое caller/actor/key может конфликтовать с новыми данными разных operations. Нужны совместимый forward-fix либо подготовленный rollback artifact с сохранением новых данных. Полный актуальный application drill остаётся открыт; рабочая БД DMB не мигрируется на основании одних unit-тестов.
