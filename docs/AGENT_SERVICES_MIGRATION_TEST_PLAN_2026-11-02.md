# Каталог испытаний перехода агентов в самостоятельные сервисы

Приложение к [техническому заданию](AGENT_SERVICES_MIGRATION_SPEC_2026-11-02.md). Сценарии ниже задают проверки будущей реализации. Наличие строки в таблице не означает выполненный тест.

Приоритет текущей приёмки — полноценная локальная работа всех пяти сервисов через Go. Реальный серверный OpenCode недоступен; серверные преобразования проверяются на независимом HTTP-эмуляторе reference-протокола. Испытания реального сервера остаются NOT_RUN и не входят в условие завершения локального перехода.

## 1 Условия выполнения

1. Для каждого теста зафиксировать artifact/version, профиль и тип проверки, начальное состояние, действия, assertions и результат.
2. Не создавать и не изменять защищённые записи БД. Для identity/RBAC unit-проверок использовать mock DTO; для живого UI — существующие готовые QA-профили по [паспорту данных](dev-testing/TEST_DATA_PASSPORT.md).
3. В PostgreSQL integration fixtures создавать только технические записи runs/receipts/leases и разрешённые обычные рабочие объекты. Тесты миграции истории используют разрешённый обезличенный набор без seed защищённых сущностей.
4. Fault injection, остановка worker/runtime и повреждение ответов выполняются на изолированном техническом стенде. Нельзя завершать чужие процессы и удалять чужие контейнеры.
5. Live Go тесты запускаются явно с конечным бюджетом. Отсутствие ключа, квоты или доступа даёт BLOCKED/NOT_RUN, не PASS.
6. Не сохранять ключи, cookies, JWT, credentials URLs и закрытые материалы в evidence. Синтетические тексты допускаются в отчёте.
7. В таблицах «Требования» указывают разделы ТЗ; окончательный машинный mapping перечисляет конкретные requirement IDs.

## 2 Локальные профили и конфигурация

Тип проверки: process/integration с fake provider для отказов; отдельные live Go прогоны обозначены явно.

| T-L02 | Для всех пяти задать локальный профиль; оставить remote URL/secret пустыми | Старт не требует remote; active profile отражает локальный Go/backend | MODE, CFG |

| T-L04 | Удалить ключ только из изолированной тестовой конфигурации активного профиля | Явная ошибка обязательной настройки; mock и другой provider не выбираются | GO, MODE, CFG |
| T-L05 | Задать конфликтующие старое и новое env имя | Отказ с именами параметров без их значений; нет случайного приоритета | CFG |

Тип проверки: независимый HTTP-эмулятор; настоящий сервер не используется.

| T-R02 | Ответ health содержит неизвестную/пустую версию | `runtime_version_unsupported`; submit отсутствует | REM |

| T-R04 | Эмулятор принимает submit, но закрывает соединение без ответа | Delivery=`unknown`; клиент проверяет прежний message; второй submit не отправляется | RUN, REM |
| T-R05 | Соединение заведомо не установлено до передачи задания | Применяется документированная safe-retry policy в пределах того же deadline; business run не дублируется | RUN, LLM |
| T-R06 | Поступает assistant result с чужим session ID | Кандидат отклонён; чужой результат не публикуется | AUTH, SEC |

| T-R08 | Ответ имеет неправильный JSON, неизвестные поля или `finish_reason=length` | Схема/полнота проверяется; нет completed с неполным документом; repair учитывает общий бюджет | LLM |
| T-R09 | Во время выполнения появляется unexpected permission request | Действие отклонено; операторский approval не выдумывается; run получает конкретную причину | SEC, REM |
| T-R10 | Отправить cancel до готового результата и затем вернуть результат | Результат не публикуется; grant отозван; выполняется cleanup | RUN |
| T-R11 | Вернуть abort success, но оставить runtime живым | Состояние cleanup pending/failed; слот не освобождён только по abort success | RUN, QUE |
| T-R12 | Cleanup transport падает; перезапустить контроллер | Сохранённая identity используется janitor; отсутствие cleanup не забыто | RUN, QUE |
| T-R13 | Эмулятор обрывает SSE, повторяет события и меняет порядок частей | Resume/dedup работают; ошибочный порядок выявлен; итог не собирается из чужих частей | EVT, REM |
| T-R14 | Необходимая capability отсутствует | Операция отклоняется до выполнения; профиль не объявляется поддержанным по имени агента | REM, MODE |
| T-R15 | Remote tool route указывает loopback Windows-хоста или отсутствующий bridge | Диагностика сообщает конкретную сетевую предпосылку; local profile не затронут | REM, OPS |
| T-R16 | Независимо изменить fixture эмулятора так, чтобы она нарушила pinned OpenAPI | Валидация fixtures падает; клиент и emulator не подтверждают одну общую ошибочную выдуманную схему | CI, REM |

Дополнительный тест настоящего локального OpenCode допускается с label `local_reference_runtime`. Даже если он проходит, `real_remote` остаётся NOT_RUN.

## 14 Формат итогового отчёта

Для каждой группы указываются общее число обязательных случаев, PASS, FAIL, BLOCKED, NOT_RUN, profile и artifact versions. Для каждого FAIL/BLOCKED приводятся test ID, фактическое отклонение, влияние, безопасный evidence ref и требуемое действие.

Отдельные строки результата:

| Область | Разрешённая итоговая запись |
|---|---|
| Локальные сервисы через Go | `accepted_local`, только если обязательные локальные критерии реально пройдены |
| Подготовка серверного адаптера | `prepared_contract_tested`, только после reference emulator suite |
| Настоящий сервер | `not_verified`, `real_remote=NOT_RUN` до отдельной будущей задачи |

Не допускается одна общая зелёная отметка, скрывающая разные уровни доказательств. Локальные дефекты и ограничения внешнего провайдера перечисляются рядом с соответствующим результатом.
