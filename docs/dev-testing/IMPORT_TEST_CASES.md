# Ручные тест-кейсы импорта

## 1. Область и безопасность

Импорт обязателен для первого полного DEV-цикла. Backend принимает только CSV, а frontend позволяет выбрать CSV/XLS/XLSX и преобразует Excel в CSV.

Тесты выполняются разрешённым профилем с `backlog_team: write_own` в выделенной области. Файлы используют только существующие значения справочников, пользователей и команд. Импорт не должен создавать, изменять или архивировать справочники, пользователей, роли, команды, состав и ответственных.

Нельзя запускать backend pytest импорта против общей DEV-БД: фикстуры автотестов создают защищённые данные.

## 2. Предусловия

- Google Chrome зафиксированной версии.
- Подготовлен профиль доступа и целевая тестовая область.
- Владелец данных предоставил разрешённые read-only значения справочников.
- Все создаваемые задачи имеют маркер цикла `DEV-QA-<цикл>-IMP-*`.
- Подготовлен журнал создаваемых task IDs для последующей очистки.
- Импортируемые файлы не содержат реальных или конфиденциальных данных.

## 3. Тест-кейсы

### TC-IMP-01. Валидный CSV UTF-8 с BOM

1. Подготовить одну валидную строку с обязательными полями и разрешёнными справочными значениями.
2. Открыть импорт из backlog.
3. Выбрать CSV и выполнить импорт.
4. Открыть созданную задачу.

Ожидается: `total=1`, `created=1`, `skipped=0`; задача доступна; поля соответствуют файлу; создана история и audit action `import`; защищённые справочники не изменены.

### TC-IMP-02. Windows-1251 и разделитель `;`

Импортировать синтетический русский CSV в Windows-1251 с `;`.

Ожидается: кодировка и разделитель распознаны; кириллица не повреждена; создана одна задача.

### TC-IMP-03. Разделитель `,` и технические ключи заголовков

Использовать `,` и допустимые ключи полей в разном регистре.

Ожидается: заголовки сопоставлены без учёта регистра; значения сохранены корректно.

### TC-IMP-04. Русские labels заголовков

Использовать утверждённые текущие `field_labels` только для чтения/сопоставления.

Ожидается: известные labels распознаны; импорт не изменяет сами labels.

### TC-IMP-05. XLS/XLSX через frontend

1. Подготовить XLS и XLSX с одной валидной строкой.
2. Импортировать каждый файл через UI.
3. В Network проверить отправляемый файл.

Ожидается: frontend преобразует Excel в CSV; backend получает допустимый CSV; задачи создаются. Прямой API-вызов с `.xls/.xlsx` не должен приниматься как backend-контракт.

### TC-IMP-06. Частично валидный файл

Файл содержит одну валидную и одну строку с отсутствующим обязательным полем.

Ожидается: валидная строка создана, ошибочная пропущена; итоговые counts согласованы; ошибка содержит row, field/label, type `required_missing`, message и fatal.

### TC-IMP-07. Неизвестное справочное значение

По отдельности использовать несуществующее значение команды/канала/заказчика/подразделения/проекта/типа/приоритета/срока/статуса, не создавая его.

Ожидается: строка пропущена с соответствующим `*_not_found`; справочник не изменён; другая валидная строка файла может быть создана.

### TC-IMP-08. Неизвестный исполнитель

Использовать синтетический login, которого нет в DEV.

Ожидается: нефатальная `owner_not_found`; обычная задача сохраняется без исполнителя; пользователь не создаётся.

### TC-IMP-09. Даты

Проверить разрешённые форматы `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `DD.MM.YY`, `DD/MM/YY` и отдельную невалидную дату.

Ожидается: допустимые даты распознаны; невалидная строка пропущена с `invalid_date`.

### TC-IMP-10. Числа и прогресс

Проверить допустимые числа, прогресс `0`, `100`, затем `-1`, `101` и дробное значение.

Ожидается: границы 0/100 приняты; неверный прогресс даёт `invalid_progress`; неверное число — `invalid_number`.

### TC-IMP-11. Неизвестный заголовок

Добавить колонку `DEV_QA_UNKNOWN_COLUMN`.

Ожидается: колонка игнорируется; не создаётся новое поле/справочник; остальные допустимые данные импортируются.

### TC-IMP-12. Пустой и недопустимый файл

Проверить пустой CSV, `.txt` через прямой backend contract и повреждённый Excel через UI.

Ожидается: понятная ошибка без созданных задач и stack trace; UI позволяет исправить выбор.

### TC-IMP-13. Повтор того же файла

Повторно импортировать валидный файл после явного предупреждения тестировщику.

Ожидается: фактическое поведение зарегистрировано. Дедупликация по внешнему ID не ожидается, поскольку такого контракта нет; созданные дубликаты учитываются в журнале и очищаются как обычные тестовые записи.

### TC-IMP-14. Узкое и широкое окно

Выполнить TC-IMP-01 и просмотреть результат на VP-01, VP-05 и VP-08.

Ожидается: modal, выбор файла, итоговые counts и таблица ошибок доступны; длинные messages/values переносятся; главное действие не перекрыто; большой экран не растягивает данные до нечитаемого вида.

### TC-IMP-15. Клавиатура и zoom 200%

Без мыши открыть import modal, выбрать файл доступным способом, запустить импорт, прочитать результат и закрыть modal; повторить ключевой экран при zoom 200%.

Ожидается: focus видим и логичен; modal удерживает focus; ошибки доступны не только цветом; кнопки достижимы.

## 4. Evidence

Для каждого прогона сохраняются:

- исходный синтетический файл;
- build, Chrome version и viewport;
- итоговые `total/created/skipped`;
- безопасный фрагмент errors;
- созданные task IDs;
- screenshot результата;
- подтверждение отсутствия мутаций защищённых данных;
- результат очистки обычных импортированных задач.

## 5. Критерии прохождения

- TC-IMP-01, 02, 05, 06, 07, 08, 09, 10, 12, 14 и 15 пройдены;
- валидные строки создаются, ошибочные изолируются;
- counts и сообщения соответствуют факту;
- история и аудит создаются для успешной задачи;
- импорт не меняет защищённые данные;
- нет необработанной ошибки UI/API;
- все созданные task IDs зарегистрированы для очистки.
