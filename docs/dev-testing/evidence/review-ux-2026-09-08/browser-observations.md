## Измерения

Контролируемый viewport мобильной карточки: **390×844 CSS px**. При верхней позиции страницы #8:

- decision card: top ≈565.1, height ≈300.0;
- participants card: top ≈881.1, height ≈301.8;
- navigation sections: top ≈1198.9;
- passport: top ≈1409.6, height ≈843.9;
- acceptance criteria: top ≈2269.5.

Предупреждение потери текста в том же viewport:

- dialog: left=8, right≈374, width=366, overflow=hidden;
- notice `.review-modal-discard`: display=flex, flex-direction=row;
- группа кнопок: left≈255.6, right≈426.9, width≈171.3;
- внутренняя группа имеет flex-direction=column, но это не исправляет горизонтальный ряд внешнего notice.

Это подтверждает переполнение внутренней композиции. Скриншот может включать полосу прокрутки и отличаться размером bitmap от CSS viewport; размеры элементов взяты из `getBoundingClientRect`, а не оценены по картинке.

Широкий desktop: **1440×900 CSS px**. Область очереди имела height=468 (52vh), top≈250.3, bottom≈718.3. Это установленное ограничение высоты, а не задержка загрузки. Качество 63% — font-size 16px, color rgb(245,158,11); сигналы — 12px того же цвета; чипы taxonomy — 11px. Сводка detail — подписи 10px, color rgb(148,163,184). Часть measured samples сохранена в [desktop-dom-metrics.json](desktop-dom-metrics.json).

В DOM оставались незаменённые `i[data-lucide]`:

- очередь: `user-round-x`, `clock-alert`, `circle-alert`, `user-round`;
- detail #8: `user-round-check`, `circle-plus`, `git-pull-request-arrow`.

Консоль Lucide сообщала, что соответствующее имя отсутствует в предоставленном наборе. На скриншоте очереди это видно как пустые круги части быстрых фильтров. Подписи остаются, поэтому это не блокировка всего действия.

Сигналы #12:

- «Требуется уточнение: Риски» → request-section-risks; узла нет;
- «Требуется уточнение: Регуляторные аспекты» → request-section-regulatory; узла нет;
- «Какое наблюдаемое условие или показатель подтвердит выполнение требования?» → request-section-problem; связь выбрана fallback-эвристикой.

Форма передачи в DOM:
