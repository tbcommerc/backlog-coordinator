# Комплексный аудит импорта задач

> Это датированный evidence-срез поведения импорта на 20.09.2026. Он не
> заменяет актуальные спецификации и не утверждает, что найденные дефекты уже
> исправлены.

## Итог

Решение **не готово к выпуску без исправления P1-дефектов**. Базовые позитивные
сценарии CSV/XLS/XLSX и адаптивная компоновка работают, но предварительное
превью не является надёжным прогнозом серверного импорта. В нескольких случаях
UI разрешает отправку файла, который сервер прочитает иначе или отклонит, а
значения с очевидными ошибками могут не получить ни одного предупреждения.

Проверка охватила:

- 56 специально сгенерированных входных файлов в 23 группах эквивалентности;
- 47 CSV-прогонов через фактический серверный parser/service без записи в БД;
- 10 сценариев HTTP-маршрута и граничных размеров;
- 4 сценария транзакции, включая ошибку строки и финального commit;
- 16 представительных файлов в реальном интерфейсе с изолированным API;
- 5 viewport: 1440×900, 1280×720, 768×800, 390×844 и 360×640;
- 4 настоящих XLSX с повторным чтением, render всех листов и проверкой формул.

Все входы, manifest, машинные результаты, скриншоты и воспроизводящие сценарии
находятся в [`evidence/import-testing-2026-09-20/`](evidence/import-testing-2026-09-20/).

## Методика и границы

Серверная часть проверялась непосредственно на `import_service.py` и endpoint
`/tasks/import`; обращения к справочникам, создание задач и commit были заменены
контролируемыми in-memory doubles. Это позволило безопасно проверить parser,
валидацию, savepoint и rollback, не создавая задачи и не изменяя защищённые
данные. UI запускался из фактического frontend-кода; ответы API импорта были
замокированы, чтобы проверить состояния интерфейса без записи в БД.

Поэтому подтверждены все доступные ветви формата файла, разбора, локальной
валидации, HTTP-ограничений, отображения результата и транзакционного контроля,
но не выполнялась destructive/integration-проверка реальных FK/ограничений
PostgreSQL и фактическое создание задач в общей БД. Абсолютное доказательство
«всех возможных ошибок» для произвольных байтов невозможно; покрытие построено
по ветвям кода, границам и классам эквивалентности.

## Критические дефекты

| ID | Приоритет | Подтверждённое наблюдение | Риск / ожидаемое поведение |
|---|---:|---|---|
| IMP-01 | P1 | CSV-preview и backend используют разные парсеры. CP1251 поддерживается сервером, но блокируется UI; пустая первая строка принимается UI, но ломает определение разделителя на сервере; quoted multiline показывается как две строки; UTF-16LE выглядит валидным в браузере, но не принимается backend. | Пользователь не может доверять предпросмотру. Нужен единый parser/контракт или серверный dry-run preview. |
| IMP-02 | P1 | `validateRows()` сопоставляет колонки только по локализованной подписи, хотя заголовочная проверка и backend принимают технические ключи. Файл №55 с пустыми title, неверными датами, progress >100 и нечисловыми значениями получил 0 предупреждений, кнопка импорта активна. | Сопоставлять по `fieldLabel` **и** DB-key; лучше возвращать нормализованный preview с сервера. |
| IMP-03 | P1 | При ошибке финального commit возвращается `total=2`, `created=0`, `skipped=0`; инвариант `total = created + skipped` нарушен. | Результат и отчёт вводят в заблуждение. После rollback все обработанные строки должны считаться неимпортированными/пропущенными с общей ошибкой. |

## Остальные дефекты и UX-наблюдения

| ID | Приоритет | Наблюдение | Рекомендация |
|---|---:|---|---|
| IMP-04 | P2 | Drop-zone — `div` без `role`, accessible name и `tabindex`; клавиатурой открыть выбор файла нельзя. Escape модальное окно не закрывает. | Сделать drop-zone кнопкой или добавить button-семантику, Enter/Space, видимый focus; поддержать Escape и возврат фокуса. |
| IMP-05 | P2 | Пустой CSV и повреждённый Excel не получают inline-ошибки в модальном окне: preview пуст, submit disabled. Для Excel используется только toast. | Показывать устойчивое состояние ошибки рядом с файлом и кнопку повторного выбора; очищать предыдущее preview-состояние до чтения нового файла. |
| IMP-06 | P2 | Сервер принимает `NaN`, `Infinity` и scientific notation для float-полей; любое неизвестное непустое boolean-значение превращается в `false`; числовой ID вовлечённой команды принимается без проверки существования. | Ввести конечность/диапазоны, явный список true/false с ошибкой на неизвестное значение и проверку каждого FK. |
| IMP-07 | P2 | Незакрытая кавычка, NUL-байт, дубли заголовков и повтор одной и той же задачи не отклоняются. При дублированном заголовке фактически побеждает одно значение; дедупликации строк нет. | Валидировать структуру CSV в strict-режиме, уникальность заголовков и определить продуктовую политику дубликатов. |
| IMP-08 | P2 | Успешный результат автоматически закрывается через 1,5 секунды, хотя именно в этом состоянии доступны «Скопировать отчёт» и «Скачать отчёт». | Не закрывать автоматически; оставить явную кнопку завершения. На время запроса и результата исключить повторную отправку. |
| IMP-09 | P2 | Общая ошибка с `row: null` отображается как «Строка null». | Для `null` выводить «Файл» или «Импорт». |
| IMP-10 | P2 | Спецификация ошибок и runtime расходятся: неизвестные `business_customer` и `did_client_group` являются нефатальными в коде, хотя документ описывает как минимум бизнес-заказчика как fatal; delimiter документирован по первой непустой строке, код берёт первую физическую строку. | Согласовать продуктовый контракт, код, тесты и документацию. |
| IMP-11 | P3 | Excel всегда читается только с первого листа. Если первым идёт инструкция, а данные — вторым, импорт блокируется; выбрать лист нельзя. | Показывать selector листа или автоматически искать строку заголовков на листах. |
| IMP-12 | P3 | Preview ограничен пятью строками и не сообщает определённую кодировку, разделитель, выбранный лист и общее число строк. | Добавить сводку файла и явные параметры интерпретации. |

## Что работает корректно

- UTF-8 BOM, UTF-8 с `;` и `,`, CP1251 на backend, русские и технические
  заголовки, регистр и внешние пробелы проходят серверный parser.
- Неизвестные необязательные колонки игнорируются; пустой файл, неверное
  расширение, отсутствие обязательных заголовков, превышение 10 МБ и 10 000
  строк получают контролируемый отказ.
- Ошибка обработки или сохранения отдельной строки изолирована savepoint:
  последующая строка продолжает обрабатываться.
- Основная модалка аккуратно помещается во все пять viewport, footer не
  обрезается, document-level horizontal overflow нет. Таблица широких данных
  прокручивается локально.
- Фокус после открытия находится внутри dialog, обычный Tab-цикл не выходит из
  него; длинное сообщение переносится и не создаёт горизонтальный overflow.
- Успех, частичный результат, длинные сообщения и большое число ошибок
  визуально различимы; базовая иерархия и адаптивность выдержаны.

## Критерии повторной приёмки

1. Один и тот же файл даёт одинаковые строки, колонки и ошибки в preview и backend.
2. №03, 23, 26, 28, 33 и 55 из manifest проходят с согласованным ожидаемым
   результатом; кнопка не активна при fatal preflight-ошибках.
3. Для любого ответа выполняется `total = created + skipped`, включая rollback.
4. Drop-zone полностью управляется мышью и клавиатурой; dialog закрывается
   Escape, возвращает фокус и сохраняет доступ к отчёту до явного закрытия.
5. Ошибка чтения видна inline и не оставляет preview от ранее выбранного файла.
6. Числа конечны и находятся в допустимых диапазонах; неизвестные boolean/FK,
   malformed CSV и дубли headers обрабатываются по явно задокументированной политике.
7. Повторный прогон сохраняет отсутствие viewport overflow на пяти размерах.
