# Повторное исправление компактного списка

Дата проверки: 21.10.2026. Основание: замечание пользователя к фактическому
экрану и [ТЗ](../work-tasks-redesign-spec.md).

## Исправлено

- Убраны конфликтующие правила адаптивности очереди. Переход к сетке зависит
  от ширины очереди (860 px), а не от прежнего порога 1079 px.
- Название получает оставшуюся ширину; исполнитель, срок и статус выровнены
  по колонкам. Высота обычных строк живого приложения на 1280 px — около 60 px.
- На узком экране нет полос и границ между полями одной задачи. Приоритет,
  препятствие и контекст находятся под названием; чек-лист сокращён до счётчика.
- До 900 px подборки заменяются селектором, поиск раскрывается кнопкой,
  создание имеет компактную кнопку «+» с доступным названием.
- Обновлены версии CSS и цепочки JS-импортов для загрузки исправлений.

## Проверка глазами

Живое приложение `http://127.0.0.1:8000` проверено под существующей QA-учёткой
на 1280 и 390 CSS px. Записи БД не изменялись. Отдельный стенд использует
настоящие компоненты страницы, CSS и демонстрационные данные с длинными
названиями/ФИО, приёмщиком, препятствием, приоритетом и чек-листом.
Осмотрены размеры 320, 390, 768, 1024, 1280 и 1440 px, светлая и тёмная темы.

Увеличение 125%, 150% и 200% проверено в браузере через уменьшение CSS viewport
и масштаб iframe. Это эмуляция геометрии zoom; штатный масштаб браузера
инструментом не изменялся. Полная проверка нативного zoom остаётся ограничением.

Автоматический итог: **51 PASS** (`workListDensity`, `workRedesign`,
`workSplitWorkspace`, один worker). После последней правки hover/selected
повторно выполнены **18 PASS** из `workListDensity`; состояние выбранной строки
дополнительно осмотрено в живом браузере. Проверены геометрия, отсутствие
горизонтального переполнения, карточка, клавиатурное меню и существующие сценарии
фильтров/черновиков. Синтаксис изменённых JS и локальные ссылки профильных
документов проверены. Первые прогоны были прерваны из-за зависания завершения
встроенного webServer на Windows; итоговые прогоны завершились с кодом 0
на отдельно запущенном локальном сервере. Ошибочное ожидание подписи меню
в новом тесте исправлено до итогового прогона.

Воспроизведение: из `dmb-backlog` выполнить
`npx playwright test frontend/e2e/workListDensity.spec.mjs frontend/e2e/workRedesign.spec.mjs frontend/e2e/workSplitWorkspace.spec.mjs --workers=1`.
Полная приёмка 32 критериев исходного ТЗ этим исправлением не объявляется:
границы общей поставки сохранены в [предыдущем отчёте](WORK_TASKS_REDESIGN_2026-10-21.md).
