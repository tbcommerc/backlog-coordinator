# Таблицы данных UI Kit

Дата проверки: 29.10.2026. Вторая очередь дополнений после сравнения с IBP.

## Что реализовано

- `dataTable` строит таблицу из описания колонок и строк: caption, scope,
  состояния loading/empty/error через ViewState, доверенные слоты toolbar/footer.
- `tableCell` задаёт текст, число, дату, безопасную ссылку, бейдж и вторую строку.
  Пользовательский текст экранируется; 0 не заменяется прочерком; отсутствующие
  и некорректные числовые значения показываются как «—». Календарная дата не
  зависит от часового пояса; недопустимая дата не нормализуется незаметно.
- `bindDataTable` передаёт запрос сортировки потребителю. Текущий порядок и
  aria-sort меняются только при новом рендере. Повторная привязка и dispose
  не оставляют дублирующихся обработчиков.
- Мобильный режим cards сохраняет подписи полей и кнопки сортировки;
  scroll сохраняет широкую таблицу внутри фокусируемой области прокрутки.
- Реестр метрик и измерения переведены на общий компонент; локальная сборка
  таблиц и устаревшие правила их геометрии удалены. Существующий серверный
  поиск, фильтры, сортировка, пагинация и проверки прав сохранены.
- Каталог содержит пример локальной сортировки; семейства зарегистрированы
  в инвентаризации UI Kit.

Подход IBP Table/TableCell использован как ориентир разделения контейнера и
ячейки. Реализация использует токены, ViewState, Button и Badge нашего проекта.
API описан в [UI Kit](../../dmb-backlog/docs/UI_KIT.md), правила владения — в
[контрактах](../../dmb-backlog/docs/UI_KIT_CONTRACTS.md).

  сохранение фильтров и существующие диалоги с защитой черновика.

  UI API, границы core, доступность диалогов, владение и обнаружение потребителей.
- Финальные снимки каталога, реестра и измерений проверены визуально.
  Артефакты: `dmb-backlog/.runtime-ui-tables-final/`, не для Git.
- Инвентаризации семейств и потребителей пересобраны и сверены с исходниками.

  эта поставка не присваивает им новых доказательств ревью.

  изменённого потребителя метрик сохранены без ложного статуса приёмки.

Первый прогон: 27 PASS, 1 FAIL — минимальная ширина таблицы растягивала внешний
grid-контейнер вместо внутреннего скролла. Исправлено ограничением расчёта
внутренней ширины (`contain: inline-size`); повтор всех 28 сценариев успешен.
Снята также послойная подсветка отдельных мобильных ячеек: hover применяется
к строке целиком, без цветных разрывов между полями.

Повторить: `npm run test:ui-tables` из `dmb-backlog/`. Конфигурация использует
собственный статический сервер 4188 и API-фикстуры; рабочая БД и защищённые
данные не изменяются. Это компонентная и интеграционная проверка, не полная
ролевая приёмка на живой БД и не полный `verify:ui-kit`.

## Границы

Не включены: изменение/закрепление/перестановка колонок, виртуализация,
универсальные выбор строк и массовые действия. Существующие сложные таблицы
бэклога не переписаны. EntityPicker, DateRange/NumberRange, StepForm и SplitPane
остаются следующими частями плана. Первая очередь описана в
[отчёте о карточках](UI_KIT_DETAIL_COMPONENTS_2026-10-29.md).
