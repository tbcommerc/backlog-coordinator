# Только название обязательно для задачи — 23.11.2026

**Последующее требование банка:** [структура БД готовится DBA отдельно](../BANK_DEPLOYMENT.md).
Применение Alembic из приложения при банковском старте запрещено. Образ и
репетиция ниже исторические; банковский профиль и проверка роли добавлены позже.

По запросу пользователя единственное обязательное бизнес-поле обычной задачи
Бэклога — непустое название длиной до 255 символов. Это правило действует
в форме создания, редакторе, POST/PATCH/PUT и CSV-импорте. Техническая версия
для optimistic lock при изменении остаётся обязательной.

## Поведение

- `POST /api/v1/tasks/` принимает `{"title":"Новая задача"}`. Команда, тип,
  канал, дата, описание и остальные атрибуты не требуют ручного заполнения.
- На форме звёздочкой отмечено только название. Кнопка создания доступна после
  его заполнения. Пустые справочники не блокируют создание.
- Редактор всех команд может оставить команду пустой и очистить ранее
  заполненные команду, тип, канал и дату. Командному редактору при создании
  автоматически назначается его команда; он не может снять или сменить её
  в обход своей области доступа. Права пользователей и роли не меняются.
- Если в справочниках существуют стандартные «Новая задача» и «Средний»,
  создание использует их как значения по умолчанию. Их отсутствие не даёт 500.
  Дата создания задачи и дата поступления при создании заполняются штатно;
  дата поступления может быть явно очищена при редактировании.
- Пустой прогресс в редакторе соответствует 0. Проверки диапазонов, форматов,
  допустимых справочных ID и согласования статуса с прогрессом сохраняются.
- CSV может содержать только колонку `title`, «Название» или «Название задачи».
  Старые `field_labels.is_required` не добавляют другие обязательные поля.
  Сами защищённые записи метаданных не изменяются.

## Развёртывание

Новая миграция [d453b20d51f9](../../dmb-backlog/backend/alembic/versions/d453b20d51f9_optional_task_team.py)
после `d352a19c40e8` снимает NOT NULL с `tasks.team_id`. Перед запуском новой
версии выполнить штатный `alembic upgrade head`. Миграция не меняет строки
справочников, пользователей, состав команд или назначения существующих задач.
Откат останавливается, если есть задачи без команды: оператор должен явно
решить их принадлежность до возврата к старой схеме. Автоматических подстановок
и удаления задач при откате нет.

Ранее проверенные образы и комплекты из
[отчёта по ссылкам](TASK_CARD_REFERENCE_FIX_2026-11-23.md) остаются историческими:
они не содержат текущего изменения и новой миграции.

## Проверка

Функционально: **53 серверных проверки PostgreSQL**, **511 модульных frontend**
и **23 браузерных проверки Chromium** прошли. Из них новые 9 серверных случаев
проверяют создание только с названием при наличии и отсутствии справочников,
чтение после сохранения, очистку необязательных атрибутов через PATCH/PUT,
отказ пустому названию, CSV с одной колонкой и командную область доступа.
Новые 5 браузерных случаев покрывают создание в обеих темах на 1440/390 px
и очистку команды, типа, канала, даты и прогресса в редакторе.

и также прошёл: снимки отражают начало формы целиком в видимой области.

Миграция проверена настоящим Alembic на отдельной PostgreSQL: старая схема →
head, вставка задачи только с названием, безопасный отказ отката с сохранением
