# Матрица проверки доступа

## 1. Принцип

Права подтверждаются одновременно на трёх уровнях:

1. **Page:** видимость меню, route и корректный redirect/forbidden UX.
2. **Action:** доступность действия и серверный результат.
3. **Object scope:** доступ к своему, командному и чужому объекту.

Скрытая кнопка не доказывает безопасность. Для запрещённого действия выполняется прямой запрос через штатный API-клиент/DevTools без изменения токена и без попыток обхода аутентификации.

Матрица заполняется по профилям AP-01–AP-07 из [`TEST_DATA_PASSPORT.md`](TEST_DATA_PASSPORT.md). Фактические штатные роли предоставляет владелец стенда; тестировщик не изменяет роли и назначения.

## 8. Запись результата

Для каждого отрицательного теста сохранить method/path/status и безопасный фрагмент response без токенов. Не прикладывать полный Authorization header, refresh cookie или персональные данные.

Критерий прохождения: 100% P0 ownership/isolation проверок и отсутствие расхождения page/action/object scope. Любое расхождение регистрируется через [`DEFECT_TEMPLATE.md`](DEFECT_TEMPLATE.md).
