## Что обнаружила репетиция

- Windows lock не включал Linux-зависимость `uvloop` для `uvicorn[standard]`.
  Dockerfile переведён на отдельный хэшированный Linux lock. Общие версии
  пакетов сохранены; установленные зависимости проверены `pip check`.
- Закреплённый ранее Collector 0.132.0 был linux/386. В Compose и валидаторе
  закреплён multi-platform manifest того же релиза; реальный `validate` проходит.
- Внутренний Nginx терял внешние HTTPS и порт в Host. Он сохраняет доверенный
  `X-Forwarded-Proto` и полный Host; внешний ingress обязан перезаписывать этот
  заголовок клиента. Проверка slash-redirect включена в полный прогон.
- Два UI Kit контракта дополнены метаданными владения без замены дизайна:
  объявлен прежний default `--registry-pin-count:5`, зарегистрирован `TableColumns`.

## Критерии внутри банка

`compose.demo-core.yaml` предназначен для локальной репетиции: его loopback
origin, временный сертификат и синтетические реквизиты не являются конфигурацией
банковской ВМ. Внутри контура нужен свой внешний HTTPS origin и секреты по
[порядку подготовки](../DEMO_STAND_SETUP.md). Это также не проверка всех
сценариев Метрик/Проектов/Рабочих задач: для них проверено открытие реестров,
а операции создания/редактирования в этом прогоне относятся к Бэклогу.

1. Перенести проверенный образ; сверить image ID/контрольные суммы. Секреты,
   сертификаты, внешний origin и доступ к инфраструктуре задаются внутри контура.
2. Проверить readiness, Redis, PostgreSQL, общее хранилище, готовность ClamAV
   с доставленными сигнатурами, миграцию и согласование справочников.
3. Запустить `stand_smoke.py` с внешним банковским URL, доверенным CA и
   `--wait-access-expiry`; затем повторить браузерный сценарий Бэклога.
4. Подтвердить создание/редактирование/повторное открытие задачи, новый
   приоритет, фильтрацию, экспорт и вложения; проверить роль наблюдателя.
5. Иметь согласованный backup БД и вложений, проверенную процедуру восстановления
   и версию для возврата. Откат схемы сам по себе не восстанавливает данные.

До прохождения этих пунктов локальные результаты не являются гарантией работы
банковских TLS/ingress/DNS/firewall, установленных ресурсов ВМ или её старых данных.
Репетиция не является нагрузочной/длительной приёмкой и не использует копию
банковской БД. Проверка обновления воспроизводит предшествующую схему
`d251c98e30f7` с синтетическими расходящимися ID. Восстанавливается PostgreSQL
через `pg_dump`/`pg_restore`; восстановление файлов из backup вложений отдельно
не проверялось. Эти границы нельзя заменять утверждением «проверено всё».
