# Унификация таблиц по эталону «Бэклог»

Дата: 04.11.2026. Область: UI Kit, бэклог, реестр метрик, очередь рабочих задач,
табличный каталог, план, отклонения и результаты проектов. Это fixture-проверка;
live-приёмка открыта. Предметные права и API не изменены.

## Что изменено

Общий `DataTable` получил `variant:'registry'`; ручные таблицы используют
`data-ui-table="registry"`. Оформление названий, служебного текста, ID и основной
строки закреплено в [контракте](../../dmb-backlog/docs/REGISTRY_TABLES.md).
У рабочих задач удалены конфликтующие размеры заголовка и desktop padding;
у проектов удалено увеличение текста ячеек, каталог получил общую поверхность.
У бэклога inline-стиль названия заменён общей ролью без изменения состава колонок.

Названия на desktop занимают одну строку с многоточием, `title` и полным текстом
в DOM; на мобильном переносятся. Дата факта, контекст, просрочка и чек-лист сохранены.
В плане проекта веха стоит рядом с названием через общий `ui-table-primary`.

## Функциональная проверка

- `registryTables.spec.mjs`: 20/20, пять полных экранов SPA × две темы × 1440/390 px.
  Проверены итоговый размер/вес названия, desktop padding, отсутствие внешнего
  overflow, переход из каталога в проект и открытие рабочей задачи.
- Unit: DataTable, выбор строк и расчёт ширин бэклога — 10/10.
- Общая регрессия DataTable, метрик и проектов: 83/85 в основном прогоне;
  два инфраструктурных сбоя (таймаут создания страницы и загрузки CSS) прошли
  отдельным повтором 2/2, без изменения кода или ослабления проверок.
- План проекта после размещения вехи рядом с названием: повтор 4/4,
  обе темы и ширины; итоговые снимки заменены осознанно после осмотра.
- `test:design`: режим сбора полных экранов 10/10; осмотренное обновление только
  связанных эталонов 7/7. Последующая проверка без обновления имела 8/10:
  падение Chromium и таймаут навигации. Финальный последовательный прогон
  завершён 10/10 без обновления снимков (`.runtime-registry-design-verified`);
  эти сбои не выдаются за визуальный diff.

Первый прогон в общем `test-results` имел 18 успешных сценариев и две ошибки
исчезнувших trace-файлов при закрытии browser context. Повтор в отдельном
`.runtime-registry-tables` завершился 20/20; эти ошибки не скрыты обновлением эталонов.

## Визуальная оценка

Осмотрены полные исходные экраны и результат в оболочке SPA, обе темы,
desktop и mobile. Оценка: общие шапки, типографика названий, поверхность и
отступы согласованы с бэклогом. Каталог проектов больше не выглядит набором
обычных ссылок на фоне страницы. Высота строк с предметными сведениями остаётся
больше минимальной; это содержимое, а не самостоятельная шкала размеров.

Рабочие задачи: дополнительно осмотрены 1366×768, инспектор, модальная карточка
и редактирование. Исходный `test:design` обнаружил семь сценариев с ожидаемыми
расхождениями; diff показывает изменение текста/ID и последующее смещение строк
таблицы, в том числе за открытой карточкой. Полные карточки осмотрены до обновления
связанных Windows-эталонов; композиционные эталоны не обновляются.

## Соответствие UI Kit и границы

Названия и базовая геометрия принадлежат общему именованному варианту, а не CSS
страниц. Ширина колонок и предметные сведения остаются у потребителей.
Обновлены каталог UI Kit и профильные документы метрик, рабочих задач, проектов.

Открыто: работа с реальной сессией и БД, роли/права, реальные сохранения,
нативный zoom 200%, touch и специальные режимы доступности. Вторичные поверхности
проверены в пределах существующей fixture-регрессии, а не полного live-протокола.
Прохождение тестов не означает приёмку всех UX/UI-состояний системы.
