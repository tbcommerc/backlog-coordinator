# UI kit: исправления и повторное ревью 17.10.2026

Объект: текущее рабочее дерево `dmb-backlog/frontend`, общий UI kit и его
потребители. Источник истины — исполняемые компоненты, CSS и проверки.
Предшествующее ревью выявило три дефекта контрактов, смешение ядра со стилями
страниц и недостаточную полноту проверки вычисленных стилей.

## Исправления

| Находка | Решение | Проверка |
|---|---|---|
| Ошибка поля уничтожает связь с подсказкой | Собственное состояние ошибки, добавление ID к описаниям, адресная очистка и восстановление исходного invalid | `uiKitReview`: повторный показ, очистка без ошибки, дополнительное описание, смешанные импорты |
| Уведомление исчезает при взаимодействии | Действие по умолчанию не имеет таймера; hover/focus приостанавливают явный таймер; поддержан ноль и возврат фокуса | `uiKitReview`: управляемые часы, наведение, фокус, уход, действие и закрытие |
| Выбрана отключённая вкладка | Нормализация выбора по доступным пунктам; отключённый tab не выбирается | unit `uiKit`, browser `uiKitReview` и изолированный пример |
| Общий CSS зависит от страниц | Отделены `core.css` и `adapters.css`; добавлены `foundations.css` и рабочий пример без старых стилей | `uiCoreBoundary`, `uiKitCore`; регрессия потребителей |
| Проверка пропускает selected и геометрию | Состояния копируются в общий эталон; измеряются поля, квадратность, отступы/высота заголовков и видимая сортировка | `uiKitConsistency`, `uiKitSizing`, `uiKitBacklog` |
| Рассинхронизация документации и тестов | Охват исправлен на 111, категория встреч проверяется по отрендеренным данным, контракт роутера допускает дополнительные guards | полный unit-прогон |

Дополнительно устранены обнаруженные строгими проверками обходы: собственный
минимум полей админки, частная геометрия кнопки V1, разные line-height
однострочных контролов и ссылка на неопределённый токен `--bg-input`.
Цвет границы ошибки сохраняется и при фокусе.

## Архитектурное решение

`kit.css` остаётся входом SPA: сначала ядро, затем адаптеры. В ядре нет ID
старых диалогов и правил предметных страниц. Совместимые названия `.btn`,
`.input`, `.badge` сохраняются. В адаптерах остаётся мост к специфичности старых
task-dialog; тест проверяет соответствие дублируемых правил размеров общему
источнику. Полное удаление старого CSS или создание отдельного npm-пакета не
заявляется.

[Изолированный пример](../../dmb-backlog/frontend/ui-catalog/core.html)
использует только шрифты, токены и ядро. Он объединяет форму с длинным текстом,
вкладки, выбранное действие, disabled/busy, ошибку и таблицу. На мобильном
горизонтальная прокрутка таблицы остаётся внутри её контейнера.

## Проверки

Из `dmb-backlog/`:

```powershell
npm run test:unit
npx playwright test 'uiKit|adminTableKit' --workers=2 --reporter=line
```

Финальный полный unit-набор: **387 PASS, 0 FAIL**.
Адресный прогон исправленных контрактов и размеров: **15 PASS**.
Каталог и четыре новых визуальных эталона изолированного примера сохранены
после изменения структуры CSS и добавления ссылки на пример. Эталоны
просматриваются вручную; финальная регрессия выполняется без их обновления.
Широкий браузерный прогон: **305 сценариев, 296 PASS / 9 FAIL**.
Заключительный адресный прогон после исправлений: **54 PASS / 0 FAIL**,
включая все девять исходных падений и два новых сценария системных настроек
доступности. Из этих 54 проверок 52 входят в широкий набор, две добавлены
после его запуска. Все 307 различных сценариев UI kit имеют успешный результат
с учётом повторов; утверждение об одном непрерывном прогоне 307/307 не делается.

Команда заключительного прогона:

```powershell
npx playwright test uiKit.spec.mjs uiKitCore.spec.mjs uiKitReview.spec.mjs uiKitSizing.spec.mjs uiKitConsistency.spec.mjs uiKitBacklog.spec.mjs uiKitAdminEditors.spec.mjs --workers=2 --reporter=line
```

Повторно проверены неизменность визуальных эталонов, selected/disabled/busy,
поля с ошибкой в фокусе, forced colors, reduced motion и compact с coarse pointer.
Все четыре эталона рабочего примера просмотрены вручную. Цвет невидимой
границы textarea не сравнивается; существующие видимые границы и геометрия
однострочных полей продолжают проверяться.

После фиксации последнего подключения kit в `index.html` дополнительно
выполнены `uiKitBacklog`, `accountSecurity`, `workTasks`: **13 PASS / 0 FAIL**.
Это подтверждает бэклог и заголовки реального SPA, формы безопасности и рабочие
задачи после изменения порядка CSS; запросы остаются на подменном API.

Промежуточные FAIL не скрываются: расширенные проверки выявляли расхождения
line-height и размеров; сравнение ресурсной таблицы сначала не учитывало её
общий вариант; тест рабочего отчёта использовал старый маршрут без `meeting_id`,
который теперь перенаправляет в сводку. Исправления относятся соответственно
к CSS, эталонному варианту и тестовому адресу, без ослабления сравнения заголовков.
Один тест административного редактора первоначально не загрузил динамический
модуль фикстуры; заключительный прогон всего файла прошёл без повторения сбоя.

## Границы подтверждения

- Chromium, светлая/тёмная темы, desktop/mobile, плотность и coarse pointer;
  адресные сценарии проверяют клавиатуру, ожидание, ошибки, закрытие и черновики.
- Вычисленные стили сравниваются на 22 поверхностях. Это не полный визуальный
  перебор всех сочетаний данных и состояний 111 поверхностей.
- API подменяется фикстурами в памяти браузера. Запросы в рабочую БД, вход
  тестовыми учётками, изменение защищённых данных и вызовы модели не выполнялись.
- Проверка прав backend, приёмка Safari/Firefox и ручная проверка скринридером
  не входят в подтверждённый результат этой работы.

## Повторное заключение

Подтверждённые дефекты контрактов устранены и защищены воспроизводимыми
регрессиями. Ядро может отображать базовый рабочий сценарий независимо от
старых стилей SPA; совместимость существующих страниц имеет явную границу.
Статус приёмки: **PASS в проверенном объёме**. Незакрытых подтверждённых
дефектов исходного ревью в этом объёме не осталось. Новых блокирующих дефектов
повторная проверка не выявила.

Дальнейшие изменения должны сохранять границу ядра, иметь пример состояния
в каталоге и проверку реального потребителя. Сохраняющийся адаптер legacy
считается описанной границей архитектуры, а не подтверждением полного удаления
исторического CSS.
