# Улучшения страниц ревью запросов по аудиту R01–R34

> Статус: реализовано и проверено по коду 08.09.2026. Исходный аудит остаётся историческим evidence-срезом; текущее поведение описывают профильные документы `dmb-backlog/docs/`.

## Что изменено

| Пункты аудита | Реализация |
|---|---|
| R01–R08 | Исправлен цикл возврата и повторной отправки; добавлены неизменяемые снимки редакций, история решений, diff, единый набор findings со статусом/важностью и стабильными targets; legacy-текст и полное содержимое переносятся в задачу со ссылкой на принятую редакцию; решение защищено проверкой прочитанной версии; отсутствующие оценки не превращаются в 0%. |
| R09–R18 | Очередь включает активные и закрытые стадии, поддерживает ID-поиск, независимые режим/стадию/сигналы, честный возраст этапа и явные сортировки. Статус связанной задачи разрешается одинаково в list/detail. Ревью можно освободить или перенаправить с причиной; автор получает обязательное inbox-уведомление о решении. Состояние фильтров живёт в URL, поиск имеет debounce, серверная выдача догружается через `limit/offset`. |
| R19–R25 | Исправлена мобильная геометрия предупреждения; причины и рабочая заметка сохраняются по request/action/version; форма имеет единый submit-lock, окна передачи — pending guard, загрузка различает stale/error. Router отбрасывает поздний результат предыдущего маршрута. Return/reject имеют разные последствия и формулировки. |
| R26–R34 | На mobile паспорт идёт до решения; длинное содержание читается в одну колонку с сохранением абзацев. Оглавление включает значимые и проблемные секции, источники раскрывают контекст. Введены контрастные semantic text/fill цвета, исправлены accessible names и порядок focus/DOM, заменены неподдерживаемые иконки. Терминология статусов и дат унифицирована, финальные состояния имеют собственный next step, карточка очереди стала компактнее и больше не является одной длинной ссылкой. |

## Принятые границы

- Отдельный SLA ревью не придуман: `review_deadline` используется только когда он явно задан, иначе показывается возраст текущего этапа. Это закрывает вводящую в заблуждение «просрочку», не создавая новое бизнес-правило.
- Передача ревью реализована безопасными операциями «освободить» и «перенаправить в команду». Прямое назначение произвольного ревьюера не добавлялось, поскольку оно требует отдельной ролевой модели.
- Пагинация ограничивает объём одного ответа и DOM. Перенос всех фильтров на сервер остаётся возможной оптимизацией после измерения реальной нагрузки, но не нужен для корректности текущего контракта.

## Проверки

- `npm run test:unit` — frontend unit/contract regression.
- `python -B backend/tests/test_requirement_artifact_integrity.py` — изолированный набор сохранности request/revision/status без БД.
- `frontend/e2e/reviewResponsive.spec.mjs` — Chromium, mobile/desktop, формы, stale-version и фактическая геометрия.
- `node --check` для изменённых JS и `git diff --check`.

Полные pytest-наборы, создающие тестовые роли, пользователей и команды, не запускаются без отдельного разрешения согласно правилам защищённых данных проекта.
