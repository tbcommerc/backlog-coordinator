# Внедрение предложенного дизайна карточки задачи

Дата проверки: 11.11.2026. Статус: композиция повторно реализована по референсам; результаты функциональной, визуальной и live-проверки учитываются отдельно.

Исходное внедрение от 09.11 не прошло визуальную приёмку пользователя. Текущий результат сверяется с исполняемым прототипом, а не с отменённой реализацией.
[Галерея сравнения](../../artifacts/task-card-implementation-2026-11-11/index.html).

## Реализованный интерфейс

- Оболочка 1160 × 790 px на desktop, полноэкранная на мобильном; единый заголовок, компактная полоса вкладок, постоянная нижняя панель.
- Основное: пять полей рабочей сводки, описание, внутренний комментарий, участники, раскрываемые атрибуты и оценки.
- Редактор: название, статус/исполнитель/срок, приоритет/прогресс/команда, описание и комментарий. Дополнительные предметные поля доступны ниже.
- Отчётные статусы: самостоятельные компактные блоки встреч, предыдущий и текущий текст, отдельное сохранение.
- Комментарии: обсуждение с ответами, корректный общий счётчик, форма ввода и сохранение черновика при смене вкладки.
- Ссылки и файлы: материалы, список файлов перед загрузкой, отдельное редактирование ссылок и раскрываемая системная информация.
- История: хронология с автором и переходом старого значения в новое.
- Рабочие задачи: список, поиск и статус, создание/привязка, зависимости и внешнее исполнение.
- В самостоятельных вкладках footer закрывает карточку; предметные действия расположены рядом с содержимым.

Именованные варианты UI Kit: `ui-task-dialog`, `ui-task-detail-composition`, `ui-task-secondary` и вариант `task-detail` для встроенного списка работ. Старые общие правила контролов, badges и сгенерированные адаптеры исключены из новой оболочки; специфичность страницы не повышалась.

## Осознанные отличия от демонстрационного прототипа

Минимальный шрифт действующего UI Kit — 12 px. В прототипе относительные размеры при корневом шрифте 14 px давали 11.375 px, поэтому они нормализованы до 12 px. Цвета и веса текста сверяются отдельно. Демонстрационная верхняя полоса не переносится в продукт: она объясняет разницу вертикального положения оболочки на парных снимках.

Срок остаётся выбором из реального справочника, а не произвольным календарём; права, дополнительные бизнес-поля, счётчики и реальные ссылки сохранены. Участники на мобильном остаются в трёх колонках, как в исполняемом исходном прототипе. Полная пиксельная идентичность всех состояний не заявляется.

## Функциональная проверка

Подтверждены отдельными тестами: явное сохранение, busy/error/retry, сохранность ввода при конфликте, безопасный undo по версии, различие ошибки/пустоты/устаревших данных, защита от позднего ответа, независимые отчётные черновики, доступность переключателей, нулевые/неизвестные числовые значения.

Прогресс теперь принимает целые 0–100 без округления к пяти. Backend истории сохраняет ноль как `"0"`, а не `null`; отдельная регрессия исполняет production update loop для 0→47, 47→0, null→0, 0→null без БД. Ранее потерянные нулевые значения в истории не реконструируются.

## Проверка живого приложения

Во встроенном браузере выполнен вход под готовым профилем BA/Участник команды и открыта синтетическая TASK-000-327:

- Все шесть вкладок загружаются; просмотрены полный экран и мобильная компоновка.
- Прогресс 47 сохранился точно, затем восстановлен 0. После исправления backend отдельно подтверждены записи 0→1 и 1→0; исходное значение восстановлено.
- Пустое название блокирует сохранение, объяснение показано у поля; отказ от черновика возвращает сохранённую карточку.
- Дополнительные атрибуты раскрываются; черновик комментария переживает смену вкладки и очищен без публикации.
- Связанная WRK-111 открывается поверх карточки; Escape закрывает только её и оставляет родительскую карточку.
- Защищённые пользовательские данные, справочники и команды не редактировались; опубликованных комментариев и уведомлений тест не создавал.

[Снимки live-проверки](../../artifacts/task-card-live-2026-11-11/).
Встроенный браузер при запрошенных 390 px сообщает CSS-ширину 433 px из-за масштаба хоста; точные 320/390/1440 проверяются отдельно в Windows Chromium, не подменяются live-снимками.

## Границы приёмки

Реальные публикации/упоминания, необратимое удаление вложений и расчёт выключенным Task Prioritiser не выполнялись. Ошибки сети, конкуренция, права и редкие состояния проверяются на изолированных данных; это не live-проверка каждой роли.

Полный цикл всех 80 демонстрационных кадров, всех ролевых путей, экранного диктора и масштаба 200% не объявляется завершённым автоматически. Открытые границы TC-18/J16/J18 сохраняются; зелёные функциональные тесты не заменяют визуальную приёмку.

На минимальной ширине 320 px подпись footer редактора может переноситься внутри слова; пересечение с кнопками устранено и проверено. Это остаётся небольшим визуальным замечанием.

Проект запущен штатным скриптом, health-check успешен: приложение http://127.0.0.1:8000, backend API http://127.0.0.1:8000/docs, Business Analyst API http://127.0.0.1:9000/docs, экспериментальный API http://127.0.0.1:9300/docs. Логи — `.runtime/`. Task Prioritiser не запускался. После перезапуска Redis выполнена штатная сверка координатора; ограничения не отключались.
