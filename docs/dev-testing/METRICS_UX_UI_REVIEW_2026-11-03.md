# UX/UI и дизайн-ревью метрик — 03.11.2026

## Исправления и повторная проверка — 04.11.2026

**Вывод R4 о закрытии всех 29 замечаний отозван в части дизайна и визуальной приёмки.** Скриншот пользователя показал, что технические проверки не подтвердили качество композиции, внешнего вида и соответствие UI Kit. Числовой бюджет высоты и отсутствие overflow не являются визуальной приёмкой. Ниже сохранены исторические результаты функциональной регрессии R4; актуальные изменения дизайна и доказательства вынесены в [повторное визуальное ревью R5](METRICS_VISUAL_REVIEW_2026-11-04.md).

Итог: **66/66** тестов общего UI-набора (`npx playwright test --config playwright.metrics.config.mjs --workers=1 --timeout=90000`), затем **4/4** целевых теста M22/M28 после расширения проверок: 403/404/503 и подтверждённое сохранение 101 поверх версии с 102. Это 69 разных UI-сценариев, один сценарий конфликта повторён и расширен. Backend: **17 passed**, 18 deselected — расчёты и отобранные изолированные проверки, не полный backend suite. Живой API подтвердил четыре соответствия годового итога/плана и цикл добавления/удаления файла и связи. Синтаксис изменённых JS и `git diff --check` прошли; 222 локальные Markdown-ссылки проверены, отсутствующих нет. Финальный статус backend и включённых зависимостей — `ready`/healthy.

Промежуточные сбои не скрыты: после уплотнения фильтров обнаружено и исправлено переполнение при 320 px; до финального прогона тяжёлые сценарии старых форм превышали общий бюджет 30 секунд на сохранении скриншотов. Финальный прогон с одним исполнителем и бюджетом 90 секунд прошёл полностью за 4,2 минуты; проверки поведения и assertions не ослаблялись. Исходный дефект кнопки при CSS zoom устранён изменением размеров диалога относительно содержащего окна.

Стенд восстановлен штатным запуском: PostgreSQL, Redis, миграции, backend и штатные агенты прошли health-check; Task Prioritiser не включался. Конфликт профилей ранее запущенных процессов устранён штатной остановкой принадлежащих проекту сервисов и повторным запуском. Seed не запускался.

## Исходный вывод аудита R1–R3 (до исправлений)

Новая квартальная модель поддерживает содержательные бизнес-сценарии, но её интерфейс пока требует доработки перед UX-приёмкой. Основные проблемы — смысловая точность реестра, сохранение контекста, избыточная высота экранов, труднодоступное переключение кварталов и техническое представление истории. Квартальная карточка визуально и по навигации заметно уступает уже существующей карточке прежней модели.

Зарегистрировано **29 замечаний: 5 P1, 22 P2, 2 P3**. Это сочетание дефектов и дизайнерских рекомендаций, а не 29 подтверждённых программных ошибок. В R2 подтверждены M03, M20, M23 и добавлены M27–M28; в R3 расширены доказательства и добавлен M29. Исправления в приложение в рамках аудита не вносились; добавлен только изолированный тестовый стенд.

Проведены живой обзор реестра, двух моделей карточки и форм, создание отдельных QA-метрик, сохранения, исправления и конкурентный конфликт. В R3 стенд восстановлен, завершены живые сохранения оставшихся форм, проверены все четыре типа, заполненные материалы, многостраничные списки и меню семи дополнительных профилей. Блок подготовки QA-записей снят прямым разрешением пользователя. **Полная приёмка всех состояний не заявляется**: настоящий транспортный таймаут, контролируемое истечение сессии и специальные проверки доступности не выполнены. ## Что работает хорошо

1. Явное различие плана, факта, замеров и итогового подтверждения заложено в интерфейс. Закрытый квартал с фактом 80 при плане 100 честно показывает недостижение цели.
2. Пропущенные квартальные факты не превращаются в нули. Есть отдельные подтверждённое значение, предварительная оценка и итог года.
3. Поиск по Enter и автоматическое применение поиска, сохранение текста/фокуса, сброс дальней страницы при поиске работают. После поиска DEV-QA со страницы 2 получены две строки и страница 1.
4. Множественный фильтр команд работает: QA Team A + QA Team B сохраняются в URL и дают ожидаемую QA-выборку. В выпадающем фильтре есть поиск.
5. Колонки «Владелец» и «Состояние» настраиваются; выбранная видимость отражается в URL.
6. Вложенная форма предупреждает о потере ввода. Изменение 80 → 81, отмена и подтверждение выхода не изменили отображаемый итог; фокус вернулся к действию карточки.
7. Escape закрывает квартальную карточку. У модального диалога есть имя, role=dialog и aria-modal; у основных контролов есть доступные названия.
8. У ba-b скрыты действия изменения чужой метрики. customer-a перенаправляется в портал; no-access не получает содержимое метрики.
9. На проверенных ширинах отсутствовал общий горизонтальный вынос страницы. Таблицы используют внутреннюю прокрутку; основные мобильные кнопки имеют высоту около 44 px.
10. Проверенные непрозрачные текстовые сочетания достаточны по контрасту. В светлой теме вторичный текст на белом — около 7,58:1, в тёмной — 6,62:1; белый текст основной кнопки — 6,29:1. Это выборочная проверка, не сертификат доступности.

## Реестр замечаний

Приоритеты: P1 — существенное искажение смысла или препятствие основному сценарию; P2 — заметное ухудшение работы; P3 — локальное улучшение. Live — воспроизведено на стенде; Code — вывод из текущей реализации, без живого контрпримера; Design — экспертная рекомендация по наблюдаемому интерфейсу.

### M01 · P1 · Фильтры вытесняют сами метрики

**Live + Design.** Открыть реестр при 1440×900 и 390 px. На desktop таблица начинается около y=572; на телефоне фильтры растягиваются более чем на 1000 px. Обычная задача «посмотреть результат» начинается с прокрутки большого набора настроек. Год, квартал, представление, команды, владельцы, проекты, два состояния, область, сортировка и архив имеют почти одинаковый вес.

**Решение:** в первой строке оставить поиск, период и переключение «Квартал / Год». Основные отборы показать компактно; дополнительные — в «Фильтры (N)». На телефоне использовать отдельную панель фильтров с явным применением и активными условиями над результатами. Сортировку и колонки разместить у таблицы.

**Приёмка:** при 1440×900 первая строка результатов видна ориентировочно до y=350; при 390×844 на первом экране виден хотя бы первый результат. Это целевые продуктовые бюджеты, не норматив WCAG. Доказательства: 01, 08, 09; registry(), qmetric-filters.

### M02 · P2 · Равные ширины колонок ухудшают чтение названий

**Live + Design.** При 1440 px все шесть колонок ≈185,5 px. Названия разбиваются на 3–4 строки, в числовых колонках остаётся свободное место. Это увеличивает высоту строк и затрудняет сравнение.

**Решение:** задать предметные ширины: название примерно 28–32%, числа компактнее, статус и владелец по содержимому. Числа выровнять единообразно, желательно по правому краю; применять табличные цифры. Сохранять полный текст без обязательного hover.

**Приёмка:** контрольный русский заголовок около 50–60 знаков обычно занимает не более двух строк на desktop; длинные значения не перекрывают соседние ячейки. Доказательство: 01; data-table.css: table-layout:fixed.

### M03 · P1 · Реестр теряет смысл диапазонного плана

**Live R2 + Code.** На созданной MET-10470 сводка показывает диапазон 90–110, а таблица «Планы и периоды» — только 90. Квартальный реестр также выводит только period.plan.target; upper не выводится. Для порога по коду отсутствует знак направления, хотя он определяет смысл цели; живое создание пороговой записи заблокировано. Доказательство диапазона: 35, 37, 38.

**Решение:** общий форматтер цели: «90–110 %», «≤ 100 мс», «≥ 100 шт», для изменения — база и целевое значение по контексту. Использовать одинаковый формат в реестре, карточке, годовых ячейках и редакторе.

**Приёмка:** четыре типа результата и оба направления сравнить на одних данных; диапазон и знак не теряются ни на одной ширине. Источник: metricsQuarterly.js:81–86, 97, 99.

### M04 · P1 · Старые данные выглядят отсутствующими

**Live + Code.** MET-071 в квартальном реестре показывает «План —», «Нет факта», «Не запланирован». При открытии прежней карточки у неё есть активный период Q4 2026, цель 100% и значение 100% от 27.10.2026. Отдельная подпись «Прежняя модель» не объясняет, что данные существуют и требуют другого представления. Это не утверждение о потере данных в БД — проблема их интерпретации.

**Решение:** показывать явное состояние «Данные прежней модели — открыть» либо отдельный раздел совместимости. Не представлять ненормализованные данные как отсутствие факта и плана. Не смешивать старый факт с новой методикой без согласованной миграции.

**Приёмка:** пользователь отличает «не внесён факт» от «есть прежние данные» непосредственно в строке. Доказательства: 01 и 15; wrapper в metrics.js и registry() v2.

### M05 · P1 · Из старой карточки теряется исходная выборка

**Live + Code.** Из годового реестра 2025 года открыть MET-071, перейти в «История» и закрыть карточку. Получен маршрут /metrics, затем нормализация на Q4 2026; исходные год и представление потеряны. Вкладки старой карточки формируют ссылки только с period_id/section, а возврат использует отдельное старое sessionStorage-состояние, которое новый реестр не поддерживает.

**Решение:** единый сохранённый маршрут возврата для обеих моделей; отдельно хранить контекст списка и состояние карточки. Фон карточки должен показывать исходный реестр, а не пустую старую оболочку с «Найдено: 0».

**Приёмка:** поиск + две команды + годовой режим + страница 2 → старая карточка → все вкладки → Escape/крестик/Back: исходная выборка и позиция восстановлены. Доказательства: 15, живые URL в протоколе; metrics.js:lastList(), modalCard(), closeCard(), ссылки вкладок.

### M06 · P2 · В годовом реестре нет годового результата

**Live + Design.** В представлении «За год» видны четыре квартала, но нет колонки итога, полноты охвата и правила агрегации. Для сравнения результатов года необходимо открывать метрики по одной.

**Решение:** добавить компактную годовую сводку: итог/предварительная оценка, полнота кварталов и правило расчёта. Для «Не рассчитывается» — понятное объяснение вместо пустого числа. Не суммировать несовместимые единицы между метриками.

**Приёмка:** по строке можно понять результат года и его полноту без открытия карточки. Доказательство: 12; registry() annual columns. Это предложение развития представления, а не заявление о нарушении серверных расчётов.

### M07 · P2 · Новая карточка и редакторы прижаты к левому верхнему углу

**Live + Code.** При 1440×900 карточка имеет x=0, y=0 и margin=0, ширину около 1100. Большая свободная затемнённая область остаётся справа. Редактор миграции аналогично занимает верхний левый угол поверх центрированной старой карточки.

**Решение:** выбрать единый контракт: центрированное окно с отступами на desktop либо явно оформленная боковая панель. Для модального варианта задать margin:auto, ограничения по высоте и устойчивое размещение вложенных форм. На телефоне сохранить fullscreen.

**Приёмка:** диалоги центрированы или согласованно привязаны к выбранной стороне на 768/1440 px, клавиши закрытия и заголовок доступны на коротком экране. Причина: reset margin:0 и отсутствие компенсирующего margin у DetailPanel. Доказательства: 05, 22, 24.

### M08 · P2 · Выбор квартала спрятан глубоко в карточке

**Live + Design.** Чтобы сменить квартал, нужно дойти до таблицы «Планы и периоды» ниже двух графиков и нажать одну из одинаковых кнопок «Выбрать». Выбранная строка не отмечена явно. На вкладках обсуждения и истории отдельного постоянно видимого переключателя периода нет; год меняется через возврат в реестр.

**Решение:** год и I–IV кварталы разместить в верхней части карточки, показать выбранный квартал, его состояние и наличие плана. Текущий период сохранять видимым во всех вкладках. Годовой обзор сделать отдельным режимом этого же переключателя.

**Приёмка:** переход между кварталами доступен без прокрутки, с клавиатуры и на 320 px; выбранное состояние обозначено текстом и программно. Доказательства: 05, 07; card():periods/tabs.

### M09 · P2 · Карточка показывает слишком много вторичных разделов до замеров

**Live + Design.** В заполненной карточке таблица замеров начинается около y=1780, на 390 px — ещё ниже. Даже при отсутствии фактов остаются годовой график, годовые значения, таблица периодов и пустые замеры. Границы однотипных секций примыкают друг к другу, почти не помогая различать уровни информации.

**Решение:** верх — краткая сводка выбранного периода; затем его график и последние замеры. Первоначальный план, редакции закрытия, годовой анализ и паспорт перенести в раскрываемые разделы или отдельный годовой режим. В состоянии без плана показать короткий сценарий следующего шага.

**Приёмка:** на desktop последние замеры либо явный переход к ним видны в первом экране/следующем коротком блоке; пустые второстепенные панели не занимают несколько экранов. Доказательства: 02, 05, 07.

### M10 · P1 · Подписи графиков на телефоне фактически нечитаемы

**Live + Code.** SVG с viewBox 600×210 сжимается вместе с текстом. При 320 CSS px высота подписей около 5,93 px; на 390 px также получается слишком мелкий текст. Дополнительная высота SVG оставляет много пустоты, но не увеличивает подписи.

**Решение:** адаптивная геометрия графика с постоянным размером текста; меньше меток на узкой ширине, отдельные HTML-подписи либо специально рассчитанный viewBox. Если график нельзя сделать читаемым, показывать компактную сводку с доступом к таблице.

**Приёмка:** подписи визуально читаются без увеличения на 320/390 px; целевой размер 12–14 CSS px, проверяемый по фактическому рендеру. Доказательства: 07, 21; observationChart(), yearChart(). Это дизайнерский критерий читаемости, не выдуманный минимальный шрифт WCAG.

### M11 · P2 · Графикам не хватает масштаба и явных значений

**Live + Code + Design.** В квартальном графике есть линия плана и точки, но нет шкалы значений и единицы у оси; в годовом — названия кварталов без числовой шкалы. На совпавшей дате факт-квадрат закрывает замер-круг. Точные значения доступны через SVG title/таблицу, однако таблица далеко, а title неудобен для клавиатуры и touch.

**Решение:** компактная ось Y с единицей, понятные отметки факта, доступная легенда, явная обработка совпадения точек. Tooltip должен открываться с клавиатуры/touch либо все существенные числа должны быть доступны рядом.

**Приёмка:** график можно интерпретировать без угадывания расстояний; совпадающие замер и факт различимы; отрицательные, нулевые и близкие значения проверены отдельно. Доказательства: 05, 07; функции графиков.

### M12 · P2 · Сводке не хватает предметного контекста и визуальной иерархии

**Live + Code + Design.** В новой карточке единица указана один раз в метастроке, план показан просто числом, тип результата и методика спрятаны в паспорте. Закрытый квартал и жизненный цикл метрики не представлены как два отчётливо разных состояния рядом с периодом. Текст результата имеет примерно тот же визуальный вес, что административные секции.

**Решение:** возле значений показывать единицы и направление цели; отдельно обозначить состояние квартала и состояние метрики. Использовать компактные смысловые статусы с текстом, а не полагаться только на цвет. Для изменения от базы дать короткую формулу/пояснение рядом с результатом.

**Приёмка:** без раскрытия паспорта понятно, что измеряется, за какой период, как трактовать успех и является ли факт итоговым. Доказательства: 05, 15, 27.

### M13 · P2 · История и подтверждения показывают внутренние структуры

**Live + Code.** История выводит period_closed, fact_updated, Автор 25, timestamp с микросекундами и +00:00. Раскрытие показывает JSON before/after. Подтверждение итога содержит not_achieved. Фильтр «Тип события» — свободное поле, требующее знания внутреннего кода.

**Решение:** русские названия действий, имя автора, локальные дата/время, период и смысловой diff «Факт: 70 → 80». Фильтр — список доступных типов событий. Технический JSON оставить как вторичную диагностическую возможность, если он нужен.

**Приёмка:** бизнес-пользователь понимает изменение без знания API; часовой пояс обозначен однозначно, старое и новое значения сопоставлены. Доказательства: 03, 14; historyBody, closures, discussionView.

### M14 · P2 · Создание метрики слишком длинное и слабо объясняет модель

**Live + Design.** Форма начинается с десяти разнородных полей и затем показывает все четыре квартала, в том числе выключенные. Название занимает одну ячейку, а почти пустой квартал — всю ширину. «Объём / Изменение от базы / Порог / Диапазон» и правила года не сопровождаются примерами. «Действие» и «Сохранить» находятся внизу длинной формы.

**Решение:** сгруппировать «Что измеряем», «Как оцениваем», «Планы». Начать с выбранного квартала, остальные добавлять по необходимости. У типов дать короткие предметные примеры. Закрепить нижнюю панель с понятными действиями «Создать и начать» / «Сохранить черновик».

**Приёмка:** минимальную метрику можно заполнить без просмотра неактуальных кварталов; длинное название не редактируется в узком поле; главное действие всегда доступно. Доказательство: 10; openForm('create').

### M15 · P2 · Разрешённый контрол молча отменяет выбранное направление

**Live + Code.** В создании при типе «Объём» выбрать «Снижение». После change значение немедленно становится «Рост», без пояснения. updatePlanForm принудительно устанавливает up; для диапазона аналогично задаётся range, но select продолжает выглядеть свободно редактируемым.

**Решение:** для фиксированного направления показать неизменяемое значение с объяснением; редактируемый select оставить только для типов, где выбор применим.

**Приёмка:** доступное действие не отменяется молча. Доказательство: [наблюдение](evidence/metrics-review-2026-11-03/captures/form-direction-observation.json); updatePlanForm():147.

### M16 · P2 · Обязательность и ошибки формы раскрываются слишком поздно

**Live + Code.** Источник и единица визуально ничем не выделены и не имеют required в форме создания, хотя нужны для начала ведения. Неполный ввод возвращает общий текст «Утвердите хотя бы один план» внизу; рядом с кварталами нет адресной ошибки и понятного перехода. Ошибки отмечают aria-invalid только при наличии fields от сервера.

**Решение:** обозначить обязательные поля для выбранного действия, выполнить согласованную предварительную проверку, вывести summary со ссылками на поля и текст рядом с ошибочным кварталом. Черновик должен иметь отдельные правила. Снимать ошибку после исправления.

**Приёмка:** title-only, отсутствие источника/единицы/цели, неверные границы и даты дают адресные понятные сообщения без потери ввода. Доказательство: 11; openForm/create, save/catch, серверная проверка incomplete_passport.

### M17 · P2 · Формы не скрывают неприменимые поля и неточно обозначают область действия

**Live + Code.** В «Область и правило года» при правиле «Сумма» виден «Масштаб отношения». Показаны четыре причины исключения, в том числе для уже существующих планов. Шапка годовой формы и редактора нескольких планов сообщает «1 квартал 2025». В новом факте/закрытии выводится «Причина исправления», а подтверждение ранней даты показано даже при дате конца квартала.

**Решение:** динамически показывать только применимые поля и называть реальную область: «Планы 2025 года», «Настройки 2025 года», «Итог II квартала». Подтверждение ранней даты запрашивать при соответствующем выборе. У паузы объяснить влияние на расписание, не скрывать его за общей кнопкой «Сохранить».

**Приёмка:** каждая форма содержит только применимые контролы, а её заголовок и подпись совпадают с изменяемой областью. Доказательства: 06, 25, 26, 32, 33; openForm().

### M18 · P2 · Статус встречи может по умолчанию попасть не в ту встречу

**Live + Code.** В форме «Статус встречи» первый и автоматически выбранный вариант — directorate · 2027-02-01, хотя дата ревью 03.11.2026. В списке есть ближайшая встреча 09.11.2026. Типы did/directorate/team_weekly показаны без перевода.

**Решение:** пустой обязательный выбор либо ближайшая подходящая встреча с явным пояснением; сортировка по близости/дате и русские названия типов. Выбранную дату повторить в подтверждении.

**Приёмка:** пользователь не может незаметно сохранить статус в случайно выбранную далёкую встречу; выбор очевиден до отправки. Доказательство: 31; openForm('report').

### M19 · P2 · Для прошедшего квартала скрыт альтернативный путь обновления предварительного факта

**Live частично + Code.** Если capability.close=true, primary выбирает «Зафиксировать итог» раньше write_fact. На II квартале 2025 доступно закрытие и добавление замера, но отдельной кнопки «Внести/обновить предварительный факт» в карточке нет. Такой путь остаётся через ячейку реестра с action=fact или «Использовать как факт» у существующего замера.

**Решение:** оставить закрытие основным действием, но показывать «Обновить предварительный факт» как вторичное, если сервер разрешает. Не заставлять пользователя возвращаться в реестр или создавать замер ради доступной операции.

**Приёмка:** владелец и редактор выполняют разрешённые операции с фактом непосредственно из карточки; подтверждение итога остаётся отдельным осмысленным шагом. Источник: primary в card():95, ссылка факта registry():84.

### M20 · P3 · Пагинация замеров и истории не сообщает положение и допускает пустые переходы

**Дополнение R2:** при ровно 25 реальных замерах «Следующие» открывает пустой список «Замеров нет»; это воспроизведено через UI, а не только выведено из кода (39). После добавления 26-го API вернул страницы 25 + 1; визуальный повтор N=26 не завершён из-за инструмента.

**Live + Code.** «Предыдущие» у замеров и «Назад» у истории активны на первой странице. Номер страницы и общее количество не показаны. Результаты API total/page отбрасываются; наличие следующей страницы выводится из items.length>=25, поэтому ровно 25 записей допускают лишний пустой переход. Смена квартала не сбрасывает page_history/page_comments; фильтр обсуждения также сохраняет номер страницы.

**Решение:** хранить метаданные пагинации, показывать диапазон/номер, корректно выключать кнопки, сбрасывать зависимую страницу при смене области.

**Приёмка:** наборы 0/1/25/26 и переход со второй страницы на другой квартал не дают ложной пустоты. Доказательства: 02, 03, 05; renderQuarterlyMetrics(), historyBody, обработчики period/discussion_period.

### M21 · P2 · После закрытия карточки клавиатурный фокус теряется

**Live + Code.** После закрытия квартальной карточки кнопкой и Escape document.activeElement — BODY. Исходная ссылка строки не восстанавливается, поскольку реестр пересоздаётся, а привязанный focusOrigin уже отсоединён. Пользователю клавиатуры приходится искать прежнее место заново.

**Решение:** сохранять идентификатор строки/ссылки и восстанавливать фокус после завершения рендера списка; отдельно сохранять прокрутку. При исчезновении строки — фокус на логичную соседнюю строку или заголовок результатов.

**Приёмка:** открытие метрики со второй страницы → Escape возвращает фокус именно на её ссылку, без прыжка в начало документа. Отличать это от успешно работающего возврата из вложенной формы. Источник: initQuarterlyMetrics(), bindDetailPanel(); живые DOM-наблюдения.

### M22 · P2 · Недоступность не объясняет следующий шаг

**Live + Code.** Для no-access прямая ссылка показывает «Метрики недоступны / Метрика недоступна / Повторить». Повтор не меняет права. customer-a перенаправляется в «Мои запросы» без объяснения, почему метрика не открыта.

**Решение:** различать временный сбой, недостаток прав и отсутствующую запись. Не раскрывать чужие данные, но давать ясный выход: «Вернуться», «Открыть доступный раздел», при необходимости штатный способ запросить доступ. Retry оставлять для устранимого повтором сбоя.

**Приёмка:** 403/404/503 имеют разные пользовательские сценарии; прямые ссылки не заканчиваются бесконечным бесполезным повтором. Доказательства: 18, 19; catch renderQuarterlyMetrics(), маршрутизация customer.

### M23 · P2 · Загрузка карточки слишком сильно связана с вторичными разделами

**Fixture R2 + Code, success feedback проверен live.** При каждом рендере карточки загружаются options, detail, замеры, история, график, комментарии, файлы, связи, снимки и реестр на фоне. Значительная часть запросов последовательная; один общий catch заменяет всю поверхность ошибкой. Моделируемый 503 только для файлов действительно скрыл всю карточку («Метрики недоступны / QA: файлы недоступны»); «Повторить» восстановил экран. В живом сохранении нулевого факта карточка обновилась, но отдельного сообщения об успехе в status/alert не было. Доказательства: 35, 42.

**Решение:** загружать обязательную сводку отдельно, вторичные вкладки — по потребности; сохранять готовую часть при частичном сбое. Для каждого действия — busy, понятный результат и безопасный повтор. Не делать вывод о фактической медленности только из числа запросов: задержки нужно измерить отдельно.

**Приёмка:** отказ загрузки комментариев не скрывает план и факт; переключение вкладок не сбрасывает контекст; при 503/timeout/409 ввод сохраняется, пользователю понятно, что произошло. Источник: renderQuarterlyMetrics():46–70, refresh():239, save():233–236.

### M24 · P2 · У файлов и связей нет видимого пути исправления ошибочного добавления

**Code + Live пустые формы; заполнение подтверждено API R2.** discussionView даёт добавление/скачивание файлов и добавление/переход по связям, но не выводит действия удаления вложения или снятия связи, хотя API их поддерживает. В форме файла не указаны ограничения размера и допустимого содержимого. В R2 синтетический файл загружен и скачан с побайтовым совпадением, QA-связь создана, дубликат отклонён 409. Их заполненное визуальное представление и исправление через UI остались непроверенными из-за таймаутов браузерного инструмента. Необходимо отличать удаление связи от удаления самой задачи.

**Решение:** для разрешённых ролей добавить управляемое снятие связи/удаление вложения с ясным подтверждением; показать ограничения файла до выбора. Для просмотра — скрыть изменяющие действия.

**Приёмка:** тестовый файл и тестовую связь можно исправить штатно, не удаляя связанную задачу и не затрагивая защищённые данные. Источник: discussionView():109–115 и DELETE files/links в router; доказательства форм: 29, 30. Удаление в этом аудите не выполнялось.

### M25 · P2 · Предпросмотр миграции требует понимания внутренних правил

**Live + Design.** Форма показывает active, «Прежние ID», выбранный предлагаемый тип «Изменение», поле факта и дату ещё до выбора «Перевести квартал» / «Сохранить явно выбранный факт». Зависимость флажков и полей визуально не выражена. Плотная сетка перемешивает описание исходного периода, решение о переносе и новые данные.

**Решение:** отдельно показать «Что есть сейчас», «Что переносим», «Как будет оцениваться». Выключать поля переноса факта до явного выбора, переводить состояния и объяснять предложенный тип на конкретных числах. До финального подтверждения показывать итог изменения.

**Приёмка:** пользователь понимает, какие данные останутся прежними и что появится в квартальной модели, без чтения технического ТЗ. Доказательство: 24; metricsMigration.js. Сама миграция не выполнялась.

### M26 · P3 · Пустые и read-only состояния содержат лишние или противоречивые элементы

**Live + Code.** Без годовой области карточка показывает «Область ведения: кварталы» без чисел; рядом «Нет факта: нет», хотя фактов нет вообще. Пустые замеры сохраняют пагинацию. В read-only остаётся раскрываемый раздел «Действия с метрикой и периодом», даже когда внутри нет действий, и пустая колонка «Действия» у замеров.

**Решение:** отдельные короткие состояния «Год не настроен», «Квартал не входит в область ведения», «Факт ещё не внесён». Скрывать пустое меню и ненужную пагинацию, объяснять режим «Только просмотр».

**Приёмка:** состояния без плана, вне области, без факта, без замеров и только для чтения различаются; пустые технические контейнеры не отвлекают. Доказательства: 02, 17; card(), observations, annual coverage.

### M27 · P2 · Отключённый годовой расчёт назван отсутствием данных

**Live R2 + Code.** У MET-10470 выбран годовой итог «Не рассчитывается», оба квартала уже имеют факт (III — итоговый 105, IV — предварительный). Блок года при этом сообщает «Нет данных» и ниже «Нет факта: нет». Это создаёт ложное впечатление потери сохранённых данных. Серверное правило для aggregation=none возвращает completeness=empty, а UI не уточняет причину.

**Решение:** показывать «Годовой итог не рассчитывается по выбранному правилу», сохраняя отдельно полноту квартальных фактов. Для недостающих данных использовать другое состояние.

**Приёмка:** none, пустой год и неполный год с расчётом имеют разные тексты. Доказательства: 37–39; annual() в metric_quarterly_rules.py и годовой блок card().

### M28 · P2 · Разрешение конфликта требует чтения технического JSON

**Live R2 + Code.** Две вкладки открыли одну версию MET-10470; редактор B сохранил 102, редактор A отправил 101 и получил 409. Ввод A сохранился. «Сравнить с актуальной версией» вывело большую структуру периодов с внутренними ID, capabilities, revisions и датами вместо компактных различий. Пользователю предлагают «Использовать актуальную версию», не показывая ясно, какие именно его поля перезапишут чужое изменение.

**Решение:** сравнение «Ваш ввод / Сейчас сохранено» только для затронутых полей, автор/время изменения и явное действие «Сохранить мой вариант поверх актуального». Не называть замену номера версии с сохранением собственного ввода загрузкой актуальных значений.

**Приёмка:** при конфликте 101 ↔ 102 видны оба числа, дата/источник и последствия выбора; технические структуры спрятаны. После подтверждения запрос A действительно сохранён: заключительный API-снимок содержит 101 и причину «QA R2: редактор A». Доказательства: 44 и 45-live-conflict-comparison-json.txt, metrics-r2-final.json.

### M29 · P2 · Длинное обсуждение отодвигает материалы на несколько экранов

**Live R3.** Комментарий из 10 000 символов показан целиком без сворачивания. Высота одного article — около 1491 CSS px на desktop и 5315 CSS px при ширине 390. Файлы, связанные задачи и снимки встреч находятся ниже комментариев. Горизонтального переполнения не обнаружено (scrollWidth = clientWidth); проблема в доступности следующих разделов. Большая дробь с precision=10 дополнительно переносится посреди числа в сводке desktop/mobile: значение точное, но считывать его трудно.

**Решение:** ограничить первоначальную высоту комментария с доступным «Развернуть», дать быстрые переходы к материалам. Для длинных чисел предусмотреть компактное представление и доступ к точному значению без разрыва дроби.

**Приёмка:** комментарии 100/10 000 символов не скрывают путь к файлам и связям; разворачивание доступно с клавиатуры и сохраняет фокус. Точное число доступно и при узком экране. Доказательства: [desktop](evidence/metrics-review-2026-11-03/captures/r3/59-r3-discussion-long.png), [390 CSS px](evidence/metrics-review-2026-11-03/captures/r3/67-r3-longtext-mobile390.png), [число](evidence/metrics-review-2026-11-03/captures/r3/66-r3-precision10-mobile390.png).

## Целевая композиция — предложение, не внедрение

### Реестр

1. Заголовок «Метрики» и «Новая метрика».
2. Поиск, единый выбор периода «IV квартал 2026», переключатель «Квартал / Год».
3. Быстрые рабочие выборки: «Все», «Мои», «Требуют внимания» с понятными счётчиками; панель дополнительных фильтров.
4. Над таблицей: число результатов, активные условия, сортировка и колонки.
5. Квартальная строка: название/ID/единица, план с направлением или диапазоном, факт с датой и признаком подтверждения, результат, владелец, состояние периода.
6. Годовая строка: четыре компактных квартала плюс итог/полнота. Старые данные имеют явную отдельную трактовку.
7. Пагинация с диапазоном строк; sticky-заголовок длинной таблицы там, где он помогает сравнивать кварталы.

### Карточка

1. Название и ID; команда/владелец; понятные состояния метрики и выбранного квартала.
2. Постоянный переключатель года и квартала; главное действие по capability, доступные вторичные действия рядом.
3. Сводка: факт с датой и единицей, план с направлением, результат/отклонение. Для итогового факта — кто и когда подтвердил.
4. Вкладки «Показатели», «Обсуждение», «История» в одном оформлении для обеих моделей.
5. На «Показателях»: компактный читаемый график и последние замеры; полный список по раскрытию.
6. Годовой анализ, первоначальный план и редакции — вторичный уровень. Паспорт и правила расчёта доступны предсказуемо.
7. На мобильном — тот же порядок приоритетов, закреплённые заголовок/действие, компактные фильтры и удобные карточки замеров.

### Визуальный язык

Сохранить действующие токены и UI Kit. Основная работа — пропорции, интервалы, типографическая иерархия и согласованность компонентов. Не вводить отдельную визуальную систему для квартальных метрик. Статусы обозначать текстом и умеренным цветом; все данные в годовой ячейке не обязательно делать одинаково синими. Для дат использовать понятный русский формат, сохраняя точное значение программно.

## Нормативные ориентиры доступности

- Для обычного текста WCAG 2.2 AA требует контраст не ниже 4,5:1, для крупного — 3:1; inactive-контролы имеют исключение. [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- Проверка reflow ориентируется на 320 CSS px; для таблиц возможны обоснованные исключения двухмерной раскладки. Поэтому внутренняя горизонтальная прокрутка таблицы сама по себе не названа нарушением. [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).
- Минимум target size AA — 24×24 CSS px с оговорёнными исключениями; 44 px здесь используется как удобный мобильный ориентир, не как универсальное требование AA. [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Методические выводы для повторного ревью

1. Проверять сосуществование новой и старой моделей как единый путь, а не только каждый экран отдельно: здесь именно переход между реализациями выявил потерю контекста.
2. Измерять координату начала полезного содержимого и фактический размер SVG-текста, а не только отсутствие overflow.
3. При оценке сложных фильтров учитывать высоту всей панели и путь до первой строки результата.
4. Проверять пустой год у метрики с историей: «нет данных в текущем контексте» не равно «метрика никогда не велась».
5. У callback-диалогов проверять возврат фокуса после повторного рендера исходного списка; корректная вложенная форма не доказывает корректность закрытия карточки.
6. Во всех доказательствах различать реальный viewport, размер скриншота и zoom; неоднозначное поведение инструмента не выдавать за баг продукта.
