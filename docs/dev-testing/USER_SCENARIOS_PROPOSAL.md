# Предложение по пользовательским сценариям

## 1. Утверждённая область устройств

- Только ноутбук или настольный компьютер.
- Единственный обязательный браузер — Google Chrome последней разрешённой корпоративной версии.
- Проверяется окно от 640×700 до 2560×1440 CSS px.
- Смартфоны, планшеты, touch-жесты и экранная клавиатура не входят в область.
- На 13–14-дюймовом ноутбуке проверяются полный экран и суженное окно рядом с другим приложением.
- На большом мониторе проверяются полный экран, неполноэкранное окно и рациональное использование ширины.

## 2. Сценарии P0 — обязательны для приёмки

### US-01. Вход, восстановление сессии и выход

Пользователь входит, открывает доступную рабочую страницу, обновляет браузер, продолжает работу и выходит. Проверяются понятные ошибки входа, отсутствие показа закрытых данных, refresh и logout.

### US-02. Поиск и просмотр задачи в backlog

Пользователь открывает backlog, применяет фильтр/сортировку, находит задачу, открывает карточку, переключает вкладки и возвращается к таблице без потери контекста.

### US-03. Изменение обычной задачи

Разрешённый пользователь редактирует обычное поле тестовой задачи, сохраняет, обновляет страницу и видит изменение в карточке/истории. Защищённые поля, команды и ответственные не изменяются.

### US-04. Создание требования через AI-агента

Бизнес-заказчик свободно описывает потребность, отвечает на уточнения, видит собранную карту и может создать драфт после минимального ядра.

### US-05. Исправление ошибки агента

Пользователь замечает неверно понятый факт, исправляет его обычной репликой и убеждается, что карта и последующий драфт используют актуальное значение.

### US-06. Проверка и редактирование драфта

Пользователь просматривает заполненные блоки, предположения, открытые вопросы и качество, редактирует раздел и повторно проверяет результат.

### US-07. Подтверждение и отправка на ревью

Пользователь выбирает заранее подготовленную команду, явно подтверждает драфт и отправляет его. Повторный click/refresh не создаёт дубль.

### US-08. Ревью требования

Ревьюер открывает очередь, находит отправленное требование, читает detail и выполняет разрешённое действие. Другой пользователь не получает доступ к чужой сессии или request вне своего scope.

### US-09. Работа в узком и широком окне

Пользователь начинает критический путь в полном окне ноутбука, сужает окно до 640–1024 px, переключает responsive-представления и затем расширяет окно до 1920/2560 px. Ввод, активная сессия и доступность действий сохраняются.

### US-10. Ошибка агента и повтор

При недоступном agent/LLM пользователь получает понятное сообщение, не теряет введённый текст и после восстановления выполняет один контролируемый retry без дублей и ложного прогресса.

## 3. Сценарии P1 — обязательны для полноценного тестового цикла

### US-11. Несколько диалогов и архив

Пользователь создаёт два требования, переключается между ними, архивирует и восстанавливает одно. Истории и карты не смешиваются.

### US-12. Комментарий и безопасное вложение

Пользователь добавляет комментарий и разрешённое синтетическое вложение к обычной тестовой задаче, обновляет страницу и скачивает файл через авторизованный endpoint.

### US-13. Уведомления

Пользователь открывает список уведомлений, различает прочитанные/непрочитанные, переходит к связанному обычному объекту и видит понятное empty state.

### US-14. Отчёты и аналитика

Пользователь с доступом открывает отчёт, применяет фильтр, получает пустой и непустой результат, проверяет таблицу/график в среднем и широком окне.

### US-15. Разграничение доступа

Пользователи разных профилей открывают разрешённые и запрещённые routes и объекты. Проверяются menu, прямой route, API и object scope; скрытие кнопки не считается достаточным.

### US-16. Конкурентное редактирование

Два разрешённых пользователя открывают отдельную тестовую задачу, один сохраняет изменение, второй получает понятное conflict/retry поведение без молчаливой потери данных.

### US-17. Настройки отображения

Пользователь переключает light/dark theme, accent и compact mode, обновляет страницу и проверяет сохранение настроек и читаемость основных состояний.

### US-18. Клавиатурный критический путь и zoom 200%

Без мыши выполняется вход, навигация к агенту, отправка сообщения, работа с modal и возврат фокуса. При zoom 200% критические действия остаются доступны.

### US-22. Импорт задач

Пользователь импортирует CSV и преобразуемый frontend Excel-файл, проверяет preview/результат, валидные и ошибочные строки, созданные обычные задачи, историю и аудит. Импорт только читает существующие справочники и пользователей и не изменяет защищённые данные. Детализация: [`IMPORT_TEST_CASES.md`](IMPORT_TEST_CASES.md).

## 4. Сценарии P2 — при наличии времени или профильной потребности

- US-21: Массовые операции с preview на выделенных задачах.
- US-23: Admin и audit log — только read-only UX и запрет доступа.
- US-24: Очень длинная сессия агента, длинные русские значения и граничные тексты.

Не входят в первый цикл по решению владельца продукта:

- US-19: Kanban;
- US-20: Express estimate.

## 5. Предложение по утверждению

Рекомендуется утвердить:

- US-01–US-10 предварительно утверждены как релизный P0-набор и могут быть дополнены;
- US-11–US-18 и US-22 входят в обязательную полноценную регрессию;
- US-21, US-23 и US-24 остаются расширенным набором;
- US-19 и US-20 исключены из первого цикла.

## 6. Зафиксированные решения владельца продукта

- P0 US-01–US-10 предварительно подтверждены; перечень будет дополняться.
- Kanban и Express estimate выключены из первого цикла.
- Импорт обязателен.
- Владелец продукта лично выполняет/оценивает бизнес-сценарии заказчика и ревьюера с использованием заранее подготовленных профилей доступа.
- Поддерживаемый браузер для первого цикла — только Google Chrome.
- Массовые операции US-21 относятся к расширенной проверке и не блокируют первый обязательный цикл.
