# Разбор семи расхождений дизайн-пилота

Проверено 05.11.2026, Windows Chromium. Область: рабочие задачи, полная оболочка
SPA, обе темы, 1440×900 / 1366×768 / 390×844, инспектор и редактор.

## Причина и решение

Семь FAIL из [проверки ссылок](NEUTRAL_LINKS_2026-11-04.md) относятся к состоянию
до завершения [унификации таблиц](REGISTRY_TABLES_2026-11-04.md). В рабочей копии
на начало этой проверки уже были изменения UI Kit и соответствующие эталоны
от 04.11.2026 22:03–22:04. Это не семь оставшихся воспроизводимых дефектов:
повтор без обновления снимков проходит все десять сценариев.

Причина старых diff подтверждена изображениями и кодом: `workQueue.js` применяет
`ui-table-title`, `ui-table-meta`, `ui-table-id`; общий `registry-tables.css`
задаёт моноширинный ID и однострочное название на desktop, перенос на mobile.
Изменение высоты длинного названия сдвинуло последующие строки. В редакторе
изменился список слева, а не поля справа. Эти правила закреплены в действующем
[контракте таблиц](../../dmb-backlog/docs/REGISTRY_TABLES.md).

Откат к старой типографике и переносам нарушил бы этот контракт. Новые CSS-правки
не потребовались. В этой задаче эталоны, допуск `maxDiffPixels: 80` и проверки
не изменялись. Исправлен устаревший открытый статус в отчёте о ссылках.

## Проверки и границы

- Функциональность: десять сценариев дизайн-пилота проходят; открытие карточки,
  поиск, отмена фильтров, порядок основных полей, отсутствие внешнего overflow.
- Визуальная оценка: просмотрены семь старых diff и свежие полные экраны;
  описанные изменения объяснены, дополнительных дефектов в области этих diff
  не обнаружено. Проверка не ограничивалась зелёным результатом тестов.
- UI Kit: используются общий вариант реестра и композиции «реестр» / «реестр
  с инспектором». Названия на desktop сокращены согласно контракту, полный текст
  остаётся в DOM, `title`, доступном имени и открываемой карточке.
- Эталоны: не обновлялись в этой задаче; [SHA-256](evidence/design-diff-review-2026-11-05/baseline-sha256.json)
  фиксирует использованный набор. Запуск без `--update-snapshots` и без режима capture.
- Сбор свежих снимков отдельным capture-прогоном: 10/10; он не заменяет сравнение.
- Это fixture-проверка настоящего SPA с перехваченными API, без записей в БД.
  Live-приёмка, роли, сохранение реальных данных и все вторичные состояния системы
  этим отчётом не закрываются. Impeccable применён как помощь в refinement/polish,
  без отдельного многоагентного critique.
