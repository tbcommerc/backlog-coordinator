Продолжение проверки: [R7 — все состояния страницы и карточки](METRICS_FULL_SURFACE_REVIEW_2026-11-04.md).

## Переоценка панели фильтров — 04.11.2026

**Общий вывод R6 о визуальной готовности отозван.** Пользователь обоснованно
указал на чрезмерно высокую раскрытую панель, отдельный чекбокс архива и повтор
условий под ней. Эта панель уже была в доказательствах R6: недостаток заключался
не только в охвате, но и в ошибочной визуальной оценке. Исторические зелёные тесты
не опровергают замечание пользователя. Ниже — исправления конкретных состояний,
а не повторное утверждение, что все визуальные проблемы приложения устранены.

- Шесть условий оформлены существующим вариантом `ui-field-inline`: подпись
  рядом со значением, без уменьшения общих размеров контролов. На desktop — две
  строки, на промежуточной ширине — две колонки, на телефоне — один столбец.
- Сортировка, «Включая архив», сброс и применение собраны в нижнюю строку.
  Быстрые условия и активные фильтры под панелью скрыты, пока она раскрыта;
  после сворачивания снова видны. Годовой toolbar на телефоне не резервирует
  полную строку для единственного поля года.
- Условия внимания внутри панели теперь входят в общий черновик и применяются
  по кнопке вместе с остальными полями. Быстрые условия снаружи остаются
  немедленными. Сброс сохраняет год, квартал и представление.
- Для выпадающих списков сохранены явные доступные имена; проверено открытое
  окно выбора владельцев с поиском. Защищённые записи и метрики не изменялись.
- Область «Мои метрики» теперь остаётся видимой снимаемой отметкой при свёрнутой
  панели и учитывается в счётчике фильтров; скрытое ограничение больше не теряется.

## Дополнение: пропущенное меню колонок

После R6 пользователь показал дефект открытого меню «Колонки»: чекбоксы стояли
вплотную в одной строке, пояснение не было отделено. Предыдущий вывод об устранении
обнаруженных обходов UI Kit был неполным: это открытое состояние не осматривалось.
Зелёные проверки закрытого реестра не покрывали дефект.

Исправлено штатным `selectionList` и существующими `ui-popover-header`,
`ui-popover-title`, `ui-popover-hint`: два отдельных пункта с полноценными зонами
нажатия, заголовок и отдельное пояснение. Локальный CSS не добавлялся.
В полноэкранные сценарии включены раскрытие меню, отсутствие пересечения строк,
границы экрана, переключение Space, изменение и восстановление колонок,
Escape и возврат фокуса. Повторный прогон: **8/8** (1440, 1366, 390 и 320px,
обе темы). Живое открытое меню осмотрено на desktop и на 320px в тёмной теме:
[desktop](evidence/metrics-impeccable-2026-11-04/columns-desktop.png),
[320px dark](evidence/metrics-impeccable-2026-11-04/columns-mobile-dark.png).

## Сценарий и композиция

Реестр нужен для сравнения плана, факта, результата и состояния за период.
Основное действие — создание метрики; поиск и период находятся перед данными,
вторичные условия раскрываются отдельно. Карточка нужна для оценки одной метрики
и внесения факта: название/действие → контекст/период → результат → динамика/замеры
→ подробности. Обсуждение и история вынесены во вкладки. Оболочка, палитра,
типографическая шкала и размеры контролов сохраняют действующий UI Kit.

  Эталоны рабочих задач не обновлялись. Финальный `npm run test:design` без
  обновления эталонов: **10/10**. После исправления сетки периода повторены
  **22/22** сценария (полная оболочка, адаптивность, увеличение, точные числа,
  вкладки, заполненные замеры). Это повтор части набора, а не 22 новых теста.
  После финальной правки сетки истории повторены **8/8** полноэкранных сценариев
  с дополнительной проверкой выравнивания и снимками истории. Локальные ссылки
  затронутой документации: **269**, пропавших целей нет; `git diff --check` чистый.
- Live: `127.0.0.1:8000`, существующая QA ba-a, 44 строки; QA VOLUME и RANGE,
  26 замеров и точное длинное число. Выполнен штатный повторный вход. Формы

## Раздельный вывод

**Функциональность:** бизнес-правила и API не менялись; регрессия проверяет
сохранность поведения после изменений представления.

**Внешний вид:** по ручной оценке разделы карточки больше не выглядят отдельными
вложенными объектами, результат читается раньше вторичных подробностей. Реестр
сохраняет плотность и согласованные линии контролов. Длинное точное значение
доступно на 320px без горизонтальной прокрутки тела карточки.

**UI Kit:** устранены обнаруженные обходы контролов в quarterly-странице и карточке;
варианты документированы и представлены в каталоге. Предметная сетка и график
остаются локальными. Это не утверждение об отсутствии любого локального CSS или
о полной миграции исторического legacy-экрана.
