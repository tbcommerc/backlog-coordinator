# Повторная проверка БД и авторизации для банка — 23.11.2026

Требование: приложение работает с заранее подготовленной DBA структурой БД.
Механизм автоматического upgrade при запуске приложения в банковском профиле
не используется. [Порядок для DBA и DevOps](../BANK_DEPLOYMENT.md).

## Изменения

- Новый [банковский core-профиль](../../compose.production-core.yaml) подключается
  к внешней готовой PostgreSQL, не содержит PostgreSQL/migration-сервисов и ИИ.
- [Команда развёртывания](../../scripts/deploy-core.py) проверяет конфигурацию,
  неизменяемый image ID, схему и ограниченную роль до остановки приложения.
  Принимает только готовую схему; DDL, seed, создание БД/ролей не выполняет.
- [Startup/readiness guard](../../dmb-backlog/backend/schema_guard.py) проверяет
  ревизию, критические столбцы и отсутствие владения/CREATE-прав/записи
  в `alembic_version`. При несовместимости приложение не стартует.
- [SQL экспорт для DBA](../../dmb-backlog/backend/schema_sql.py) не подключается
  к БД. Обновление содержит транзакцию, блокировку и проверку исходной ревизии.
  Неизвестная схема не получает автоматический `stamp` или repair.
- [Шаблон DML-прав](../../infrastructure/postgres/runtime-role-grants.sql)
  применяется DBA отдельно и не содержит логинов/паролей или CREATE ROLE.

## Проверки

Серверная регрессия на отдельной PostgreSQL: **58 passed**. Включает
авторизацию, cookie-политику, NULL-права, справочники, создание только с названием,
явную очистку ссылок и 5 новых случаев отказа неподготовленной схеме, проверки
реальной структуры и раннего завершения production startup.

Полная репетиция с ограниченной runtime-ролью и отдельным DBA-процессом —
**PASS, 21 этап**, завершена 23.11.2026. Проверены:

- отказ неподготовленной БД с нулём созданных таблиц и без старта backend;
- отдельное применение начальной SQL-структуры DBA и реальный запрет
  `CREATE`, `ALTER`, `DROP` для роли приложения;
- банковский deployment без миграций, два backend, DEBUG=false, HTTPS;
- первый администратор и приглашение, вход, `/auth/me`, cookie/refresh,
  справочники, задача только с названием, редактирование и связанные реестры;
- ClamAV/вложения, ограничения наблюдателя и HTTPS redirect;
- два естественных истечения access и refresh, перезапуск с сохранением данных;
- SQL обновления заполненной старой схемы с сохранением различающихся ID
  справочника/задачи; отказ неверной исходной версии без изменения записей;
- backup в другую БД и повторный вход;
- повторный операторский deployment с сохранением схемы, записей и действующей
  refresh-сессии;
- выполнение **точных файлов комплекта** на дополнительных пустых БД:
  начальная структура содержит 0 пользователей, 0 прикладных ролей и 0 записей
