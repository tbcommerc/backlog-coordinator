## Исправления

| Дефект | Итоговое поведение |
|---|---|
| REF-01 | Все одиночные справочные селекторы и вовлечённые команды хранят ID. Одинаковые ФИО, заказчики и проекты различаются логином, подразделением или кодом; при необходимости добавляется ID. Подразделение определяется по ID заказчика. Черновик и сравнение изменений также учитывают ID. |
| REF-02 | POST/PATCH/PUT проверяют существование подразделения до записи; неизвестный ID даёт 422 с указанием поля, задача не изменяется частично. |
| REF-03 | Отказ загрузки справочников явно показан компактным Alert с повтором запроса. Старые значения и текст черновика сохраняются. Недоступные справочные контролы блокируются до успешного повтора. |
| REF-04 | Новые варианты меток содержат только активные записи. Ранее назначенная архивная метка остаётся видимой и может быть явно снята. |
| REF-05 | Исторические подразделение и клиент ДИД показаны выбранными с отметкой «недоступно». Сохранение других полей не очищает их; очистка выполняется явно. |
| REF-06 | ID вовлечённых команд проверяются при создании, изменении и массовом обновлении. Неизвестный ID возвращает 422 с индексом элемента. |
