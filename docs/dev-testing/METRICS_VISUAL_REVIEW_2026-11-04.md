# Метрики — повторное UX/UI и дизайн-ревью

Продолжение проверки по DESIGN.md и Impeccable: [R6](METRICS_IMPECCABLE_REVIEW_2026-11-04.md).
В нём устранены оставшиеся локальные обходы UI Kit, внутренние разделы карточки
переведены на plain, добавлены проверки полной оболочки и обновлены доказательства.
Этот документ сохраняет историю R5; актуальный вывод о соответствии — в R6.

Ревью выполнено повторно после замечания пользователя к результату R4. Его вывод о визуальной готовности был необоснованным: прохождение функциональных тестов, отсутствие переполнения и положение первой строки не подтверждали качество дизайна. [Предыдущий отчёт](METRICS_UX_UI_REVIEW_2026-11-03.md) исправлен; исторические результаты сохранены с явным ограничением.

Дизайн, внешний вид и соответствие UI Kit закреплены как обязательные приоритетные части ревью в [AGENTS.md](../../AGENTS.md) и [протоколе](../../dmb-backlog/docs/UI_KIT_REVIEW_PROTOCOL.md). Результат оценивается по полному живому экрану, а не отдельным контролам.

## Проверка

Функциональность: **71/71 UI-сценарий пройден** в полном прогоне (`playwright.metrics.config.mjs`, один worker, timeout 90 секунд, 5,7 минуты). После замечаний живого просмотра и добавления V12 — **17/17** целевых проверок; после окончательной доработки 320 px и вложенного текста Badge — **6/6** проверок. Всего покрыто 72 разных сценария, часть запускалась повторно; это не заявление об одном полном прогоне на 72 теста. Включены создание и ошибки сохранения, read-only, конфликты, обе модели карточки, состояния 403/404/503, десятичная точность, пагинация, клавиатура, светлая/тёмная темы и ширины 320/390/768/1024/1440. Новые сценарии проверяют доступность нулевых сигналов в фильтрах, читаемую ширину года после преобразования FilterSelect, смену квартала/режима, стрелки и фокус Tabs, раскрытие точного числа и отсутствие обрезания подписи статуса. CSS zoom=2 проверен отдельно от обычных размеров viewport.

Промежуточные прогоны: один старый селектор «Годовой итог» стал неоднозначным после добавления DescriptionList; уточнён до раскрываемого раздела. Первый процесс тестов не завершил запись результатов из-за ограничений файлового доступа. Попытка использовать уже остановленный внешний сервер отменена; итоговый успешный прогон сам поднял изолированный сервер и сохранил статус `passed`. Функциональные assertions не ослаблялись.

Стенд: обнаружен несовместимый устаревший профиль глобального ограничителя после обновления его кода. Выполнена штатная остановка принадлежащих проекту сервисов; доказано отсутствие активных/ожидающих операций и журналов. Служебный профиль атомарно приведён к текущему протоколу с сохранением лимитов 2/64/8. Затем очищен подтверждённый процесс частичного запуска помощника, для которого не завершилась запись владения. Повторный `scripts/start-project.ps1 -SkipDependencyInstall` завершился с кодом 0 и `Project is fully running`. Итоговый `/api/v1/health/ready`: `ready`, database/redis/attachment_storage/agent/agent_v2 — `ok`, Prioritiser — `disabled`. Защита не отключалась, бизнес-данные не сбрасывались, seed не запускался.

## Визуальная оценка и UI Kit

**Дизайн / внешний вид:** V01–V12 устранены в перечисленных ниже проверенных состояниях. Оценивался полный экран приложения с боковой навигацией и шапкой, затем полная видимая область карточки. Реестр имеет одну собранную основную панель и читаемые строки; дополнительные условия не конкурируют с данными в свёрнутом состоянии. В карточке различимы контекст, календарь, вкладки и результат квартала. На 390 px план и факт расположены рядом, на 320 px — последовательно; вкладки остаются видимыми, большие числа читаются целиком. При повторной оценке проверялась не только разница с плохим исходным вариантом, но и самостоятельная читаемость новой композиции.

**UI Kit:** используются PageHeader, Button, DataTable, FilterSelect, SegmentedControl, FilterChip, Badge, Tabs, SectionCard, DescriptionList, DetailPanel и Pagination. Размеры и типографика контролов берутся из общего набора. Локальные правила задают композицию, адаптивную сетку и ширины колонок. Обоснованные исключения: текст смыслового результата может переноситься внутри Badge вместо многоточия; на 320 px уменьшен горизонтальный отступ вкладок без уменьшения шрифта и высоты цели; длинное число раскрывается отдельно. Конфликт со вложенными правилами общего слоя совместимости Badge подтверждён в браузере и закрыт тестом.

**Функциональность:** пройденные проверки перечислены выше. Проверки R4 сохранены как историческая функциональная база, а его прежняя визуальная приёмка заменена этим разделом. Повторный R5 не создавал и не менял метрики, пользователей, команды или справочники; формы открывались и закрывались без сохранения. Семантика квартальных расчётов и API не изменялась.
