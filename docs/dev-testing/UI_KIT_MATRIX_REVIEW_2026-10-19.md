# UI kit: оставшиеся поверхности и сложные состояния — 19.10.2026

Продолжение [живого QA-прохода 18.10](UI_KIT_LIVE_REVIEW_2026-10-18.md).
Проверены реальные модули SPA на изолированных данных, включая формы и состояния,
которые нельзя безопасно воспроизводить на рабочей БД. Найденные расхождения
исправлены; инвентарь расширен со 111 до **113 поверхностей**.

## Условия проверки

19.10 локальный стенд не прошёл health-check: backend, agent и agent-v2
показывали `health=unreachable`; переход браузера на `127.0.0.1:8000` завершился
таймаутом. Проверка вне песочницы также не подтвердила здоровье; Docker Desktop
вернул HTTP 500 при чтении списка контейнеров. Новая QA-сессия на рабочем стенде
не выполнялась. SQLite и новые учётные записи не создавались.

Все последующие browser-проверки используют локальный сервер статических
исходников на порту 4173 и API в памяти. Формы — исполняемый код приложения,
а не скриншоты-макеты. Для внутренних открывателей диалогов тестовый ответ
модуля раскрывает функцию только внутри браузерной фикстуры. В production
экспорты не добавлялись. Сохранения, конфликты и защищённые административные
операции выполнялись исключительно в изолированных данных.

Для **23 типов сложных диалогов** прежние light/dark, desktop/compact/mobile/coarse
проверки расширены режимом **320×568, dark, coarse**: границы окна по обеим осям,
размеры контролов, отсутствие горизонтального переполнения, Tab, Escape и
возврат фокуса. Каталог 35 модальных сценариев дополнительно проверяется целиком
и шестью визуальными эталонами. Каталог сам по себе не принимается за проверку
реального открывателя.

Новые формы проверены на **1440×900, 768×600, 320×568 и 640×360** в обеих темах.
Для каждого режима размещения поля последовательно прокручивались в видимую
область; нижнее подтверждение оставалось доступным. Проверены также четыре
изолированных успешных отправки с составом полей соответствующего режима.

Два устаревших эталона модального каталога сверены отдельно: раздел задач

Второй случай проверен также без hover. Обновлены только эти два эталона;
допустимый порог различий не увеличивался.

## Проверки и результаты

- Полный frontend unit-набор: **387 PASS / 0 FAIL**.
- Первый проход сложных форм: **242 PASS / 2 FAIL / 1 не выполнен** из 245.
  Падения: устаревшая версия ревью и эталон task; не выполнен следующий serial
  сценарий каталога. Причины исправлены и включены в заключительный повтор.
- Расширенный проход остальных семейств: **294 PASS / 2 FAIL** из 296.
  Падения: компактный эталон confirm и высота панели уведомлений; обе причины
  разобраны, исправлены и включены в заключительный повтор.
- При разработке новых регрессий отдельно выявлены прокрутка fieldset,
  недоступность подтверждения позади native dialog и незавершённая отрисовка
  значка асинхронного состояния; исправлены. Промежуточные падения не выдаются
  за окончательные результаты.
- Адресный проход жизненного цикла после исправлений: **23 PASS**.
- Заключительный проход без обновления эталонов: **84 PASS / 1 FAIL** из 85.
  Единственное падение — измеритель прямых детей `display: contents`: такой
  контейнер не имеет собственного прямоугольника. Измеряются его реальные
  дочерние grid-элементы; ограничения переполнения и высоты не ослаблены.
  Все 15 новых сценариев и 23 открывателя сложных диалогов в этом прогоне прошли.
- Адресный повтор всего набора `notificationSurfaces`: **23 PASS / 0 FAIL**
  (30.1 сек). Неустранённых падений из перечисленных прогонов не осталось.

## Заключение

### Дополнительная проверка типографики по замечанию пользователя

Прежний проход был недостаточен для заключения о типографике: сравнение общих
контролов не включало `font-family` и `font-weight`, а размеры сами по себе не
доказывают загрузку нужной гарнитуры. После замечания выполнен отдельный проход.

| Находка | Исправление и доказательство |
|---|---|
| Четыре фикстуры (`workTasks`, `workWorkspaceRouter`, `accountSecurity`, `localSpellcheck`) не подключали `fonts.css` | Подключён тот же локальный Inter, что в SPA. Новый unit-контракт запрещает фикстуры с базовой типографикой без предшествующего `fonts.css` |
| Общие контролы имели разные начертания: выбранный фильтр V1 — 600, выбранная кнопка аналитики — 650, поля аналитики — 550 при обычном поле 400 | Убраны локальные переопределения; общие кнопки используют 500, значения полей — 400. Семантические заголовки и числовые KPI сохраняют собственные роли; все числа веса внутри variable Inter технически допустимы, дефект был в согласованности одинаковых ролей |
| Chart.js использовал собственный Helvetica/Arial вместо Inter для canvas-подписей | Общая тема задаёт гарнитуру для осей, заголовков, легенд и tooltip. ECharts получает её также явно в tooltip и легенде |
| При холодной загрузке смена декларации шрифта и повторный `update()` сохраняли измерения fallback: 44.46 px вместо 47.79 px для тестовой подписи | Оба движка инициализируются после загрузки Inter. Для Chart.js проверяется совпадение кешированной ширины подписи с `canvas.measureText` загруженного Inter. Устаревшая асинхронная инициализация отчётного canvas не перезаписывает новый canvas/новую версию графика |

Через Chromium `CSS.getPlatformFontsForNode` подтверждено фактическое рисование
локальным **Inter Variable** всей русской азбуки с Ё/ё, латиницы и цифр при
начертаниях **400/500/600/700**, в обеих темах на 1440 и 390 px. Проверяется
`isCustomFont`, а не только строка из `getComputedStyle`. В аналитике действующий
показатель также использует Inter; сохранённая декларация Unbounded не означает
его фактическое применение. Для моноширинных ID/кода допустим системный fallback
из отдельного `--font-mono` (на проверяемой Windows это Consolas).

Усиленный `uiKitConsistency` сравнивает гарнитуру и начертание кнопок, полей,
бейджей, заголовков таблиц и подписей сортировки на прежних 22 поверхностях в
четырёх вариантах темы/плотности/ширины. Сравнение выполняется после
`document.fonts.ready`. Проверка загрузки обоих canvas-движков намеренно
задерживает ответ с файлом шрифта.

Результаты: первый усиленный проход — **57 PASS / 4 FAIL** из 61 (обнаружены
расхождения начертаний); после исправления — **67 PASS / 0 FAIL**.
Отдельная промежуточная проверка холодного canvas выявила ошибку измерений,
поэтому одного `update()` было недостаточно. Итоговый unit-набор — **388 PASS**.
Проверки: [uiKitTypography](../../dmb-backlog/frontend/e2e/uiKitTypography.spec.mjs),
[uiKitConsistency](../../dmb-backlog/frontend/e2e/uiKitConsistency.spec.mjs),
[uiTypography](../../dmb-backlog/frontend/tests/uiTypography.test.mjs).
Дополнительная сверка каталога, ядра, canvas, spellcheck и плотности рабочих
страниц — **26 PASS / 0 FAIL**, без обновления визуальных эталонов.

Эти результаты относятся к Chromium и изолированной SPA; живой QA-стенд и
другие браузеры дополнительно не проверены. Полная ревизия всех текстовых
стилей каждой предметной страницы не заявляется.

Обнаруженные расхождения устранены в реальных компонентах и закреплены
поведенческими проверками. Закрыты пробелы инвентаря, коротких экранов,
вложенного подтверждения и состояний сохранения сложных форм.

113 строк матрицы не означают полный перебор всех бизнес-данных, ролей и
сочетаний состояний. Новые проверки не подтверждают серверные права,
результаты живой модели, многопользовательскую нагрузку или свежую приёмку
рабочей БД. После восстановления локального стенда остаётся живой QA-повтор
новых форм; результаты 18.10 сохранены с исходной датой и областью проверки.
