# Дополнение UI Kit компонентами карточек сущностей

Дата: 29.10.2026. Статус: первая очередь дополнений после сравнения с IBP.

## Реализация

- ReadOnlyField и DescriptionList: подпись/значение, пустое значение, ноль,
  загрузка, ошибка, безопасная ссылка, доверенная разметка и копирование.
- SectionCard: заголовок, описание, действия, тело, футер; сворачивание через
  native details; локальные состояния загрузки, ошибки и отсутствия данных.
- DetailPanel: готовая разметка и контроллер существующего dialog; модальное,
  встроенное и полноэкранное представления, запрет закрытия при busy,
  единый callback проверки черновика, очистка обработчиков и возврат фокуса.
- Пилоты: описание/результат и атрибуты рабочей задачи; секции и паспорт метрики.
  Обе карточки используют общий контроллер DetailPanel. Предметные размеры
  существующих карточек сохранены через явно обозначенный режим consumer.
- Семейства зарегистрированы в UI Kit; каталог содержит интерактивные примеры.

API и ответственность описаны в [UI Kit](../../dmb-backlog/docs/UI_KIT.md)
и [контрактах](../../dmb-backlog/docs/UI_KIT_CONTRACTS.md).

## Проверки

Изолированные проверки работают со статическим сервером и тестовыми ответами
в памяти. Защищённые записи пользователей, команд и справочников не изменяются.
Результаты 29.10.2026:

- **72/72 браузерных сценария PASS** в отдельной конфигурации
  `playwright.ui-details.config.mjs`: 12 проверок новых компонентов и каталога,
  23 проверки существующих диалогов, 4 сценария метрик, 12 сценариев списка
  с панелью и 21 сценарий карточки рабочей задачи. Проверены светлая/тёмная
  темы, 320–1440 px, клавиатура, busy, отказ закрытия, вложенные диалоги,
  черновики, смена представления и сохранение фокуса. Тестовые API-операции
  перехвачены фикстурами и не поступают в рабочую БД.
- **31/31 Node-проверка PASS**: UI API, границы core, токены, доступность
  диалогов, владение компонентами и обнаружение потребителей.
- Генерируемые `family-inventory.json` и `review-inventory.json` сверены с
  исходниками. Проверены 62 локальные Markdown-ссылки, битых нет.
- Общий `check-review-coverage.mjs` пока **FAIL**: устаревшая запись ревью
  `avatar → js/app.js`. Этот файл в поставке не изменялся. Новые семейства и
  ревью затронутых потребителей помечены `pending`; прежние доказательства
  сохранены, успешная живая приёмка не присвоена автоматически.

Повторить браузерные проверки из `dmb-backlog/`: `npm run test:ui-details`.
Используется собственный статический сервер 4187 без переиспользования чужого
процесса. При запуске в Windows sandbox завершение сервера может потребовать
разрешения на остановку его процесса; итог текущего прогона — exit code 0.
Снимки и трассы текущего прогона находятся локально в
`dmb-backlog/.runtime-ui-detail-verified/`, они не предназначены для Git.

При проверке исправлена потеря делегированных обработчиков при подключении
контроллера к существующей карточке: модальное окно сохраняет свой контейнер.
Добавлен регрессионный сценарий. Перемещение между встроенным и модальным
режимами больше не вызывает возврат фокуса как при удалении окна.

## Границы

Поставка включает три семейства первой очереди. Общие DataTable/TableCell,
EntityPicker, DateRange/NumberRange, StepForm и SplitPane ещё не внедрены.
Существующая геометрия карточек остаётся у экранов, общий renderer доступен для
новых панелей. Новая полная приёмка всех ролей на живой БД не заявляется.

В IBP заимствован подход к композиции, а не CSS: цвета, шрифты, размеры и
отступы используют токены нашего проекта.
