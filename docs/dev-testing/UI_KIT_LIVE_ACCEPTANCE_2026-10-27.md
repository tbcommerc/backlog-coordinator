### Найдено и исправлено

1. **Неотличимые сущности аудита.** Рабочие задачи и метрики отображались как «Другой объект». Добавлены названия 18 типов, неизвестный тип сохраняет идентификатор. Фильтр «Метрики» повторно проверен на живых записях.
2. **Пустая страница после повторного входа.** Router сохранял сведения о старой оболочке и добавлял обработчик hashchange при каждом входе. Состояние сбрасывается, обработчик единственный. Повторены входы трёх заказчиков и дальнейшие смены ролей.
3. **Вложенные main.** Исправлены ошибки доставки, ревью, обе карточки заказчика, недельный и директорский отчёты. Добавлен общий guard всех компонентов. В живых outbox/review/customer request/weekly/directorate подтверждён один main.
4. **Серверная ошибка вместо отсутствующей команды.** Экспресс-оценка показывала английское `User has no team assigned` и экспорт. Теперь используется ViewState с объяснением; запросы и недоступные действия не запускаются. Повторно проверено под admin без команды.
5. **Недоступное действие в пустом состоянии метрик.** Подсказка создания теперь зависит от can_create. Повторно проверено под no-access.
6. **Роль «—» после входа.** Login/refresh возвращают role, профиль использует role_name. Auth нормализует подпись без изменения permissions. Новый вход ba-a-peer → настройки подтверждает корректную роль.

## Блокирующая предпосылка

- Backend слушает `127.0.0.1:8000`, но `/health` не отвечает: запрос вне песочницы завершился по таймауту 5 секунд.
- Браузер сообщил `ERR_NETWORK_IO_SUSPENDED`; после этого надёжная живая проверка невозможна.
- Штатный `scripts/start-project.ps1` остановился на preflight Backlog Assistant: `Docker and the pinned runtime image must be available`.
- Отдельная проверка `docker info` вне песочницы вернула HTTP 500 от `dockerDesktopLinuxEngine` для `/v1.56/info`. Это подтверждает недоступность Docker API, но не доказывает отсутствие runtime-образа.
- Повторный запуск установленного Docker Desktop штатным способом не дал подтверждения восстановления. Данные не пересоздавались, seed не запускался, PostgreSQL не заменялся SQLite.

Длительную загрузку админки нельзя достоверно атрибутировать UI до восстановления инфраструктуры и повторного воспроизведения.
