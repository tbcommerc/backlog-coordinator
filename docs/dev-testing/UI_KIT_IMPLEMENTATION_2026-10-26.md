# Внедрение исправлений UI Kit U01–U30

Дата: 26.10.2026. Основание: [глубокое ревью](UI_KIT_DEEP_REVIEW_2026-10-26.md). Правила: [контракты семейств](../../dmb-backlog/docs/UI_KIT_CONTRACTS.md).

## Статус

Изменения по всем 30 пунктам внесены. Дополнительно устранены пять интеграционных нарушений нового модуля метрик и два устаревших ожидания удалённого редактора отчётов в одном unit-тесте. Полный unit-набор: **400/400 PASS**. Заключительная приёмка UI Kit: **135/135 браузерных сценариев PASS**, guards PASS, исходники не изменились во время прогона. Создан [verification-receipt.json](../../dmb-backlog/frontend/ui-catalog/verification-receipt.json). Проверки не отключались, исключения для новых нарушений не добавлялись.

## Повторное ревью

После первого внедрения усилено сравнение вычисленных стилей: кроме кнопок, полей, badges и таблиц оно проверяет FilterChip, KPI, Avatar, Progress, checkbox, tabs, collapse и их внутренние части. Это обнаружило оставшиеся подчёркнутые локальные фильтры рабочей страницы, наследование шрифта прогресса, локальные размеры аватаров и вес текста вкладок. Исправлены причины; для vertical tabs эталон воспроизводит тот же aria-orientation, чтобы допустимый вариант не считался дефектом.

При заключительном чтении обнаружен дополнительный крайний случай U15/U21: скрытый штатный слот ошибки приводил к очистке внешнего aria-invalid. Исправлено владение состоянием, добавлена проверка полного цикла внешняя ошибка → серверная ошибка → clear. Очистка видимой штатной ошибки удаляет только её ID описания; классы слота сохраняются. Промежуточный прогон остановлен; окончательный успешный прогон выполнен после этой правки.

Снимки core обновлены после изменения общего disabled и информационных чипсов; просмотрены desktop light и mobile dark, а также mobile light в ходе внедрения. Повторный прогон проверяет остальные снимки. Неизвестное значение прогресса не приравнено к нулю, ширины предметных колонок не унифицированы искусственно.

## Результаты прогонов

- **Окончательный объединённый `npm run verify:ui-kit`: PASS**, 135/135 браузерных сценариев за 7.6 минуты и весь набор UI guards. Проверка SHA-256 до/после совпала, receipt создан штатной командой. Полный локальный вывод: `.runtime/ui-kit-final-verification.txt`.

- Адресные DeepContracts и Consistency: **14/14 PASS** после последнего исправления ориентации tabs.
- После уточнения начального disabled Upload и связи динамического статуса с file input: повторно **10/10 DeepContracts PASS**; отдельные Ownership/Feedback/MeetingCapture unit — **10/10 PASS**.
- Полный unit-набор после интеграционных исправлений: **400/400 PASS** (предыдущий диагностический прогон: 394/400). Полный локальный вывод — `.runtime/ui-kit-final-unit.txt` (runtime-журнал не включается в Git).
- Дополнительный расширенный браузерный набор: **117/117 PASS** за 7.9 минуты (Core, FamilyContract, Review20261021, DataDisplay, Composites, ComplexFormsReview, Charts, DialogAcceptance, InfoChips). Вместе с адресным набором — **131/131 PASS**. Это результаты двух прогонов, а не одного атомарного снимка дерева.

Дополнительные шесть unit-ошибок, найденные в общем дереве, устранены: `uiCoreBoundary` — metrics.css перенесён до kit; `uiMigrationMatrix` — новый metrics.js и три поверхности зарегистрированы с ограниченной областью доказательства; `uiSizingOwnership` — две кнопки метрик используют ui-link; `uiStyleOwnership` — две таблицы используют ui-table-data, убрана локальная типографика ячеек; `uiTypography` — 10/11 px заменены на text-xs; `moduleContracts` — удалены только два ожидания client_request_id/version удалённого редактора админки. Остальная проверка модуля сохранена и проходит. [Новый браузерный набор метрик](../../dmb-backlog/frontend/e2e/uiKitMetricsIntegration.spec.mjs): **4/4 PASS**, реестр, открытие/закрытие формы, readonly файлы/связи, light/dark, 390/1440. Это проверка интеграции UI Kit, не приёмка бизнес-функций нового раздела.

## Живой интерфейс

Использована существующая сессия QA ba-a на `http://127.0.0.1:8000`. Проверены список рабочих задач, меню строки, открытие WRK-27, вкладка «Материалы» и доступное имя file input, возврат в список, сводка, disabled KPI с нулём, текстовый KPI «Не включены», переключение светлой/тёмной темы. После обновления страницы просмотрена мобильная компоновка 434 px. Тема возвращена в светлую, временное переопределение viewport сброшено. Записи БД не изменялись, файлы не загружались.

При первом переходе на доску backend стал недоступен; `project-status.ps1` подтвердил `backend: process=stopped, health=unreachable`. После восстановления (`running/ready`) проверка продолжена: доска загрузила колонки, переключение «Новые» → «В работе» показало соответствующие карточки; визуально проверен мобильный вид. В «Моих запросах» подтверждены нулевые счётчики, пустое состояние и доступные действия. Пагинация на живых данных этой учётки не появилась из-за отсутствия запросов; её состояния проверены изолированно. Изолированные браузерные тесты работают на отдельном статическом сервере и не объявляются заменой полной живой приёмки всех ролей и маршрутов.

Снимки live-проверки: [светлая сводка](evidence/ui-kit-deep-2026-10-26/implementation-live-summary.png), [тёмная сводка](evidence/ui-kit-deep-2026-10-26/implementation-live-dark.png).

После завершения сессии выполнен разрешённый штатный вход QA ba-a; реквизиты не выводились и не сохранялись. На прямом маршруте «Поручения из встреч» проверены форма, связанный file input с ограничениями, нулевой счётчик и disabled переход к подтверждению. Разбор и сохранение не запускались.

«Экспресс-оценка» открылась с пустым списком задач, нулевыми итогами и штатным стартовым состоянием. Заполненные inline-редакторы этого пользователя отсутствуют, поэтому их имена и поведение подтверждены изолированной проверкой реального renderer, а не созданием записей в БД.

## Как повторить приёмку

Из `dmb-backlog`: `npm run verify:ui-kit`. Только полный PASS создаёт `frontend/ui-catalog/verification-receipt.json`; `npm run check:ui-evidence` затем проверяет его актуальность. Family inventory — список кандидатов и хешей, не сертификат. CI уже выполняет все `frontend/tests/*.test.mjs` и Playwright suites, поэтому новые проверки входят в существующий quality gate без выборочного пропуска.

Автоматическая приёмка относится к перечисленным UI-контрактам и сценариям. Полный перебор всех ролей, данных и бизнес-операций не заявляется; область живого прохода перечислена отдельно. Добавление новой поверхности, варианта или состояния требует расширить проверку, а не ссылаться на старый PASS.
