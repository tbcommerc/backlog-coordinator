# AGENTS.md — контракт агентного слоя

> Проверено по `.opencode/tool/`, `agent-prompts/`, CLI и FastAPI 01.09.2026.

Файл читают агенты opencode при работе в этом репозитории.

## Что это за проект

Агент-приоритизатор инициатив трайба инноваций банка. Одна функция: для каждой
задачи Единого бэклога вычислить приоритет P1–P5 и, если поле Value не заполнено
вручную, рассчитать его по единой методике. Методика зафиксирована в ТЗ v2.0,
её конспект — `docs/METHODOLOGY.md`.

## Разделение ответственности

```
opencode-агент          → собирает вводные, объясняет результат, задаёт вопросы
  └─ .opencode/tool/*.js  → тонкие обёртки, JSON внутрь и наружу
       └─ app/cli.py       → интерфейс детерминированного ядра
            └─ app/core/    → Value, Cost, C/V, восемь факторов, свёртка, овверрайды
```

**Агент не считает числа.** Value, приоритет, C/V и веса вычисляет Python.
Это требование методики, а не архитектурная придирка: расчёт должен быть
воспроизводимым, иначе ранжирование нельзя защитить перед методологом как
объективное.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `backlog-stats` | Распределение по P1–P5, командам и уровням уверенности |
| `backlog-query` | Список задач с фильтрами и сортировкой |
| `task-explain` | Карточка задачи: факторы, вводные Value, овверрайды, история |
| `task-recompute` | Пересчёт одной задачи в шкале всего бэклога |
| `backlog-recompute` | Пересчёт всего бэклога |
| `reference-read` | Действующая версия справочника |
| `rag-search` | Поиск по четырём слоям: `k3`, `knowledge`, `backlog`, `methodology` |
| `rag-status` | Состав корпуса, режим поиска, версия пакета K3 |
| `rubric-read` | Критерии оценки факторов F5 и F6 |
| `assessments-read` | Действующие оценки F5 и F6 с обоснованием |
| `strategy-assess` | Записать оценку F5 — только `strategy-analyst` |
| `dependency-assess` | Записать оценку F6 — только `dependency-analyst` |
| `attribution-run` | Ex-post атрибуция `value_external` (требует подтверждения) |
| `snapshot-status` | Версия и статистика зашитого слепка исторических Value |
| `agent-estimate` | Stateless-сценарий `value`/`priority` для контракта Координатора |

Записи в справочники у агентов нет намеренно: калибровка методики — решение
методолога, и оно должно фиксироваться с автором и временем.

Оценки F5 и F6 пишут только профильные субагенты, каждый свой фактор. Субагент,
способный двигать оба фактора одним суждением, легко подогнал бы их под желаемый
приоритет — см. `docs/FACTOR-ASSESSMENT.md`.

## Границы, которые нельзя нарушать

1. **Внешний контур.** В материалах за пределы трайба эффект не подсвечивается
   как «экономия времени сотрудников» или «высвобождение ПШЕ». Наружу идёт
   только `value_external` доходным методом; у обслуживающих команд до запуска
   ex-post атрибуции это `TBD` — так и указывается, без подстановки
   `value_internal`.
2. **Методологические решения не пересматриваются** без явной просьбы владельца:
   единые константы, классификация команд на зарабатывающие и обслуживающие,
   раздвоение Value, состав восьми факторов. Они прошли четыре итерации
   согласования.
3. **Числа не выдумываются.** Отсутствующая вводная — это вопрос автору задачи и
   пониженный уровень уверенности, а не правдоподобная подстановка.
4. **Материалы слоя `k3` имеют банковскую классификацию K3.** Использовать их,
   чтобы понять задачу, можно. Цитировать в материалах, уходящих за пределы
   трайба, — нельзя. В git расшифрованный корпус не попадает никогда: в
   репозитории лежит только шифротекст.

## Запуск

В составе DMB Platform используй корневой `scripts/start-project.ps1`. Он
запускает FastAPI prioritiser на `127.0.0.1:9100` в отдельном
`.venv-prioritiser` и ждёт `/health`.

Standalone opencode runtime:

```bash
bash tools/launch/start-agent.sh preflight   # проверить окружение
bash tools/launch/start-agent.sh start       # поднять opencode
bash tools/launch/start-agent.sh status
bash tools/launch/start-agent.sh stop
```

Модель выбирается в селекторе opencode. Конфигурация провайдеров — `opencode.json`.

## Интеграция с DMB Backlog

- `/agent/value/full` и `/agent/priority/full` принимают полный набор атрибутов
  задачи и не читают БД backlog.
- Backend сохраняет результат только после проверки прав, task version и edit lock.
- Prioritiser не должен изменять пользователей, роли, команды, справочники и их
  ответственных. Исторический snapshot и reference YAML меняются только по
  прямой задаче владельца методики.
- Порт 9100 является внутренним; до появления service auth его нельзя публиковать
  наружу.

## Стиль

Русский язык в общении, английский в коде и коммитах. Конкретика и цифры вместо
общих формулировок. Методологически спорные места поднимаются явно.
