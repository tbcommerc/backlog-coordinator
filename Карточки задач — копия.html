Контекст задачи

Карточка — базовая единица DMB Backlog. Она должна работать в 4 сценариях: канбан-доска (drag&drop), бэклог команды (таблица+карточки), статус-отчёты для директорских, аналитические дэшборды PO/PL. Каждый вариант ниже решает определённую пользовательскую задачу.

UX/UI rationale (PO взгляд)

Цель: максимальная плотность информации на колонку канбана (обычно 280-320px).

Иерархия чтения (F-pattern):

  • ID + приоритет — мгновенная идентификация, P1 виден сразу (красный бейдж)
  • Название — главный объект, 2 строки с line-clamp защищает layout от длинных формулировок
  • Статус + срок — операционная информация "что происходит"
  • Прогресс-бар — визуальный якорь, работает периферийно
  • Команда + assignees — социальный слой, помогает в daily standup

Почему левая цветная полоса: цвет приоритета работает как преаттентивный атрибут — мозг считывает его за 50мс без фокуса внимания (по Гестальту). Эффективнее, чем фоновая подсветка всей карточки.

Компромиссы: убрали фин. метрики (S/V, млн ₽) — на канбан-доске они шум, их место в бэклоге команды.

UX/UI rationale (PO взгляд)

Цель: одна карточка = полноценный "паспорт задачи" для grooming и sprint planning.

Трёхуровневая структура:

  • Header — идентификация и таксономия (ID, приоритет, команда, статус). Позволяет фильтровать взглядом.
  • Body — описание + метрики в grid 2×2. Числа в "плитке" — известный паттерн dashboard'а, глаз быстро сканирует KPI.
  • Footer — социальный контекст (кто работает) и прогресс.

Цветовая семантика метрик: фин. эффект — изумруд (позитив), S/V — индиго (аналитика). Цвет несёт смысл, не декор.

Блок "Комментарий по статусу": выделен синим, т.к. это последняя актуальная информация — PO читает именно его перед директорской. Blue = информационный, не тревожный.

Почему не collapsed: в бэклоге команды задачи просматриваются поштучно, а не массово — плотность не критична, важна полнота.

UX/UI rationale (PO/Designer)

User story: "Как Leader Трайба, я хочу видеть ROI задач, чтобы защищать бюджет квартала перед CIO."

Hero-блок с S/V: главная метрика вынесена в цветной header крупным шрифтом (3xl). Это якорь внимания — по исследованиям Nielsen, первые 2-3 элемента получают 80% внимания.

Финансовый grid 3×1: Затраты (нейтральный серый) → Эффект (позитивный зелёный) → Payback (аналитический индиго). Порядок слева направо = логика принятия решения.

Точка безубыточности на прогресс-баре: уникальный элемент. Показывает не "сколько сделали", а "когда начнёт окупаться". Маркер-линия на 50% — момент, когда cumulative effect > cumulative cost.

Что НЕ показываем: assignees, комментарии, статусы — не релевантно для финансовой аналитики. Закон Хика: меньше опций = быстрее решение.

UX/UI rationale (PO/Designer)

Принцип "Negative-first": красный banner + border-2 + pulse-анимация иконки. Карточка должна "кричать" — это OK для редких критических кейсов.

Структура "Сигнал → Диагноз → Действие":

  • Banner — что случилось (просрочено, эскалация)
  • Grid 2×1 индикаторов — конкретные цифры отклонения (не "плохо", а "65% вместо 85%")
  • Блокер в тёмной плашке — причина + ответственный. Тёмный фон = "чёрный ящик" проблемы
  • Impact-линейка — последствия в цифрах. Фин. риск, downstream зависимости, SLA
  • CTA-buttons — действие внутри карточки, не нужно открывать детали

Почему CTA внутри: для директорской статус-встречи это критично — решение принимается за 30 секунд на задачу. Переход в детали = потеря темпа совещания.

Accessibility: цвет не единственный канал — везде есть иконки и текст. WCAG AA compliant.

UX/UI rationale (PO/Designer)

Паттерн "List-row as card": гибрид таблицы и карточки. Работает когда задач 50+ и пользователь сканирует список.

Горизонтальная композиция (Z-pattern):

  • Слева — цветовая индикация приоритета (тонкая полоска 6px, не массивная)
  • Центр — ID + команда + название (основной контент)
  • Справа — операционные метрики (срок, прогресс, навигация)

Высота 60-70px: оптимально для "одна задача = одна строка зрения". На 24" мониторе помещается ~12 задач без скролла.

Прогресс в мини-формате: bar высотой 4px — периферийная информация, не отвлекает от названия.

Адаптивность: на мобильных колонка "Срок" скрывается, остаётся только прогресс — progressive disclosure.

Идеальный use-case:替代表格 в "Карточках" режиме бэклога команды. Быстрее чем таблица, информативнее чем список.

Задержка со стороны Risk-команды по обновлению compliance-правил. План Б — временный fallback на legacy-движок.

UX/UI rationale (PO/Designer)

Концепция "Project Passport": для 5-10 ключевых инициатив банка. Одна карточка заменяет отчёт на 2 страницы.

Dark-header premium: тёмный градиент = "VIP-статус". Психология: чёрный ассоциируется с важностью (black card, executive class). Отделяет ключевые проекты от обычных задач.

Timeline с "точкой сейчас": белый кружок на прогресс-баре — уникальный элемент. Показывает не абстрактный %, а "где мы во времени". Gradient emerald→amber — эмоциональный сигнал "начали хорошо, приближаемся к дедлайну".

Health score "A": как в кредитных рейтингах (S&P, Moody's). Топ-менеджмент привык к этой шкале — не нужно объяснять.

Milestones вместо статуса: executives мыслят вехами, не процентами. Три состояния: ✓ сделано / 🔄 в процессе / ○ впереди. Гештальт: прогресс как путь.

Risk с планом Б: не просто "есть риск", а "есть риск + есть mitigating action". Топ-менеджмент не любит проблемы без решений.

Высота ~500px: сознательный выбор. Executive карточка открывается полноэкранно или в модале — это отдельный артефакт, не элемент списка.

Итоговая стратегия реализации

Рекомендую не выбирать один вариант, а внедрить адаптивную систему: базовый компонент <TaskCard variant="..."> с 6 пресетами. Переключение по контексту (раздел приложения) + ручной override в настройках пользователя. Это соответствует паттерну "Progressive Disclosure" и учитывает разные ментальные модели аудиторий (team vs executives).
