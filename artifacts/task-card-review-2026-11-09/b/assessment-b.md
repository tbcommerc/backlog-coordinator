## Подтверждённые замечания исходников и UI Kit

### B01 — P2: выбранность команд и тегов не доступна assistive technology

`modal.js:5738–5745`: `cardChipsTeams` и `cardChipsTags` создают toggle-buttons только с `.on` и декоративными plus/check. Нет `aria-pressed`, checkbox-семантики или скрытого текста состояния. Обработчик 7892–7902 меняет массив, перерисовывает body и не восстанавливает фокус на изменённом toggle. В режиме полного/быстрого редактирования пользователь скринридера не получает явного состояния выбора; клавиатурный пользователь после выбора может потерять место.

UI Kit требует источник выбранности `aria-pressed` для toggle/filter chips и передачу состояния независимого выбора. Исправление: общий именованный вариант multi-select/checkbox либо Button с корректным `aria-pressed`; вернуть фокус на тот же идентификатор после перерендера. Это исходниковое доказательство; фактическое прохождение скринридером ещё не выполнено.

### B02 — P2: вложенные рамки и повтор названия расходятся с актуальной композицией карточки

`cardRenderHeader:5892–5904` уже выводит название h1. `cardBodyMainV30:6179–6190` снова выделяет то же название отдельной рамкой, затем отдельные рамки описания и пустого внутреннего комментария. Далее `6195–6221` добавляет рамки внутренних групп «Исполнение», «Оценка и прогноз», «Команда», «Заказчик», «Классификация». CSS `components.css:4990`, `5161` задаёт поверхностям border/radius/padding; это части одного объекта, а не самостоятельные объекты.

Live [13-main-clear.jpg](../live/13-main-clear.jpg) подтверждает геометрию: три верхние поверхности, включая повтор названия и пустой комментарий, занимают крупную часть первого экрана; исполнителя/заказчика видно у нижнего края, KPI и трудозатраты дальше. Актуальный DESIGN.md требует `sectionCard({variant:'plain'})` внутри одной карточки, UI_KIT_CONTRACTS — ReadOnlyField/DescriptionList и SectionCard; здесь ручные `cardF/cardIcell/cardSec`, `.cl`, `.task-title-card`, `.task-desc`. Предлагается одна верхняя идентификация, компактные главные атрибуты перед длинным описанием, внутренние plain-разделы. Это композиционное замечание, не требование уменьшить шрифт или поля.

Мобильные [33-main-mobile390.jpg](../live/33-main-mobile390.jpg), [35-mobile390-dark.jpg](../live/35-mobile390-dark.jpg) (390×844) усиливают замечание: до нижней панели попадает только начало «Исполнение»; срок, прогресс и исполнитель остаются ниже первого экрана. При этом название повторяется сразу под шапкой, а пустой внутренний комментарий занимает полноценную отдельную поверхность. Обрезания внешней ширины не видно; главный дефицит — порядок информации и потраченная высота, в обеих темах. Горизонтальная лента вкладок показывает примерно две из шести, крайняя стрелка обозначает продолжение.

### B03 — P2: известные нулевые затраты превращаются в отсутствие данных

`cardEffortTable:6224–6234`: `const eoRub = (+eoV) ? ... : null` и `ftzRub` аналогично; вывод `eoRub ? ... : '—'`. При валидном 0 дней табличная стоимость показывает «—», хотя ноль известен. Контракт UI Kit прямо запрещает считать ноль отсутствием данных. Исправление: различать null/undefined/пустую строку и числовой 0; форматировать 0 ₽. Пока source-level; на живой карточке с нулевым значением не подтверждено.

### B04 — P3: локальные визуальные правила продолжают владеть частью контролов

UI Kit поздно подключается через kit.css, содержит зарегистрированные legacy adapters и dialog bridges. Поэтому само наличие локального правила не доказывает, что оно побеждает; нельзя объявлять все кнопки несоответствующими.

Однако `components.css:6844` отдельно задаёт размер/вес `.task-title-card .title-input` (13.5px), при стандартном `--control-font:0.8125rem`; широкий вложенный ID-scope и селекторы `input:focus` сохраняют отдельный слой внешнего вида. `cardCustomerReference:6166` также собирает select вручную. Следует перенести нужные различия в явный именованный вариант UI Kit и подтвердить computed styles до удаления совместимости. Это технический риск консистентности, а не доказанный дефект всех отрисованных размеров.

### B05 — P2: отчётные статусы резервируют по 132px для отсутствующего прошлого текста

[14-reporting.jpg](../live/14-reporting.jpg): у трёх карточек прошлого статуса показан один «—», но под ним остаётся почти целая пустая текстовая область. Четвёртая встреча начинается у нижнего края и требует прокрутки. Причина конкретна: `pages.css:6965` назначает `.reporting-status-field .fval { height:132px; overflow:auto; }` одновременно и read-only прошлому статусу, и редактору следующего. Нужно оставить ограниченную высоту длинному содержимому/редактору, а отсутствие прошлого статуса свернуть до строки «Статус не заполнен». Здесь рамка каждой встречи оправдана самостоятельным сохранением; проблема в внутренней пустоте, не в самом количестве карточек.

Дополнительные наблюдения: `cardBodyRep:6277` при ошибке предлагает повторно переключить вкладку вместо явного Retry/ViewState; это source-only ветка, live failure не воспроизведён. В главном просмотре отсутствующий срок представлен одной иконкой календаря без «Не указан» (13-main-clear); стоит явно обозначить отсутствие значения.

### B06 — P2: диалог условий AI-расчёта теряет внутренние отступы

[25-ai-requirements.jpg](../live/25-ai-requirements.jpg): заголовок касается левого/верхнего края, вводная строка начинается вплотную к краю; список выглядит отдельной вложенной поверхностью, кнопка выровнена иначе. Для сравнения [29-status-progress-confirm.jpg](../live/29-status-progress-confirm.jpg) показывает нормальные поля общего подтверждения. `showPrioritiserRequirementsModal:6016` монтирует `.app-modal` внутрь `#task-detail-overlay`. Внутри этого ID-скоупа `components.css:4660` применяет `* { margin:0; padding:0 }`, который по специфичности перекрывает общие header/body отступы `modal-system.css:77–126`. Это воспроизведённый конфликт локального CSS и UI Kit, а не только наличие старых классов.

Предварительная source-only гипотеза о выходе Tab за вложенный диалог **снята**: нейтральный live [31-ai-focus.json](../live/31-ai-focus.json) показывает цикл «Закрыть → X → Закрыть» внутри AI dialog. Локальная функция focus trap не является единственным обработчиком; нельзя выводить полный runtime из одного файла. Визуальная часть замечания подтверждена. Исправление: стандартная оболочка/монтирование, удалить broad reset вместо добавления ещё одной page-specific заплаты.

### B07 — P3: disclosure трудозатрат показывает две команды раскрытия

[22-main-bottom.jpg](../live/22-main-bottom.jpg) одновременно показывает стрелку + «Развернуть» около заголовка и «Показать» справа; [24-effort-bottom.jpg](../live/24-effort-bottom.jpg) — «Свернуть» и «Скрыть». `cardEffortDisclosure:6236–6241` сохраняет `.effort-disclosure-hint` вместе с общим `.ui-disclosure-text`, который уже рисует действие. Это прямое визуальное расхождение с единым disclosure-контрактом. Удалить прежний hint/стрелку, оставить один общий вариант. У обоснований KPI также видны локальные chevron возле названия и общий текст справа; проверить scoped pseudo-elements при унификации.
