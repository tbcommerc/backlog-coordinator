# Сверка основной вкладки с утверждённым прототипом

Дата: 11.11.2026. Исполнитель: A. Область: `cardBodyMainV30`, основной редактор,
визуальные helpers и именованный UI Kit `ui-task-detail-composition`.
Этот отчёт заменяет выводы отменённой реализации в `implementation-a.md`.
Shell, вторичные вкладки и live-проверка интеграции принадлежат общему отчёту.

## Что исправлено

Прежняя интерпретация заменена структурой `proposal.js`/`proposal.css`: сводка из
пяти полей, описание с внутренним комментарием, участники, четыре показателя,
один нижний disclosure. Дополнительные атрибуты раскрываются кнопкой внутри
участников. Убраны лишние разделы с раскрытием на первом экране.

Полный редактор повторяет порядок и сетку прототипа: название; статус,
исполнитель, срок; приоритет, прогресс, команда; описание и комментарий.
Остальные бизнес-поля доступны ниже основной формы. Сохранены быстрый редактор,
словари, метки и команды, Markdown, расчёт стоимости, C/V, AI-действия, PIP и
доступ к Агенту V2. Данные БД не менялись.

Прогресс теперь допускает любое целое 0–100: 47 сохраняется как 47, без округления
до пяти. Пустое, дробное и выходящее за диапазон значение блокирует сохранение.
Backend уже поддерживает этот диапазон целых чисел.

Размеры и типографика оформлены именованными стилями UI Kit, без ID-усилений:
body 14/21, подписи 12/18, показатели 18/26, форма gap 18×20, textarea 94 px,
controls 32/44 px. Ширина оболочки 1160 px реализована родительским агентом.
Размер шрифта контролов ограничен снизу 12 px по действующему контракту UI Kit:
это явное отклонение от 11.375 px, получившихся в прототипе из rem при root 14 px.
Mobile textarea сохраняет 16 px. Проверка `uiTypography` не ослаблена.
Combobox исполнителя и команды сохраняет рамку, размеры и штатный поиск.

Chromium, а не сравнивался с JPEG другого DPR. Реальный компонент исполнялся
в API fixture с `profile=proposal`: одинаковые название, описание, участники,

## Проверки и границы

- Unit: `taskCardInitialRender.test.mjs` + `taskCardInlineEdit.test.mjs` — 40/40.
  Проверены сохранность полей, целый прогресс, quick edit, dirty/save, доступное
  имя, AI-вызовы, uploads keyboard и их новые структурные ожидания. Тесты не удалены.
- Unit контрактов: `modalDesignSystem`, `moduleContracts`, `responsiveLayout`,
  `uiTypography` — 7/7. Ожидания обновлены под named shell, числовой прогресс и
  остановку Escape после закрытия одного слоя; требования не удалены.
- Fixture: `taskCardReferenceMatch.spec.mjs` — два парных сценария; один worker.
  Финальный проход — 2/2, отдельный output-каталог исключает конфликт trace-файлов
  с другими прогонами. Сняты также четыре нижних кадра `*-main-lower-*`, проверены
  плановая стоимость 360 000 и фактическая 120 000 на одинаковых ставках.
- Fixture: сценарий `attributes remain reachable, editable and cancelable` — PASS.
- Финальная единая регрессия — **21/21 PASS**, Windows Chromium, один worker:
  Composition — 9 (light/dark, 1440, 1366, 390, 320), ReferenceMatch — 2,
  Increment + Responsive — 10. Лог: `main-regression-final-2026-11-11.log`;
  output: `dmb-backlog/artifacts/task-card-main-final-2026-11-11`.
  Найдена и исправлена реальная потеря единицы «млн ₽» при динамическом обновлении
  финансового эффекта; новая KPI использует отдельный `finDisplay`, сохраняющий
  единицы и null-состояние. Старые проверки файлов обновлены на два доступных
  действия (имя и иконка), с проверкой обоих. Атрибуты/трудозатраты явно
  раскрываются перед проверкой содержимого. Снимки Composition сняты заново;
  повторно осмотрены desktop editor и dark editor 320. Root исправил выход
  текста footer под кнопку; тест Range измеряет правую границу текста и проверяет
  отсутствие пересечения с действиями во всех восьми сочетаниях ширины/темы.
  На 320 px слово «Изменений» переносится внутри слова: перекрытия нет, но короткая
  формулировка пустого статуса остаётся возможным улучшением. Финальные пары после
  исправления edit badge сняты заново; badge теперь следует за названием.
- UI Kit: DescriptionList, SectionCard plain, общие controls и named composition;
  старый range-контракт заменён числовым. Обновлены TASK_CARD, UI_PAGE_COMPOSITIONS,
  UI_KIT_CONTRACTS и минимальный пример каталога.

Весь экран не объявляется попиксельно идентичным. У прототипа есть демонстрационная
полоса сверху и нарисованный фон реестра; API fixture их не имитирует. Поэтому
абсолютный верх панели отличается на 22 px desktop / 36 px mobile. В реальном
приложении остаются счётчики вкладок и настоящая дата обновления. Срок является
выбором значения справочника, а не HTML date input; команда остаётся доступной
для изменения, тогда как в прототипе readonly. Это сохранённые бизнес-контракты,
а не незаметно подменённая модель данных. Дополнительные бизнес-поля ниже формы
также отсутствуют в статичном первом экране прототипа.

Парная сверка с прототипом покрывает светлую тему и два viewport. Дополнительная
регрессия и полные fixture-кадры включают dark и ширину 320/1366; это не эквивалент
приёмке всех 80 состояний. Реальные роли, backend-сохранение, блокировки,
конфликты и полный live-обход не объявлены принятыми этим отчётом. Старые снимки
и зелёные unit не заменяют новую визуальную/live-приёмку.
