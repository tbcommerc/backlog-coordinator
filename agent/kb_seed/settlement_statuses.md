# Статусы расчётов по сделкам (Settlement Statuses)

## Статус Failed (несостоявшийся расчёт)

Статус **Failed** присваивается сделке, если расчёт по ней не состоялся в
регламентный срок (по графику расчётов). Это означает, что сделка не была
исполнена через депозитарий / платёжную систему в дату расчёта (settlement date).

Основные причины Failed:
- нехватка ценных бумаг на счёте депо продавца;
- нехватка денежных средств на счёте покупателя;
- неверные или неполные платёжные реквизиты контрагента;
- сбои в передаче инструкций в депозитарий / платёжную систему;
- расхождения в параметрах сделки между системами (позиция, цена, дата расчёта).

### Действия при статусе Failed

1. Выявить причину несостоявшегося расчёта по инструкциям депозитария.
2. Урегулировать сделку: повторная отправка инструкции, покупка/заимствование
   ценных бумаг, урегулирование наличными (cash settlement) при согласии сторон.
3. Зарегистрировать рекламацию контрагенту, если расчёт не состоялся по его вине.
4. При повторных сбоях — эскалировать владельцу модуля расчётов платформы.

## Связанные статусы

- **Pending** — инструкция отправлена в депозитарий, расчёт ещё не наступил.
- **Matched** — инструкции по сделке совпали у обоих контрагентов.
- **Unmatched** — инструкции не совпали (расхождения по параметрам сделки).
- **Settled** — расчёт исполнен, ценные бумаги и денежные средства переведены.
- **Cancelled** — сделка или инструкция аннулирована.
- **Released** — поручение принято и ожидает исполнения.

## Бизнес-метрики

- Settlement rate: доля сделок, расчитанных в дату расчёта.
- Количество и доля Failed / Unmatched сделок — ключевой показатель качества
  пост-трейд обработки и данных.
