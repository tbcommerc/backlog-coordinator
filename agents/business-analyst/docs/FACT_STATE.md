# Состояние фактов и операций диалога

Проверено по текущему коду и регрессионным тестам 08.09.2026.

Основной runtime использует [AgenticBA](../business_analyst/dialogue/agentic.py).
Состояние и сериализация находятся в [state.py](../business_analyst/dialogue/state.py)
и [session.py](../business_analyst/session.py). Старые JSON сессии читаются с пустыми
значениями новых полей; отдельная миграция таблиц не требуется.

## Контракт решения

`Fact` содержит `field`, `value`, `confidence`, `assumption`, `evidence`,
`operation`, `answer_status`. Сохраняется совместимость с `correction`:
отсутствующая операция означает `replace` при `correction=true` и `add` иначе.

| Операция | Применение |
| --- | --- |
| `add` | Заполняет пустое поле; дополняет составное поле без удаления прежних элементов. Иное значение одиночного поля становится конфликтом. |
| `replace` | Заменяет полное значение по подтверждающей цитате текущей реплики. |
| `remove` | Удаляет указанный элемент составного поля или всё поле по прямому указанию. |
| `confirm` | Подтверждает существующее значение, не подменяет его другим. |
| `defer` | Сохраняет `unknown`, `not_applicable` или `deferred` из `answer_status`. Последний хранится как `skipped`. |

Составные поля: пользователи, сценарии, бизнес-правила, критерии приёмки,
данные и интеграции, зависимости, риски, регуляторные аспекты, открытые вопросы.
Элементы разделяются переводом строки или точкой с запятой. Одинаковые элементы
не дублируются. Добавление иной числовой версии того же правила создаёт конфликт;
пользователь должен указать замену.

JSON проверяется без преобразования строк в boolean и `null` в строку.
Неверные типы, нечисловая/бесконечная уверенность и недопустимые операции вызывают
ошибку схемы. Ошибочное решение повторно запрашивается один раз.

## Проверка источника

Проверяются наличие пользовательской цитаты, лексическая связь с кандидатом,
числа и некоторые признаки отрицания/неуверенности. Это консервативная проверка,
она не доказывает семантическую истинность произвольного текста. Факты с
недостаточной опорой сохраняются как кандидаты в `requirement_assumptions`,
не заполняют канонические поля и не закрывают минимальное ядро.

Если старый провайдер не вернул evidence, точное значение, присутствующее в
текущей реплике, само используется как цитата. Классификация intent проверяется
по признакам соответствующего типа обращения в пользовательской реплике.
Для исправления, удаления и подтверждения требуется опора на текущую реплику.
Повторение того же значения не повышает и не снижает прежнюю достоверность.
Короткое «нет» трактуется как отсутствие интеграций, зависимостей, рисков или
регуляторных аспектов только после закрытого вопроса именно об этом поле.
Допустимы только фиксированные формулировки отсутствия без новых объектов,
чисел и правил; исходная цитата «нет» сохраняется. Открытый вопрос и вопрос
с отрицанием не дают такой опоры.

## Устойчивое состояние

`Slot` хранит `evidence`, `message_id` и `provenance` — источники составных
элементов. Реплике пользователя без внешнего идентификатора присваивается
внутренний ID. Цитата сохраняется в поле независимо от размера окна истории.

`requirement_conflicts` хранит ID, код, важность, поле, обе версии, вопрос,
цитату и статус. Конкретный конфликт версий имеет `severity=critical`;
неконкретное замечание модели — `warning`. Следующее решение модели не удаляет
открытый конфликт. Явная замена/подтверждение поля разрешает связанные конфликты.
Для ручных правок предусмотрен `resolve_field_conflicts(field, value, reason)`.

`requirement_assumptions` хранит ID, текст, поле, источник и статус кандидата.
Подтверждённая правка разрешает предположения соответствующего поля.
Неконкретные предположения модели без поля остаются отдельными открытыми
замечаниями; они не повышают полноту и не заполняют требование автоматически.

Модель получает `requirement_state` со всеми обработанными статусами,
происхождением и достоверностью, открытые конфликты, предположения и gaps.
Окно последних реплик дополняет эту память и не является её заменой.

## Контракт ответа оркестратора

`apply` сохраняет прежний возвращаемый тип `list[str]` обновлённых полей.
`decision.application_results` содержит результат каждого кандидата:
`field`, `operation`, `status`, `reason`. Статусы: `applied`, `unchanged`,
`rejected`, `conflict`. Отклонения семантической проверки также включаются.
Оркестратор использует эти результаты, чтобы не подтверждать пользователю
изменения, которые фактически не были применены.

Регрессии: [test_agentic_ba.py](../business_analyst/tests/test_agentic_ba.py) и
[test_session_retention.py](../business_analyst/tests/test_session_retention.py).
