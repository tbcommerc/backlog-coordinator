# Проверки и границы подтверждения

Проверено 15.10.2026. [Полный отчёт на 80 примерах](EVALUATION_80_2026-10-15.md) содержит все вопросы, эталоны, исходные результаты, исправления и ограничения.

## Актуальные результаты

- Оценочный набор: **80/80**; основные вопросы 60/60, безопасность и отказы 20/20.
- Целевые объекты в top-5: 21/21; числовые примеры: 21/21.
- Настоящие OpenCode 1.17.13 и `glm-5.3-flash`: 72 запуска на синтетических данных; полных модельных циклов 68. Восемь внедрённых отказов не считаются ответами модели.
- 45 unit/contract тестов сервиса, 32 изолированных теста интеграции DMB, 7 Node-тестов интерфейса — пройдены.
- 7 сценариев Chromium с тестовым API — пройдены, включая 390/1280 px, повтор отправки, идемпотентность, черновик/фокус, отмену, текст карточки/историю и условия поиска.
- 16 реальных PostgreSQL-проверок на 1101 временной доступной задаче — пройдены: полная выборка и суммы, ACL, null/zero, литералы и русские формы, запрет записи read-only.

Пользователи, роли, команды и справочники в БД не создавались и не изменялись. Большой набор существует в памяти; SQL-проверки создают только временные рабочие записи и удаляемую пустую проверочную таблицу в собственной БД агента. Расширенные реальные данные DMB провайдеру не отправлялись.

## Сквозной сценарий и изоляция

15.10.2026 ранее пройден живой браузерный сценарий под существующей учётной записью: пять явно разрешённых задач, уточнение, перезагрузка и история, переход к карточке, новый разговор и отмена, широкий и мобильный экран. Оба ответа получены через Docker/OpenCode и настоящую модель, по два обращения без ошибок брокера. [Снимок ответа](../../../docs/dev-testing/evidence/backlog-assistant-2026-10-15/chat.jpg).

Отдельно ранее проверены два Docker instances: разные credentials/state, отказ чужому паролю, read-only FS, запрет внешнего TCP и отсутствие Docker socket, удаление состояния. PostgreSQL probe проверил повтор миграции, конкурентные create/enqueue и claims, глобальный лимит и потерю lease без повторного dispatch. Эти проверки не заменены синтетическим DataPort.

## Ограничения

Полный набор использует native launcher только для синтетических данных. Рабочий сервис остаётся в Docker с сетевой изоляцией. SQL/ACL, пользовательский интерфейс, контейнерная изоляция и модельная оценка — отдельные уровни проверки.

Последовательные задержки: p50=13.72 с, p95=21.69 с. Это не подтверждение цели p95 ≤20 с при десяти активных пользователях. Промышленные сертификаты и нагрузочный пилот не квалифицированы.

Поиск выполняет детерминированные фильтры и ограниченную нормализацию русских подстрок; embeddings и семантическое ранжирование не реализованы. Свободные утверждения модели заменяются проверенными серверными фактами. Фиксированный набор использован для регрессии и не гарантирует ответ на любую новую формулировку.

## Исправление составных подсчётов — 17.10.2026

Причины исходного сбоя: буквальное разрешение русских названий; отсутствие разрешения статуса; несовпадение фразы «в работе» с текущим статусом «ПРИНЯТА В РАБОТУ»; попадание промежуточных разрешений в резервный ответ. Дополнительно сокращён каталог для подсчётов, чтобы завершение ответа укладывалось в прежний input-бюджет. Резерв output приведён к фактическому пределу `max_tokens=1500`; лимиты 6000 output, 16000/40000 input и четыре обращения сохранены. Подтверждённый usage заменяет резерв, поэтому прежний резерв 3000 сам по себе не ограничивал каждый успешный запуск двумя обращениями.

Повторные проверки:

- 48 unit-тестов сервиса, включая обязательное сохранение разрешённых фильтров, запрет конфликтов/неразрешённых названий и сохранение литерала при подсчёте.
- 45 unit-тестов интеграции, включая разрешение статуса, склонения, варианты квартала/года, исключение промежуточных таблиц и уточнение вместо незавершённого подсчёта.
- 7 Node-тестов интерфейса.
- `python -m evaluation.filter_regression`: шесть полных циклов реальной модели/OpenCode на синтетических данных — PASS. Исходная формулировка и вариант с явным статусом дают 1; отдельные команда/статус/квартал — 4/4/3; отсутствующий 4Q 2025 вызывает уточнение. Синтетический статус использует фактическое название «ПРИНЯТА В РАБОТУ».
- 19 сценариев исходного корпуса последовательно: E01, E03, E10, E11, E21, E31, E32, E39, E45, E49, E65, E73–E80 — PASS. Это 11 полных модельных циклов поиска, карточек, запросов, группировок, истории, сравнения, встречи и запрета записи плюс восемь внедрённых отказов.
- Реальный PostgreSQL, READ ONLY: тем же `query.execute` разрешены «проектного офиса», «в работе», «4-го квартала»; для текущей доступной пилотному пользователю выборки получены «Проектный офис», «ПРИНЯТА В РАБОТУ», `4Q 2026` и 1 задача. Рабочие и защищённые записи не изменялись.

Обезличенные синтетические результаты находятся в `.runtime/filter-regression-results.json` и `.runtime/assistant-regression-sequential-2026-10-17.jsonl` в корне проекта; в Git не добавляются. Полный параллельный повтор 80 примеров остановлен из-за нехватки памяти; его сбои старта не засчитаны как функциональная приёмка. Оставшиеся тестовые процессы остановлены по проверенным PID. Нагрузочная приёмка не выполнялась.

Сквозной повтор через браузер с живой моделью в этом прогоне не выполнялся: ни один готовый QA-профиль не входит в текущий allowlist помощника. Allowlist и учётные записи не менялись. Работа модели и текущего PostgreSQL проверены отдельно; новый браузерный результат по реальным данным не заявляется. Сервисы помощника и Data API перезапущены, mTLS health-check пройден.

После ресурсного сбоя также восстановлен основной backend штатной командой uvicorn без запуска seed/миграций; заключительный `/api/v1/health` вернул 200.
