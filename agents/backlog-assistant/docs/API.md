# API и хранение

Проверено 14.10.2026. Версия внешних контрактов `1.0`; внутренние идентификаторы OpenCode не выдаются браузеру.

| Gateway `/api/v1/backlog-assistant` | Назначение |
|---|---|
| `GET /capabilities` | Доступность пилота текущему пользователю |
| `POST /sessions`, `GET /sessions` | Создание с Idempotency-Key и список собственных разговоров |
| `GET/PATCH/DELETE /sessions/{id}` | История с повторной проверкой прав, контекст/архив, удаление |
| `POST /sessions/{id}/messages` | Идемпотентная постановка вопроса, ответ 202 |
| `GET /runs/{id}`, `POST /runs/{id}/cancel` | Состояние и отмена |
| `GET /results/{id}?cursor=0` | Повторное чтение сохранённого запроса с текущими правами |
| `POST /messages/{id}/feedback` | Оценка ответа |

Agent API использует тот же набор под `/v1`. Дополнительные `/v1/internal/*` возвращают gateway только манифесты квитанций и исполнений; публичного proxy к ним нет. Входящий `execution_ref` создаёт DMB, браузер не может его передать. Контекст нормализуется по схеме и проверяется при создании/изменении; ревизия предотвращает отправку в устаревшую область.

Статусы: queued, running, cancelling, completed, partial, failed, cancelled, interrupted, expired. Незавершённая очистка хранится отдельно. На один диалог разрешён один активный вопрос, на владельца — два, глобально — четыре выполняющихся/неочищенных и двадцать ожидающих; до десяти вопросов в минуту на владельца.

Data API: `/internal/backlog-assistant/v1`, отдельный порт 9450. Operations: activate/check/revoke execution; разрешённый каталог tools; исполнение tools; answers/verify; sources/validate; results; receipts/purge. Помимо mTLS требуется service token, инструменты требуют execution grant. Повторное чтение использует короткое подтверждение текущей auth-сессии, привязанное к владельцу и receipt IDs.

Схемы релиза: [QuerySpec](../contracts/query.schema.json), [Context](../contracts/context.schema.json), [ToolResult](../contracts/tool-result.schema.json), [Answer](../contracts/answer.schema.json), [tools](../contracts/tools.json), [Agent OpenAPI](../contracts/agent.openapi.json), [Data API OpenAPI](../contracts/dmb-data.openapi.json). Экспорт: `python -m contracts.export`. DMB использует копию артефактов, тест сравнивает её с релизом; runtime-импорт соседнего проекта не требуется.

Сервис хранит свои таблицы sessions, runs, idempotency, nonces, feedback, purge_outbox. Input/answer/receipt refs находятся в записи run. Миграция `backlog_assistant.migrate` отказывается работать в БД с чужими таблицами. Retention разговоров — 30 дней; удаление квитанций доставляется через outbox. DMB хранит только таблицу `backlog_assistant_integration` (execution/idempotency/receipt), миграция `e8f1b2c3d405`. Истёкшие интеграционные записи очищаются при регистрации нового исполнения.

Исторические вопросы возвращаются только после повторной авторизации источников: они могут содержать цитаты уже закрытых данных. Названия разговоров нейтральные. Сохранённые ответы перепроверяются целиком; они не подаются новой модели как актуальные факты.


## Уточнения и история — 14.10.2026

`GET /v1/runs/{id}` и элементы истории возвращают `text` исходного вопроса только после успешной повторной проверки всех его receipts. При недоступных источниках ни вопрос, ни ответ не раскрываются. Заголовки списка разговоров остаются нейтральными.

Внутренний `POST /executions/{execution}/conversation` принимает `receipt_refs` (до 18), требует действующий execution grant, проверяет текущие права и совпадение conversation. Возвращает до трёх предыдущих инструментальных запросов без старых фактов. Новый вопрос заново читает данные. API недоступен через публичный gateway.

Генеративная схема исключает служебные `context`, `as_of`, `coverage`, `sources`: адаптер заполняет их доверенными данными до полной проверки Answer. Полная опубликованная схема Answer не меняется. `uniqueItems` исключён только из схемы для провайдера; серверный валидатор продолжает его проверять. В поисковых результатах модель получает компактное превью максимум пяти задач без описаний и финансовых полей; браузер получает проверенную серверную проекцию.


## Профиль выполнения — проверено 15.10.2026

Работа runtime ограничена 50 секундами; до общего дедлайна 60 секунд оставлен резерв для повторной авторизации и публикации уже полученных серверных результатов. При отсутствии результатов возвращается ошибка, данные не придумываются. Завершение локального HTTP-брокера ограничивает graceful shutdown двумя секундами. Для glm-5.3-flash передаётся reasoning_effort=low и max_tokens=1500; резерв бюджетирования остаётся консервативным (3000 на попытку, 6000 суммарно), неизвестная доставка расходует резерв.


## Исправления по оценочному набору — 15.10.2026

- Уточнение после `resolve_context` сохраняет `kind=clarification`; ответ без источников не объявляется успешным.
- Генеративная схема не запрашивает также `summary_claims`, `actions`, `followups`, `limitations`: эти поля формирует сервер. До пяти вариантов уточнения допускаются после ограничения списка адаптером.
- `query_changes.to` — точная исключающая верхняя граница; `fields` ограничивает запрошенные изменения, плановый период соответствует `deadline_id`.
- Вопрос по публичному номеру `TASK-*` требует поиска: внутренний ID из номера не вычисляется.
- Модельное превью ограничивает вложенные списки пятью элементами и длинные строки 400 символами. Полный результат и квитанции сохраняются сервером; числа и таблицы модель не пересчитывает.
- Отказ инструмента 401/403/404 останавливает выполнение через `source_access_denied`. Последующий широкий поиск и публикация ранее полученного частичного результата запрещены.
- Карточка и запрос показывают описание, комментарии/историю, когда они были прочитаны. Причина текущего статуса запроса берётся из последнего события этого статуса; старое отклонение не подставляется как текущая причина.
- Полнота учитывает обрезанную историю и комментарии. Сравнение возвращает выбранные измерения; агрегат различает количество задач и групп.

Формирование проверенного ответа выделено в `presentation.py`; авторизация квитанций остаётся в `ledger.py` и выполняется до представления данных.

## Уточнения поиска и исполнения, 15.10.2026

Поиск сохраняет явно заданные публичные номера `TASK-*` и слова после «со словом» на границе ToolBridge. Если модель опустила это условие, оно добавляется к её фильтрам через AND до проверки схемы и вызова Data API. Остальные формулировки интерпретирует модель; произвольное понимание естественного языка этим правилом не гарантируется.

Data API расширяет русские окончания только у полностью кириллических слов длиной от семи букв, сохраняя основу длиной не менее четырёх букв. Исходная фраза и нормализованные слова проверяются параметризованными предикатами. ID, `%`, `_` и прочие литералы не превращаются в шаблоны. Это ограниченная нормализация подстрок, не семантический поиск. Применённые условия возвращаются в `data.search_terms` и отображаются над таблицей.

Внутренние ссылки проверяются по типу (`task:N`, `request:N`, `review:N`, `meeting:N`) до чтения домена. Неверный синтаксис допускает исправление вызова; отказ доступа к корректной ссылке останавливает весь запуск. При неоднозначном разрешении объекта сервер сохраняет вопрос и различимые варианты с ссылками, даже если модель не завершила ответ.

Модель получает компактный просмотр данных и `snapshot_ref`; полные receipts, источники, их принадлежность и актуальные права остаются на серверной проверке. Сокращение модельного контекста не изменяет разрешения и не повышает бюджеты.

При очевидном одиночном намерении (поиск, карточка, сравнение, агрегация, изменения или встреча) runtime получает только соответствующий поднабор уже разрешённого каталога. Это пересечение, а не выдача новых прав. Неизвестные и составные вопросы сохраняют исходный каталог.

Полные короткие положительные команды «Покажи мои задачи», «Найди задачи без …» для четырёх определённых отсутствующих полей и «Найди задачу о …» закрепляют однозначные условия в bridge. Отрицания, неизвестные варианты и составные предложения этим правилом не разбираются. Прочие фильтры модели сохраняются как дополнительные ограничения.

Невалидный завершённый ответ без чтения данных может быть исправлен одним новым сообщением в той же изолированной сессии. Общие budgets, grant и deadline сохраняются. Неизвестная доставка нового сообщения только опрашивается, без повторной отправки. Ответ с неподтверждённой ссылкой не публикуется; после получения настоящих receipts возможен только проверенный серверный fallback.


## Разрешение фильтров и представление — проверено 17.10.2026

`resolve_context.kind` дополнен значением `status`. Поиск команды/проекта учитывает ограниченную нормализацию русских окончаний. Период поддерживает варианты квартала Q4/4Q/4-й квартал и явно заданный год; отсутствующий год не подставляется. Поиск остаётся ограничен текущими правами и контекстом. «В работе» сопоставляется со статусом «ПРИНЯТА В РАБОТУ».

Уникальные результаты разрешения команды, проекта, статуса и периода закрепляются перед `aggregate_backlog`: пропущенное условие добавляется, конфликтующее запрещает вызов. Нулевое или неоднозначное разрешение не может превратиться в широкий подсчёт.

В опубликованных `summary_claims`/`verified_blocks` промежуточные `resolve_context` не отображаются. Все их receipts по-прежнему перепроверяются. При отсутствии предметного чтения возвращается `clarification` с вопросом. Пустой агрегат означает ноль задач, независимо от числа найденных ранее названий.
