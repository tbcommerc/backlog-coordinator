# Архитектура и границы

Проверено 17.10.2026 по исполняемому коду и синтетическим тестам; ограничения живой проверки перечислены в TESTING.md.

Браузер → DMB gateway → Agent API → собственная PostgreSQL-очередь → worker → один Docker/OpenCode instance на вопрос. Контроллер предоставляет этому экземпляру приватный MCP bridge и модельный broker. Предметные чтения выполняет отдельный mTLS Data API DMB. Пакет агента не импортирует ORM, auth или миграции DMB.

Gateway подписывает HMAC-подтверждение личности, привязанное к HTTP-методу, пути с query string, телу и Idempotency-Key. Срок — 30 секунд; сервис отклоняет повторы nonce. Обе внутренние HTTP-границы требуют клиентские сертификаты. Data API не подключён к браузерному FastAPI-приложению.

Делегирование содержит первоначальную область объектов и активную auth-сессию DMB. Каждый инструмент пересекает её с текущими правами. Личность, роль, SQL и URL отсутствуют во входной схеме инструментов. Customer-проекция использует существующий сериализатор; customer list/detail используют общие ACL helpers. Исключение связанной с собственным запросом задачи разрешает только detail и не расширяет список. Запросы без команды не образуют область «моя команда».

Чтения выполняются внутри PostgreSQL `REPEATABLE READ`, `READ ONLY`, `statement_timeout=3000ms`. Отдельные транзакции записывают только интеграционные executions/receipts. Манифест квитанции содержит всю выборку, включая участников агрегатов и непоказанные строки. При проверке ответа и повторном чтении истории перепроверяются все использованные квитанции, включая нецитированные. Отзыв одного источника закрывает весь старый ответ.

OpenCode закреплён на 1.17.13. До prompt проверяются версия, primary agent, provider, MCP и permissions. Разрешены только точные имена tools и `StructuredOutput`; built-in coding agents отключены. Instance получает собственные home/XDG/workspace/state/tmp, пароль HTTP и токен bridge; не получает ключ модели, grant DMB, пользовательский JWT или Docker socket. Конфигурация монтируется read-only. После настройки firewall процесс запускается как UID 10001 без capabilities. Egress разрешён только на порт своего bridge; корневая ФС read-only, CPU/RAM/PIDs/tmpfs ограничены. Предельная жизнь контейнера — 90 секунд, даже при аварии контроллера.

До создания instance сохраняется его cleanup identity, до prompt — dispatch intent. После неоднозначной доставки prompt не повторяется. Lease истекает за 10 секунд; потерянный запуск становится interrupted и не возвращается в очередь. Очистка подтверждается удалением контейнера при доступном Docker daemon; неочищенный instance удерживает глобальный слот. Запрос отмены запрещает публикацию даже при готовом ответе. Сначала отзывается grant, затем останавливается и удаляется runtime.

Бюджет: 60 секунд работы, очередь до 15 секунд, 6 tools до 3 секунд каждый, до 4 фактических модельных запросов, включая повторы OpenCode. Перед сетевым вызовом резервируются 1500 output tokens (фактический `max_tokens`), суммарно до 6000. Для input используется консервативная оценка по UTF-8 bytes с запасом, ограничения 16000/40000; она может отклонить запрос раньше фактического токенизатора. При недостоверном usage ответ запрещён. Автоматического переключения провайдера нет.

Если модель вернула невалидный кандидат, worker может выдать `partial` из уже полученных серверных таблиц после повторной авторизации. Это детерминированный fallback, без дополнительного LLM-цикла. DMB публикует числа и таблицы из квитанций, а не сгенерированные моделью строки. Свободное объяснение пока не прошло семантическую приёмку.


## Составные вопросы о количестве — проверено 17.10.2026

Однозначные запросы количества получают только `resolve_context` и `aggregate_backlog` из разрешённого каталога. Независимые разрешения команды, статуса и периода запрашиваются одним модельным ходом; runtime допускает шесть шагов при сохранённых ограничениях в четыре модельных обращения и шесть чтений. Подтверждённый `usage` заменяет резерв output; неизвестная доставка сохраняет резерв.

Разрешение названий работает только по уже доступным объектам и поддерживает статус. Формы «проектного офиса» и «Проектный офис» сопоставляются консервативной нормализацией; «в работе» соответствует «ПРИНЯТА В РАБОТУ». Обозначения Q4/4Q/4-й квартал сопоставляются с имеющимися периодами без угадывания года. Несколько совпадений требуют уточнения.

ToolBridge закрепляет однозначно разрешённые фильтры в агрегации; конфликт или неразрешённый фильтр запрещает подсчёт. Промежуточные разрешения остаются проверяемыми зависимостями, но не становятся таблицами или утверждениями о количестве задач. Если получены только разрешения, сервер возвращает уточнение вместо ответа с пустыми выборками.
