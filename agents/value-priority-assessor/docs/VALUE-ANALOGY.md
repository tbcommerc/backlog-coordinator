# Оценка Value по аналогии

> AS-IS сверено с `value_priority_assessor/core/analogy.py`, snapshot и тестами 02.09.2026.

Значение, введённое человеком, — истина: агент его не пересчитывает (ТЗ Ф1).
Но 193 таких значения в бэклоге — ещё и обучающая выборка. По решению владельца
от 2026-08-11 агент использует их, чтобы оценивать похожие задачи.

## Зачем это понадобилось

В прототипе формульная оценка опиралась на подстановки — 20 пользователей,
15 минут на операцию, 50 раз в год. Эти числа не были измерены. Путь удалён
02.09.2026: теперь формула требует все числовые драйверы из задачи или реального
ответа модели и иначе возвращает отсутствие оценки.

Бэктест показал, чего это стоит:

```bash
python3 scripts/value_backtest.py
```

| Метод | Попадание в 2 раза | Попадание в 3 раза | Медианная log-ошибка |
|---|---:|---:|---:|
| Медиана всего бэклога | 11.5% | 22.4% | 2.303 |
| Формула по типовым значениям | 14.1% | 21.9% | 1.267 |
| Медиана команды | 54.2% | 59.4% | 0.509 |
| **Аналогия по 3 похожим задачам** | **67.2%** | **78.6%** | **0.209** |

Метод — leave-one-out на 192 задачах с известным ответом: каждая
предсказывается по остальным. Формула при этом считается заново, со снятым
ручным значением, — иначе она «предсказала» бы ответ, прочитав его.

Эти результаты объясняют отказ от прототипных подстановок. Аналогия остаётся
допустимым методом, потому что использует реальные значения, введённые людьми;
формула считается рядом только при наличии полного набора драйверов.

## Как устроено

Индекс из задач с человеческим Value, эмбеддинги `intfloat/multilingual-e5-base`
по строке «команда. название». Для задачи без Value берутся три ближайших
аналога, оценка — их медиана.

**Медиана, а не среднее.** Значения тянутся от 0 до 3600 млн ₽; одна крупная
задача в соседях сдвинула бы среднее на порядок.

**Аналоги своей команды предпочтительнее.** Если внутри команды нашлось хотя бы
два аналога, чужие не рассматриваются: методика оценки внутри команды едина, у
соседней она может быть другой.

**Задача не может быть аналогом самой себе** — иначе оценка выродилась бы в
копирование собственного значения.

## Уверенность

Складывается из трёх независимых сигналов:

| Сигнал | Влияние |
|---|---|
| Схожесть с лучшим аналогом | ≥0.96 — высокая, ≥0.93 — средняя, ниже — низкая |
| Аналог чужой команды | высокая понижается до средней |
| Разброс значений аналогов | ≥5× понижает на ступень, ≥20× сразу до низкой |
| Расхождение с формулой | ≥3× понижает на ступень |

Разброс добавлен не из осторожности, а по факту дефекта. У задачи TASK-200-007
нашлись три аналога той же команды со значениями 111, 0.5 и 1.9 млн ₽ при
схожести 0.98 — и первая версия объявляла оценку надёжной, потому что учитывала
только близость текста. Медиана 1.9 млн ₽ остаётся разумной, а «высокая
уверенность» при расхождении в 112 раз — нет.

## Что показал прогон на реальном бэклоге

230 задач получили оценку по аналогии. Распределение уверенности:

| Уверенность | Задач |
|---|---:|
| Низкая | 216 |
| Средняя | 12 |
| Высокая | 2 |

Это не поломка, а честный отчёт о том, чего хватает данным.

**Задачи без Value менее похожи на заполненные, чем заполненные друг на друга.**
Медианная схожесть с лучшим аналогом: 0.962 внутри эталонного набора против
0.904 у задач, которые нужно оценить. Незаполненными остались как раз те задачи,
у которых нет близких предшественников.

Поэтому **цифры бэктеста — верхняя граница, а не ожидаемая точность на новых
задачах.** Так и следует их читать.

## Заполняли ли команды Value согласованно

Проверил отдельно, потому что от этого зависит, есть ли смысл учиться на этих
данных. Среди 362 пар почти одинаковых задач одной команды (схожесть ≥0.95):

* медианное расхождение Value — **1.4×**;
* расходятся более чем в 5 раз — **8% пар**.

То есть на действительно похожих задачах команды оценивали согласованно. Высокий
разброс у аналогов незаполненных задач — следствие того, что их «похожие» задачи
находятся на расстоянии 0.90, а не 0.96, а не следствие произвола в заполнении.

Практический вывод: **метод будет тем точнее, чем больше Value заполнено
вручную.** Каждое новое человеческое значение расширяет покрытие и поднимает
уверенность у соседних задач.

## Диапазон оценки

Точечная оценка вводит в заблуждение: «25 млн ₽» выглядит одинаково убедительно
и когда истина лежит между 11 и 148, и когда между 0.1 и 1275. Поэтому рядом со
значением всегда показывается диапазон, в который истинное значение попадает в
95% случаев.

Множители не выведены из предположения о нормальности — распределение Value
тянется от 0 до 3600 млн ₽. Они получены **конформной калибровкой на фактических
ошибках**: `scripts/value_calibrate.py` прогоняет leave-one-out, собирает остатки
`log1p(оценка) − log1p(истина)` и берёт по ним квантили 2.5% и 97.5% отдельно для
каждого метода и уровня уверенности.

```bash
python3 scripts/value_calibrate.py --write
```

| Метод | Уверенность | n | Делим на | Множим на | Покрытие |
|---|---|---:|---:|---:|---:|
| Аналогия | высокая | 7 | 2.3× | 5.9× | унаследовано |
| Аналогия | средняя | 82 | 2.3× | 5.9× | 95.1% |
| Аналогия | низкая | 103 | 292.5× | 50.9× | 96.1% |
| Формула | низкая | 186 | 8.1× | 345.2× | 96.2% |

Нижняя граница — `оценка / down_factor`, верхняя — `оценка × up_factor`.

**Интервал асимметричен**, и это не небрежность: оценка систематически
занижает — у формулы верхняя граница в 345 раз, нижняя в 8. Симметричный
интервал был бы одновременно шире нужного снизу и уже нужного сверху.

**Группа с числом наблюдений меньше 20 наследует множители более широкого
уровня.** Конформная граница на уровне 95% требует, чтобы `ceil(0.95·(n+1)) ≤ n`;
при семи наблюдениях квантиль вырождается в максимум остатка и гарантии не даёт.
Такие записи помечены `calibrated: false`, и подсказка об этом сообщает.

Квантили берутся округлением наружу, а не интерполяцией: при первом прогоне
интерполированный квантиль дал покрытие 92.7% вместо обещанных 95%.

**У ручного значения и у нуля по методике интервала нет.** Ручное значение —
истина, ноль регуляторной задачи — тоже. Рисовать вокруг них диапазон значило бы
придумывать неопределённость, которой нет.

### Насколько можно доверять этим 95%

Покрытие измерено на эталонном наборе — задачах, где Value уже заполнен. Они
похожи друг на друга сильнее, чем на задачи без Value (медианная схожесть 0.962
против 0.904), поэтому **на новых задачах фактическое покрытие, скорее всего,
ниже заявленного.** Проверить это нельзя: у задач без Value нет истины, с
которой можно сравнить.

Смягчает положение то, что почти все такие задачи попадают в уровень низкой
уверенности, где интервал очень широк — от «делим на 292» до «умножаем на 51».
Такой диапазон честно сообщает, что оценка не годится для решения о приоритете,
и что единственный способ его сузить — заполнить Value вручную.

## Чего метод не делает

Он воспроизводит то, как оценивали команды, включая их систематические сдвиги.
Если команда завышала эффект, аналогия завышение продолжит.

Это прямое следствие решения считать человеческие значения истиной, и оно
принято сознательно. Но стоит помнить, что ТЗ ставило и обратную цель —
«устранить структурную возможность манипулирования Value». Аналогия работает
против неё: она переносит прошлые оценки на новые задачи.

Защита от этого — не в алгоритме, а в прозрачности: подсказка под полем Value
всегда называет конкретные задачи-аналоги с их значениями и схожестью, поэтому
завышение видно глазами. Если Core проставил 58.3 млн ₽ двадцати задачам подряд,
это будет видно в списке аналогов.

## Настройка

```bash
PRIORITISER_VALUE_ANALOGY=1      # 0 — вернуться к формуле
PRIORITISER_VALUE_ANALOGY_TOP_K=3
```

Индекс кэшируется в `data/index/analogy.faiss` и пересобирается при изменении
набора ручных значений. Полный пересчёт 440 задач с аналогией — 23 секунды
(норматив НФ8 — 264 секунды на этот объём).

## Порядок методов

1. **Ручное значение** — если заполнено, используется как есть;
2. **Ноль** — регуляторные задачи и RnD/L2P;
3. **Аналогия** — если найдены похожие задачи с человеческим Value;
4. **Формула** — если аналогов нет.

Формула считается всегда: она попадает в `value_inputs.formula_cross_check` для
аудита (НФ19) и в перекрёстную проверку уверенности.
