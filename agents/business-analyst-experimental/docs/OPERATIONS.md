# Эксплуатация Assistant V2

> Настройки LLM и запуска сверены с кодом 12.10.2026.

## Включение пилота

1. Задайте одинаковый нестандартный `AGENT_V2_SECRET` в DMB и Agent V2.
2. Укажите BA/PO в `AGENT_V2_PILOT_USER_IDS` или
   `AGENT_V2_PILOT_EMAILS` DMB. Полный администратор допускается автоматически;
   пустой список закрывает доступ остальным пользователям.
3. Запустите `scripts/start-project.ps1`.
4. Проверьте `/api/agent-v2/ready` и backend `/api/v1/ready`.

При стандартном локальном запуске V2 обязателен: launcher устанавливает
`AGENT_V2_ENABLED=true` в DMB и сервисе и проверяет readiness. Старый флаг
`-IncludeBusinessAnalystExperimental` сохранён для совместимости; даже значение `$false` не отключает V2.
При ручном запуске `AGENT_V2_ENABLED=false` не регистрирует gateway. Аварийный
`AGENT_V2_KILL_SWITCH=true` на DMB закрывает gateway, а тот же флаг сервиса запрещает
mutating API. Пункт sidebar и страница `#/agent-v2` остаются видимыми и
показывают локальный статус без вызова API. Основные сервисы DMB и V1 продолжают работать. Старый самостоятельный прототип удалён 02.11.2026; [сравнение и сохранённые решения](../../../docs/AGENT_V2_RETIREMENT_2026-11-02.md).

## Изоляция runtime

- virtualenv: `.venv-agent-v2/`;
- порт: `9300`;
- DB/роль: `agent_v2_sessions` / `agent_v2`;
- PID: `.runtime/agent-v2.pid`;
- stdout/stderr: `.runtime/agent-v2.out.log`, `.runtime/agent-v2.err.log`.

Production (`AGENT_V2_DEBUG=false`) требует PostgreSQL, нестандартный secret,
`openai_compat` и ключ провайдера. SQLite и mock допустимы только для
изолированной разработки/тестов.
Контейнерный entrypoint также изолирован: `business_analyst_experimental.main:app`, порт `9300`.

## OpenCode Go через API-ключ

В `agents/business-analyst-experimental/.env` для отдельного подключения V2:

```dotenv
AGENT_V2_INHERIT_V1_LLM=false
AGENT_V2_LLM_PROVIDER=openai_compat
AGENT_V2_OPENAI_BASE_URL=https://opencode.ai/zen/go/v1
AGENT_V2_OPENAI_MODEL=glm-5.3-flash
AGENT_V2_OPENAI_REASONING_EFFORT=low
AGENT_V2_AGENT_DECISION_MAX_TOKENS=8192
AGENT_V2_OPENAI_API_KEY=<ключ подписки OpenCode Go>
```

Секрет хранится в локальном `.env`, исключённом из Git. Не переносите его
в `.env.example`, frontend, документацию или диагностические отчёты.
Модель задаётся без префикса `opencode-go/`. Список доступных моделей предоставляет
`GET https://opencode.ai/zen/go/v1/models`; протокол конкретной модели указан в
[документации OpenCode Go](https://opencode.ai/docs/go/#endpoints).
Текущий провайдер агента поддерживает `/chat/completions` и JSON mode;
модели с `/responses` или `/messages` требуют другого адаптера.

Для создания полного документа и сверки переноса отдельная настройка
`AGENT_V2_DOCUMENT_MAX_TOKENS=12000` (1024–32000, значение по умолчанию 12000).
Диалог, точечные правки и бизнес-ревью сохраняют бюджет
`AGENT_V2_AGENT_DECISION_MAX_TOKENS`. Короткий бюджет может
оборвать структурированный ответ модели. `OPENAI_REASONING_EFFORT` допускает
пустое значение (параметр не отправляется), `low`, `medium` или `high`.
JSON-ответ с `finish_reason=length` отклоняется как незавершённый.
При доработке первого черновика частичный набор операций модели применяется
поверх уже проверенного кандидата: отсутствие поля в ответе не удаляет его
содержание и ссылки на источники. Явные замены проходят обычную валидацию;
результат повторно проверяется на полноту переноса. Проверено 09.10.2026.
09.10.2026 реальный Go вернул HTTP 200 и корректный JSON; на искусственном БТ
проверены создание правки и ревью (12 валидных замечаний без изменения документа).
Это не оценка полноты ревью на материалах заказчика.

Создание черновика требует двух модельных вызовов, при исправлении — максимум
четырёх. Создание и ревью используют общий бюджет ожидания 150 секунд на действие;
клиент учитывает остаток при запросах и повторных попытках. Сетевой socket timeout
не является абсолютным ограничением времени чтения всего ответа. При исчерпании
бюджета доступный результат помечается непроверенным; бесконечных повторов нет.
Стандартный gateway timeout — 180 секунд. Настройки загружаются при запуске V2.

Содержательный синтетический прогон (без рабочей БД):

```powershell
& '.venv\Scripts\python.exe' -B agents/business-analyst-experimental/scripts/evaluate_generation.py --runs 1 --format compact --output .runtime/agent-v2-generation-eval.json
```

Команда явно обращается к настроенной реальной модели и отправляет только
встроенный пример напоминаний. `--runs` допускает 1–5 повторов. Проверяются
форматы `--format bold|markdown|plain|compact|short` (проверено 09.10.2026).
`short` намеренно не содержит границ и вопросов автора; `compact` содержит
полный пример без Markdown и пустых строк. Дополнительно проверяются число
фрагментов и точная граница цели. В полном примере проверяются
основные разделы, пять критериев, четыре авторских вопроса, допуск пяти минут,
текущий исполнитель и отсутствие вопросов об исключённых каналах/руководителях.
JSON сохраняет синтетический документ и отчёт; ключи не выводятся.

`AGENT_V2_INHERIT_V1_LLM` — настройка корневого launcher. При `false`
он сохраняет собственные provider/key/base/model V2 и проверяет их наличие.
Пустое значение или `true` сохраняет прежнее поведение: эти четыре значения
копируются из `agents/business-analyst/.env`. В работающем процессе настройки читаются при старте;
после изменения `.env` нужен перезапуск V2.

Проверка именно реального подключения, без запуска проекта и без доступа к БД,
из корня репозитория:

```powershell
& '.venv\Scripts\python.exe' -B agents/business-analyst-experimental/scripts/check_llm.py --timeout 30
```

Команда делает реальный запрос с коротким искусственным JSON-примером,
используя настройки и клиент агента. Успех — `ok=true` и
`json_contract_ok=true`; вывод не содержит ключа и полного тела ответа провайдера.
Это проверка соединения и формата, а не оценка качества написания БТ.
HTTP 400/401/403 не повторяются автоматически; тип и категория ошибки помогают
различить ограничения модели, ключа и подписки. `/ready` проверяет наличие
конфигурации и не заменяет этот запрос.

Клиент передаёт собственный `User-Agent` приложения и непрозрачный
`x-opencode-session`, постоянный для разговора. Он не представляется OpenCode CLI.
Zen использует другой адрес — `https://opencode.ai/zen/v1`.
Проверенная 09.10.2026 прежняя конфигурация Zen / `big-pickle` ответила
`403 FreeTierError`; это не рабочая замена доступу Go.

## Откат

Установите kill switch либо выключите feature flag и перезапустите DMB/V2.
Документный цикл использует таблицу `requirement_reviews` в DMB, добавленную
миграцией `a6d2f8c0b431`; сессии находятся в отдельной БД. Прежний приём
поручений использует `RequirementRequest`. При выключении пилота таблицы и
отправленные редакции сохраняются; удаление данных для отката не требуется.
