# DMB agent contracts

Проверено 04.11.2026. SDK 1.4.0 находится в текущей миграционной поставке.
Общий статус и незавершённые проверки: [IMPLEMENTATION](../../docs/dev-testing/agent-services/IMPLEMENTATION.md).

Пакет содержит только технические DTO, ModelPort/RuntimePort, transport adapters,
лимит логических операций, общий управляющий API, очередь и её миграцию.
Предметные схемы, промпты, расчёты и применение результата остаются в сервисах.
Импорт модулей не создаёт схемы и не обращается к модели.

## Reference OpenCode

Reference — OpenCode 1.17.13, snapshot и hash находятся в `reference/`.
`RemoteOpenCode` преобразует реальные session/message/permission/abort/delete
операции этого API. По умолчанию remote-профиль выключен. Адаптер без инструментов
отклоняет MCP и любые разрешения сверх StructuredOutput.

`PreparedRemoteRuntime` добавляет инструменты только после получения отдельной
аренды `IsolatedLease` от доверенного `ProvisioningPort`. Это внешний deployment
интерфейс, а не дополнительный выдуманный маршрут OpenCode. Новый общий сервис
управления контейнерами не требуется: допустимы заранее подготовленные
изолированные экземпляры с проверяемым владением и подтверждённой очисткой.

Аренда связывает run UUID, неизменяемый image digest, runtime version, отдельные
workspace/state/credentials, hashes конфигурации и каталога инструментов,
ссылки на ограниченные grants и срок жизни. Реализация `inspect` обязана
независимо проверять фактические ресурсы, подключённый каталог MCP и ограничения
сети, а не возвращать непроверенные поля входного запроса.

Manifest версии `1.0` содержит `tools` (имя `dmb_*` → JSON Schema) и `network`
с отдельными HTTPS-адресами `tool_bridge` и `model_broker`. Runtime получает
только ограниченные per-run credentials моста/брокера. Ключ inference-провайдера
остаётся у брокера. Он обязан ограничивать реальные попытки, tools, токены,
deadline и неопределённый usage; его контракт не заменяется одним счётчиком submit.

Сервис проверяет effective config и resolved permissions агента через reference
HTTP API. Разрешены только StructuredOutput и точный allowlist инструментов;
agent overrides, другие providers, plugins, instructions и неожиданные permission
events несовместимы с профилем. Перед dispatch проверка повторяется.

Необходимые направления сети: сервис → HTTPS OpenCode; runtime → HTTPS tool
bridge; runtime → HTTPS model broker; broker → разрешённый Go inference origin.
Ни `127.0.0.1`, ни `host.docker.internal`, ни Windows-пути не считаются доступными
удалённому экземпляру автоматически. Их заменяет явная конфигурация контура.

В приватной привязке для восстановления сохраняются ссылки на run/lease,
session/message, dispatch и delivery. В неё не входят endpoint credentials,
provider key или bridge token. Неизвестная доставка наблюдается без второго
submit. Отмена немедленно запрещает collect; освобождение ресурса требует
отзыва grants и подтверждения уничтожения именно своей аренды.

`runtime_model`/`runtime_records` предоставляют технический мост ModelPort и
checkpoint для отдельных выключенных по умолчанию remote-профилей V1, V2,
meeting-analyzer и оценщика. Подключение требует явной конфигурации, предварительной
миграции приватных bindings и успешного preflight. Сквозная серверная приёмка
не заявлена. Janitor очищает прерванные сессии только после terminal fence,
совпадения сохранённого профиля и доказанной смерти локального владельца либо его долговечной отметки `owner_finished` в текущем процессе. Неизвестный или чужой владелец не принимается автоматически.
Поиск без результата не доказывает отсутствие ресурса; слот остаётся занят.
Abort/delete имеют собственные конечные HTTP-дедлайны после отмены операции,
при этом её слот и запрет публикации сохраняются.

## Проверки

Проверено 04.11.2026: срок идемпотентности фиксируется отдельно для каждого
нового ключа при его создании (7–90 дней). Сокращение настройки хранения не
сокращает уже выданную гарантию. Для старых записей без сохранённого срока
применяется консервативное окно 90 дней. Приватная отметка срока хранится в JSON
профиля, не входит в хеш запроса и не передаётся обработчику или клиенту.
После удаления входа и результата технический tombstone сохраняет эту отметку;
активные запуски очистка не удаляет. Изменение не требует DDL, но откат на старый
код очистки требует отдельно сохранить гарантию срока: прежний cleaner не должен
работать с новой базой до совместимого обновления.

`tests/test_remote_http.py` запускает отдельный HTTP-эмулятор используемого
подмножества snapshot. `test_prepared_runtime.py` проверяет также несовместимую
аренду, hashes/grants, effective permission override, неопределённую доставку,
восстановление наблюдения и отказ очистки. Эти результаты имеют тип
`contract_emulator`; `real_remote=NOT_RUN`.

Локальный запуск и управляющий API описаны в [RUN_API](../../agents/RUN_API.md).


Проверено 04.11.2026: уникальность общих квитанций включает operation;
`Store.find_key` требует operation явно. Явная миграция меняет только известное
ограничение caller/actor/key, сохраняя строки и события. Для SQLite она работает
с остановленными worker и подтверждённой резервной копией. PostgreSQL выполняет
изменение ограничения в транзакции. Обратное сужение области может конфликтовать
с новыми данными и автоматически не выполняется.

Проверено 05.11.2026: Usage дополнен независимыми reported cost и Go allowance. При отсутствии сохраняются null и provider_partial_usage/provider_not_reported; ноль не выдумывается. Булевы, строковые, отрицательные и бесконечные значения не принимаются. Тариф и валюта из числа токенов не вычисляются.
